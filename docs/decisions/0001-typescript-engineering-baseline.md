# ADR-0001：TypeScript 工程与质量基线

- 状态：已接受
- 日期：2026-07-26

## 背景

Runtime 将由多个可独立部署的应用和一组共享领域包组成。首个业务功能出现前，需要确保本地和 CI 使用相同版本、相同命令与相同边界，避免空骨架演变成相互跨目录引用的单体工程。

## 决策

1. 使用 pnpm Workspace 管理应用、共享包和经过审查的 vendor 包；每个应用和共享包拥有独立 `package.json` 与 `tsconfig.json`。
2. 使用 TypeScript 严格模式。每个包独立编译，禁止依赖根目录一次性扫描全部源码所产生的隐式可见性。
3. 使用 Biome 同时完成格式和静态检查，减少 ESLint、Prettier 及其桥接插件之间的配置面；使用 Vitest 执行单元测试。
4. CI 固定 Node.js `24.18.0` 和 pnpm `10.15.1`，冻结安装后依次执行格式、静态检查、类型、测试、构建和配置校验。
5. `.env.example` 由显式键集合约束。疑似真实凭据会被拒绝，校验错误不能包含配置值。Compose 只用该示例做静态展开。

## 影响

- 新包必须显式声明依赖并独立通过类型检查和构建，新增时会有少量配置重复。
- 统一工具减少了初始维护成本；若未来遇到 Biome 无法表达的领域规则，应先记录决策，再引入专用检查器。
- CI 不依赖开发环境和外部服务，因此基础工程校验可重复；真实基础设施测试由后续集成测试工作流承担。
