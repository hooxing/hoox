# ADR-0044：Agent 工作台三段式信息架构

- 状态：已接受
- 日期：2026-07-28
- 决策者：Runtime 团队
- 关联任务/PR：产品化 Web 视觉与交互重构
- 替代关系：补充 ADR-0039

## 背景

ADR-0039 已确定浏览器只经公开 API 读取 Thread、Run、事件和 Artifact，并且事件展示必须限定在安全摘要字段。原工作台把会话、对话、运行活动和产物堆叠在单一内容列中；当运行活动较多时，用户难以同时辨别当前会话、Agent 回复与可交付结果，也缺少窄屏下可用的导航方式。

本次只调整 `apps/web` 的表现层和本地交互，不增加 API、不会保存用户输入，也不会声称存在服务端尚未提供的会话历史或功能。

## 决策驱动因素

- 在桌面上同时维持会话上下文、对话焦点和可交付物可见性；
- 将可读的 Agent 对话与过程性工具活动清楚分层；
- 保持工具 payload 的最小披露边界；
- 支持键盘提交、可见焦点、语义化标签和移动端可达性；
- 不改变 ADR-0039 的轮询、导航代次与下载授权行为。

## 备选方案

### 方案 A：三段式工作台，右侧栏可折叠

左侧固定为会话导航，中部聚焦对话与输入，右侧承载活动安全摘要和交付物；右栏可由用户收起，窄屏时会话导航和右栏改为按需抽屉。优点是信息层级稳定且不遮蔽对话，缺点是实现与响应式样式更多。

### 方案 B：维持单列堆叠

优点是实现少；缺点是活动、产物与对话争夺同一阅读顺序，长运行时无法快速定位交付物。

### 方案 C：加入独立的“运行详情”页面

优点是可容纳更多信息；缺点是把同一次协作拆成多次导航，并需要额外路由和状态恢复，当前 API 不足以支撑。

## 选择

选择方案 A。中部仅渲染用户当前提交的请求、受限的助手文本和简短活动行；右侧重复呈现同一事件的安全摘要，以便在不离开对话的情况下扫描运行过程。它不读取或展示 `event.payload` 原文，继续由 `eventSummary` 作为唯一受限字段投影。

输入框支持 Ctrl/⌘ + Enter 提交；所有图标按钮有可访问名称、禁用状态和可见焦点。当前没有 Run 时显示引导空态，Run 创建后而尚未收到事件时显示加载空态，失败仍沿用 API 错误横幅与重试。

## 理由

该方案把用户的三个主要问题——“我在哪个会话”“Agent 在说什么”“产物是否可用”——分别映射到稳定区域。它只重组已有客户端状态，因而不会扩大可信边界或改变轮询时序。右栏折叠让较小桌面仍能优先阅读对话；移动端抽屉避免永久占用内容宽度。

## 影响

### 正面影响

- 桌面端可同时看到会话、对话和交付物；
- 运行状态有中文语义和颜色之外的文字表达；
- 无数据、运行中、错误和产物缺失都有明确反馈；
- 键盘和屏幕阅读器可识别主要操作与区域。

### 负面影响与成本

- 小屏需要打开会话或活动抽屉才能查看全部区域；
- 同一活动会在对话流和右侧摘要中出现，换取更快的扫描；
- 前端样式和展示组件增加，需要持续保持窄屏回归检查。

### 安全、数据与运维影响

- 不新增请求、持久化或身份信息；
- 活动与工具信息仍只来自 `eventSummary`，测试断言原始工具回执不会进入 HTML；
- Artifact 的预览和下载仍须通过既有授权 URL 解析流程。

## 验证

- `workspace-view.test.tsx` 验证运行状态文案、运行空态、工具回执最小展示、创建防重入，以及移动抽屉的 inert、Escape 和焦点往返；
- Web TypeScript typecheck、Vitest、Vite 生产构建和 Biome 检查通过；
- 人工以 320px、820px 和桌面宽度检查会话抽屉、右栏默认折叠、无水平溢出与焦点样式。

## 可逆性与回退

改动局限于 `apps/web` 展示组件、样式和本 ADR，不含迁移或协议改变。若需回退，恢复此前的单列入口即可；API、轮询和状态 reducer 无需数据修复。
