# ADR-0057：模型输出的安全 Markdown 展示边界

- 状态：已接受
- 日期：2026-07-30
- 决策者：Runtime 团队
- 关联任务/PR：前端模型输出支持 Markdown
- 替代关系：补充 ADR-0044

## 背景

ADR-0044 将模型的 `message.delta` 文本聚合为中部对话中的 Agent 回复，但当前实现使用普通段落节点，只保留换行，标题、列表、表格、链接和代码块都以 Markdown 源文本展示。模型输出属于不可信输入；若为支持 Markdown 而直接注入 HTML，原始 HTML、事件属性或危险 URL 协议可能越过浏览器安全边界。此外，Markdown 图片若直接渲染，会让模型文本触发浏览器向任意第三方地址发起请求。

本次仅改变 Web 展示层，不修改事件协议、聚合顺序、后端持久化或活动安全摘要规则。

## 决策驱动因素

- 支持常用 Markdown 与 GFM 表格、任务列表、删除线和自动链接；
- 对围栏代码块、行内代码和长表格提供可读且不破坏布局的样式；
- 禁止模型文本注入原始 HTML、脚本和危险链接协议；
- 阻止模型输出借助远程图片产生非用户发起的第三方网络请求；
- 将安全策略集中在独立展示组件中并用自动化测试锁定。

## 备选方案

### 方案 A：`react-markdown` 与 `remark-gfm` 的受限组件渲染

使用 React 节点构建 Markdown 结构，显式跳过原始 HTML，沿用库的安全 URL 转换，外部 HTTP(S) 链接使用新窗口和 `noopener noreferrer`，图片语法只显示替代文本。优点是无需使用 `dangerouslySetInnerHTML`，GFM 语义和 React 生命周期一致；缺点是增加一组固定版本依赖，并且暂不展示 Markdown 图片。

### 方案 B：Markdown 转 HTML 后使用消毒器注入

先生成 HTML，再按白名单消毒并通过 `dangerouslySetInnerHTML` 注入。优点是可选解析器较多；缺点是必须持续同步标签、属性、协议和插件生成物白名单，错误配置会直接形成 XSS 边界。

### 方案 C：自行实现少量 Markdown 规则

只处理标题、列表和代码围栏。优点是依赖少；缺点是 Markdown 嵌套、转义和增量输出组合复杂，容易产生不一致解析与安全缺口，GFM 兼容成本高。

## 选择

选择方案 A。新增 `AssistantMarkdown` 作为助手文本的唯一 Markdown 展示入口，使用精确版本的 `react-markdown@10.1.0` 与 `remark-gfm@4.0.1`。渲染器启用 GFM、设置 `skipHtml`，并显式使用 `defaultUrlTransform` 过滤危险协议；HTTP(S) 与协议相对的外部链接在新窗口打开，并附加 `noopener noreferrer`，相对链接保持当前窗口行为。

Markdown 图片不生成 `img` 节点，只输出可读的替代文本。代码块只进行结构与样式展示，本次不引入语法高亮器或执行任何代码。

## 理由

React 节点渲染避免引入 HTML 字符串注入点，显式关闭原始 HTML 又使安全意图不会依赖默认行为。成熟的 CommonMark/GFM 解析器比自制正则更能稳定处理嵌套、转义与流式增量形成的临时不完整语法。外部链接仍保持可用，同时新窗口隔离和协议过滤限制导航风险；远程图片降级则避免被动网络访问，在未来具备可信媒体代理前保持更小边界。

## 影响

### 正面影响

- 模型输出可展示标题、段落、列表、引用、表格、任务列表、删除线、链接与代码；
- 原始 HTML 不进入 DOM，危险协议不会保留为可导航链接；
- 模型文本无法通过图片语法触发第三方资源请求；
- 对话增量聚合、活动摘要和 API 契约保持不变。

### 负面影响与成本

- Web 生产包增加 Markdown 解析相关依赖和体积；
- Markdown 图片暂时只显示替代文本；
- 每次增量到达都会重新解析当前助手文本，超长回复的性能需在真实负载中继续观察。

### 安全、数据与运维影响

- 不使用 `dangerouslySetInnerHTML`，不启用 `rehype-raw`；
- URL 使用安全转换，外部网页链接带有新窗口隔离属性；
- 不新增持久化、服务端请求、环境变量或生产数据；
- 依赖使用精确版本并记录在 `pnpm-lock.yaml` 中。

## 验证

- `markdown-view.test.tsx` 验证 GFM 表格、任务列表、删除线、带语言代码块、原始 HTML 丢弃、危险协议过滤、外部链接隔离和远程图片降级；
- `workspace-view.test.tsx` 验证运行时间线的助手增量文本确实经过 Markdown 展示入口；
- Web Vitest、TypeScript typecheck 与 Vite 生产构建必须通过；
- 仓库级 `pnpm check` 在提交前执行并记录结果。

## 可逆性与回退

改动仅位于 Web 展示组件、样式和依赖，不含数据迁移。若需要回退，可恢复助手普通文本段落并移除两项依赖及本 ADR 对应实现，既有事件和客户端状态无需修复。

## 后续工作

- 在具备同源媒体代理与内容策略后，重新评估可信 Markdown 图片展示；
- 以真实长回复测量流式增量期间的解析开销，再决定是否需要节流或分段渲染；
- 如需语法高亮，单独评估高亮器体积、语言包范围和 HTML 安全边界。
