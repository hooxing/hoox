# ADR-0059：在 Agent 对话中内联交付 Artifact

- 状态：已接受
- 日期：2026-07-30
- 决策者：Runtime 团队
- 关联任务/PR：Agent 工作台交付物阅读路径优化
- 替代关系：补充 ADR-0039、ADR-0044 与 ADR-0042

## 背景

Artifact 已通过当前 Run 的受权读取接口投影到工作台。此前 Web 页面只在右侧活动栏提供 Artifact 列表；用户读到
Agent 的完成回复后，还必须横向切换视线并寻找侧栏才能预览或下载。这使“回复说明—交付物操作”脱离同一阅读路径，
也会在窄屏默认收起侧栏时隐藏主要入口。

现有 Artifact 读模型只声明其归属 Thread 与 Run，不声明其对应某个 `message.delta` 事件。因此页面不能把单个文件
可靠绑定到某一条流式文本消息。

## 备选方案

### 方案 A：继续仅在右侧活动栏展示

保留当前布局且没有实施成本，但用户必须离开 Agent 回复区域，窄屏还需要先展开侧栏，无法满足交付后立即操作的体验。

### 方案 B：在每条 Agent 消息中按时间戳猜测归属文件

视觉上最接近“每条回复附文件”，但 Artifact 与事件没有共同的稳定关联键。以时间戳或轮询批次推断会在并发、恢复和
重试后造成错误归属。

### 方案 C：在当前 Run 对话时间线后内联展示本次 Run 的 Artifact

将运行已经投影的全部 Artifact 紧随对话区展示，并在卡片中继续提供既有预览、下载动作；右侧栏只保留运行活动和
模型诊断，不再重复提供 Artifact 主入口。

## 选择

采用方案 C。内联卡片以“本次回复的可下载产物”标识其 Run 级归属，不声称文件精确来自某一条流式消息。只有当前
Run 存在且 Artifact 列表非空时才渲染；发布中的文件仍显示状态但预览和下载按钮保持禁用，已发布文件继续通过现有
受权 URL 和纯文本安全预览流程打开。

## 理由

Run 是 Artifact 在当前公开协议中唯一可靠且已受权的会话级关联边界。把它放在对话时间线后能缩短完成说明到文件操作
的路径，同时不需要新增 API、事件字段或错误的消息级推断。移除侧栏重复列表避免形成两个看似同等、实际可能因布局
隐藏而不一致的主入口。

## 影响

### 正面影响

- 文件名、可用状态、预览与下载紧随 Agent 回复区域呈现；
- 窄屏用户无需打开右侧栏即可取得交付物；
- 不改变 Artifact 授权、预签名 URL、媒体类型限制或文本转义安全边界。

### 负面影响与成本

- 交付物较多时会延长对话区域；
- 未建立单消息级关联，页面只能准确表达“本次 Run 的交付物”。若后续需要逐回复绑定，必须先扩展服务端契约并提供稳定
  关联键。

### 安全、数据与运维影响

- 仅改变已获取的 UI 投影，不新增请求、持久数据、浏览器权限或凭据流；
- 继续复用现有预览和下载处理，文本预览不以 HTML 注入页面。

## 验证

- 组件测试验证内联 Artifact 卡片保留预览、下载可访问名称；
- App 集成测试验证 Artifact 位于 Agent 对话区域、位于回复之后，右侧活动栏不再重复该文件；
- 执行 Web 定向测试、类型检查、Biome 检查以及工作区 `pnpm check`。

## 可逆性与回退

此改动不修改 API 或数据。回退时可恢复右侧列表并移除内联组件；既有 Artifact 事实、下载 URL 和预览行为不受影响，
无需数据迁移。

## 后续工作

- 若产品需要为每条 Agent 消息精确附加文件，设计并版本化 Artifact 到消息事件的稳定关联协议；
- 根据真实多文件任务观察是否需要折叠或按类型分组内联列表。

## 实施记录

- 2026-07-30：Web 工作台将当前 Run 的 Artifact 内联到对话区，并从右侧活动栏移除重复入口。
