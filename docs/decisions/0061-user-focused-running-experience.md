# ADR-0061：面向用户的运行状态体验

- 状态：已接受
- 日期：2026-07-30
- 决策者：Runtime 团队
- 关联任务/PR：面向用户的运行状态体验改造
- 替代关系：部分替代 ADR-0044 中的活动安全摘要展示

## 背景

现有工作台逐条展示 Run 事件，并在右侧重复展示“安全摘要”。即使内容已做字段限制，`callId`、工具生命周期和内部运行事件仍会让用户难以回答三个核心问题：运行是否继续、当前做到哪里、最终得到了什么。另一方面，现有创建 Thread API 要求非空标题，但让用户先命名会话会打断任务输入。

## 备选方案

### 方案 A：前端派生标题与紧凑运行投影

首条有效请求在浏览器按确定性规则清洗并截断为标题，随后按原有 `createThread(title)`、`createRun(input)` 顺序调用。事件仅在浏览器投影为有限的用户动作；右侧仅保留 Artifact。

### 方案 B：扩展后端协议，由服务端或小模型生成标题

可在所有客户端统一标题，但需要新增 API/持久化语义或模型依赖，且首版无必要承担失败与隐私边界。

### 方案 C：继续保留原始安全摘要

实现成本低，但仍把运行内部视为主要内容，不符合用户阅读目标。

## 选择与理由

选择方案 A。标题规则为压缩空白、移除常见 Markdown 标记、截断到 26 个字符并补省略号；有效请求不可能使用兜底值，仍保留“新任务”作为防御性回退。它与既有必填 `title`（1–200 字符）协议完全兼容，不修改 API、数据库或 Worker。

工具事件按内部 `callId` 仅用于合并开始/结束状态，永不进入可见文案。已知工具映射为“搜索网页、执行代码、生成文件、读取资料”等动作；未知工具落入“正在处理任务”。未知生命周期事件一律不显示。运行状态卡只回答当前是否运行、进度和等待输入；历史默认折叠。`message.delta` 聚合的正文与 `run_waiting.question` 则作为卡片外的正常 Agent 正文，不因状态结束、失败或取消而丢弃。`waiting` 是用户输入边界：仍可停止，但不显示运行动画、不累计时长，也不继续短轮询。

Agent 正文使用受控 Markdown：跳过原始 HTML，使用默认 URL 转换阻断危险协议，Markdown 图片退化为文本避免第三方请求，外部 HTTP(S) 链接使用 `noopener noreferrer` 新窗口隔离，并支持 GFM 表格、任务列表、删除线与代码块。每个字符串型 `message.delta` 都原样拼接（包括独立空格和空行）；waiting 问题不做前端截断，只有规范化后与完整正文完全相等时才去重。正文不设置内部高度或二次纵向滚动；只有代码块与表格可横向滚动，由中部运行区承载长回复。

## 影响

- 正面：用户不再需要输入标题；运行状态可持续感知且不被日志淹没；无 Artifact 时右栏自动收敛。
- 负面：工具映射是启发式，未知工具只能显示通用动作；客户端刷新后仍依赖既有最新 Run 恢复，不保存输入草稿。
- 安全：不新增业务网络请求或持久化；不渲染原始 payload、`callId`、回执或内部事件；模型 Markdown 不执行 HTML、不加载外部图片。
- 兼容：不变更公开 API、Thread 标题字段、Run 创建时序或取消、产物预览下载流程。

## 布局实现记录

桌面端采用固定高度应用壳：页面根节点禁止整体滚动，左侧会话列表、中部运行内容和右侧产物抽屉各自管理垂直滚动。会话标题和输入区在中部保持可见，长结果只在中部内容区域滚动。无 Artifact 时不渲染右侧占位栏；Artifact 到达后从会话顶部的“产物 n”文字按钮打开覆盖式抽屉。归档改为带文字的按钮，避免只凭图标猜测操作。

产物抽屉打开时把焦点移入关闭按钮，支持 Escape 和关闭按钮返回“产物 n”入口；若 Thread 切换使入口卸载，则回退到中部工作区，避免焦点停在隐藏节点。任务输入框禁用手动纵向拉伸，确保固定应用壳中的发送操作始终可见。

## 验证

- `event-view.test.ts` 验证生命周期过滤、工具聚合、流式文本空格/换行保真、waiting 问题和最终文本投影；
- `workspace-view.test.tsx` 验证紧凑组件不显示工具调用标识、waiting 不显示运行动画，右栏不存在安全摘要；
- `main.test.tsx` 验证首条请求自动创建 Thread 并使用确定性标题；
- 执行 Web 测试、typecheck、构建与全量 `pnpm check`。

## 可逆性

改动仅位于 Web 展示与输入编排，未写入新数据、未改变协议。若需回退，可恢复原有事件列表和显式标题输入；已创建 Thread 的标题仍是既有合法数据，无迁移或清理要求。
