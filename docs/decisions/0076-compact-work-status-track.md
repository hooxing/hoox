# ADR-0076：紧凑工作状态轨道与对话视觉去重

- 状态：已接受
- 日期：2026-08-01
- 决策者：Runtime 团队
- 关联任务/PR：工作台首轮可用性反馈
- 替代关系：替代 ADR-0072 的 Web 思考内容折叠入口；细化 ADR-0075

## 背景

工作台首版把思考记录和执行步骤分别放入两个相邻的折叠控件。两者层级相同、展开方向相同，却要求用户先判断要打开哪一个；在底部固定进度区内尤其显得拥挤。连续上下文还会在每轮正文后渲染“运行已完成。”，与固定进度区的完成状态重复。用户消息同时使用右侧气泡和“你”头像，任务列表虽然有 CSS 截断，但长标题仍然贴近侧栏边界。

## 决策驱动因素

- 固定进度区应当快速传达当前和历史工作状态，而不是成为第二个详情面板；
- 不在普通界面默认暴露模型逐字思考内容；
- 成功状态只保留一个权威展示位置，失败和等待等异常信息仍须可见；
- 对话双方仍需通过位置、气泡和 Agent 标识清楚区分；
- 已存量的长 Thread 标题不能依赖数据库迁移才能改善。

## 备选方案

### 方案 A：保留两个折叠控件并调整间距

改动小，但仍保留两个并列入口，无法解决用户需要选择详情类型的问题。

### 方案 B：合并为单个详情弹层

信息容量大，但引入新的遮挡、焦点管理和移动端交互成本，超出底部状态区的用途。

### 方案 C：使用横向工作状态轨道

把分析和通用执行步骤投影为紧凑状态项，在固定进度区内横向滚动并自动跟随最新项；不显示原始思考正文。完成通知、用户头像和长标题同时做视觉去重。

## 选择

选择方案 C：

- 思考仅投影为“分析任务”或“已完成分析”，与搜索、读取、代码执行、文件生成等步骤进入同一横向轨道；
- 轨道支持鼠标、触控板和触摸横向滚动，并在新状态到达时定位到末项；
- 删除 Web 端原始思考正文入口，但不改变事件持久化、恢复或服务端协议；
- 精确隐藏连续上下文中的“运行已完成。”，保留失败、取消和其他 Runtime 提示；
- 用户消息不再显示头像，继续通过右对齐气泡和“你的请求”标签区分；Agent 头像保留；
- 新 Thread 标题限制为 18 个 Unicode 字符，侧栏对存量标题按 16 个字符投影，完整标题仍保留在可访问名称和悬浮提示中。

## 理由

状态轨道能在有限高度内直接展示过程，不需要打开两个详情区。隐藏逐字思考内容减少内部文本和技术错误进入普通用户界面的风险，同时不损失任务是否正在分析、执行了哪些类型步骤等进度信息。其他三项去重都只改变前端投影，不影响事实数据。

## 影响

### 正面影响

- 运行区更紧凑，当前和历史步骤可以直接扫读或横向滑动；
- 成功提示、用户身份和长标题不再重复占用空间；
- 失败 Runtime 提示、Agent 身份、完整标题和连续上下文能力保持不变。

### 负面影响与成本

- 普通工作台不再查看逐字思考正文；诊断该内容需要使用受控的开发诊断渠道；
- 横向轨道不显示浏览器原生滚动条，需要通过内容露出和触控行为表达可滚动性；
- 存量标题只在显示层缩短，数据库中的原始标题不变。

### 安全、数据与运维影响

- 不修改 API、数据库、事件或 Artifact 契约；
- 不删除已持久化的思考事件，只减少普通界面的默认披露；
- 无迁移、配置或运维变化。

## 验证

- 组件测试验证横向状态项、逐字思考隐藏、完成通知去重和用户头像移除；
- 标题测试验证新建标题与存量侧栏标题的 Unicode 安全截断；
- 样式测试验证状态轨道 `overflow-x: auto` 且旧折叠样式已移除；
- 浏览器人工验收桌面与窄屏状态轨道、侧栏标题、对话身份和 Artifact 区；
- 执行 Web 测试、类型检查、构建和仓库 `pnpm check`。

## 可逆性与回退

全部改动位于 Web 投影层，没有数据迁移。可恢复旧折叠组件、完成通知、用户头像或完整标题显示；服务端事实和已有 Thread 数据无需回退。
