# ADR-0084：Runtime 直接回答与显式执行授权边界

- 状态：已接受
- 日期：2026-08-02
- 决策者：Runtime 团队
- 关联任务/PR：减少非必要工具调用并防止内容请求被擅自执行
- 替代关系：补充 ADR-0029，不替代其 Prompt 信任分层与能力清单结论

## 背景

现有 `PLATFORM_HARNESS` 限定了工具清单、Sandbox 与 Artifact 效果边界、低信任上下文以及
Compaction 所有权，但没有说明何时应调用工具。模型因此可能在仅凭已提供内容就能回答时仍读取
资源或运行命令；也可能把“给出一条命令”、“写一段示例”等内容请求当成执行授权。这会带来
多余延迟、费用和外部效果风险。

请求级文本、附件路径、Thread 或 Run 事实不能为此注入 system prompt。在相同能力配置下，
system prompt 必须保持字节稳定，以继续利用 Provider 上下文缓存和既有摘要审计链路。

## 决策驱动因素

- 能直接回答的请求不应支付工具往返的延迟与费用；
- 要求返回可执行内容不等于授权 Runtime 执行该内容；
- 必要的资源读取、易变事实核验和用户明确要求的外部效果仍需允许调用工具；
- 行为规范不能引入请求级 system prompt 变体，也不能削弱 Tool Router 和执行许可边界；
- Prompt 行为语义的变更必须可通过版本、摘要和 Golden 测试审计。

## 备选方案

### 方案 A：在固定 Platform Harness 中补充行为边界

将直接回答、必要工具调用和“内容请求不是执行授权”写成固定 Harness 条款。实现集中且可做
Golden 回归，代价是部署新版本后 Provider 会产生一次新 Prompt 缓存。

### 方案 B：由 Runtime 分类请求并动态注入 system/developer 指令

可以针对每个请求精细表达是否允许工具，但需要新的意图分类事实源；分类错误会阻断必要工具或开放非预期
执行，动态注入还会破坏 system prompt 字节稳定性。

### 方案 C：仅依赖用户措辞和模型默认行为

不需要代码变更，但用户必须反复声明“不要执行”，不能形成可回归的 Runtime 行为契约。

## 选择

采用方案 A：

1. 若当前对话和已提供内容足以正确回答，Agent 直接回答。不为展示过程、确认已知事实或收集
   非必要信息调用工具。
2. 仅当完成用户请求确有必要时调用工具。该条款不禁止读取用户要求处理但尚未提供的内容、核验
   必须准确的易变事实，或产生用户已明确要求的外部效果。
3. 当用户要求给出或展示命令、示例、代码或文本时，Agent 将它作为答案内容返回，不擅自执行。只有用户同时明确
   要求执行、验证或应用，才能将所给内容作为工具输入。
4. 三项规范均使用 `prompt-builder` 内的固定文本，不接收请求级开关或内容。相同 capability manifest
   下，不同 Tenant、Skill、User 上下文重建出字节一致的 system prompt。
5. 将 Runtime Prompt 版本升级为 `runtime-system-prompt.v2`；输入 schema 和 capability manifest 格式仍为 v1。
   `promptDigest` 按新字节重新计算。
6. ADR-0029 的工具白名单、Sandbox/Artifact 效果、低信任上下文和 Compaction 边界保持不变。
   Harness 不能取代 Tool Router 授权、执行许可或业务校验。

## 理由

固定 Harness 能在不引入新信任输入的情况下表达通用意图边界。“仅在确有必要时调用”而非“不调用”，
保留了处理未提供资源和易变事实的能力。把“给出可执行内容”与“执行该内容”分开，则使请求的外部效果与
用户明示授权对齐。版本升级让运维诊断能区分新旧行为契约，而摘要仍提供精确字节证据。

## 影响

### 正面影响

- 简单问答不再因不必要工具调用延迟；
- 命令、示例、代码和文本的生成请求不再自动扩大为执行请求；
- 相同能力配置的后续请求仍共享字节稳定的 system prompt。

### 负面影响与成本

- 发布 v2 时 Provider 需要为新 system prompt 建立一次新缓存；
- “确有必要”仍由模型结合请求判断，Prompt 不是可形式化证明的意图分类器；
- 新旧 Session 在滚动发布期可能分别使用 v1 和 v2，诊断必须结合 Prompt 版本和摘要解释。

### 安全、数据与运维影响

本决策不新增工具、凭据、网络出口、持久数据或宿主机权限。模型仍只能调用 capability manifest 中的
工具，并经 Tool Router 和既有许可校验产生效果。不得记录完整低信任内容；Prompt 版本与摘要继续可用于审计。

## 验证

- Prompt Builder Golden 测试固定 v2 的全部 Harness、manifest 和 Prompt 摘要；
- 契约测试断言直接回答、必要工具调用和显式执行三项边界；
- 契约测试替换请求级 Tenant、Skill、User 内容，断言相同能力配置的 system prompt 字节一致；
- Pi Session 装配测试断言 Provider 可见 system prompt 含新规范，低信任攻击文本仍不进入 system role；
- `pnpm check` 通过格式、静态分析、类型、单元测试、构建与配置门禁。

## 可逆性与回退

本变更不涉及持久 Schema 或数据迁移。可回退 Prompt Builder 和 Pi 诊断期望以恢复 v1，已记录的 v2
摘要保留为历史证据；回退会重新开放非必要工具调用和内容请求被误执行的风险，应通过正常发布而非运行时
动态降级完成。

## 后续工作

- 通过脱敏指标观察每轮工具调用数和用户要求纯内容时的工具调用率；若仍有系统性偏差，新增可重放的模型行为评测，
  不把用户原文注入 system prompt。
