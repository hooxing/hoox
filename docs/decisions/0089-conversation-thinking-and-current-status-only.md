# ADR-0089：思考归入对话与单一当前状态

- 状态：已接受
- 日期：2026-08-03
- 决策者：Runtime 团队
- 关联任务/PR：浏览器批注后的运行信息层级调整
- 替代关系：替代 ADR-0085 的底部思考披露位置，以及 ADR-0076 的历史状态轨道

## 背景

思考正文放在底部固定进度区后，会与 Agent 最终回答分处两个阅读区域。运行完成时，底部又同时出现
“已完成本次任务”“已完成分析”和“思考已完成”，同一个结果被重复表达。用户真正需要的是在对话中按需
阅读思考正文，并在底部一眼看见任务当前所处状态，而不是浏览已经经过的状态历史。

## 决策

1. 思考披露区从底部状态卡移入对应 Run 的 Agent 对话消息，位于最终回答正文之前。运行中尚无最终回答时，
   先创建同样的 Agent 消息承载实时思考；最终回答进入 Thread Context 后，披露区附着到同一 Run 的持久化
   Assistant 消息，避免重复回答或改变阅读顺序。
2. 思考仍沿用原生 `details/summary`、安全 Markdown、运行中展开、完成后折叠、异常终止停止动画和用户手工
   展开保持等既有契约。展开区参考主流对话产品保持约三行正文高度，超出内容在区域内滚动，避免长思考
   挤占最终回答和输入区。
3. 底部状态卡只显示一个当前状态：思考、搜索、读取、执行代码、生成文件、等待输入、完成、失败、取消或
   恢复中断。删除历史步骤轨道、完成计数和“已完成分析”等重复投影。
4. 事件、数据库、API、授权和思考正文安全边界不变；本决策只改变 Web 投影与组件组合。

## 影响

- 思考和最终回答处于同一阅读路径，三行视窗既能确认实时方向，又不会持续挤占对话空间。
- 状态卡的信息密度降低，只回答“现在进行到哪里”，不再承担历史审计作用；历史事实仍保留在 durable 事件
  和开发诊断中。
- 当前 Run 的 Assistant Context 是否已经持久化必须按 `runId + assistant role` 判断，不能只凭同 Run 的任意
  User/Runtime Context 隐藏流式消息。

## 验证

- 组件测试覆盖思考仅出现在 Agent 消息、与持久化最终回答同卡且顺序正确、运行中自动展开和异常终止收敛。
- 状态测试覆盖运行中只显示当前动作、成功只显示“已完成”，且 DOM/CSS 不再包含历史状态轨道。
- 执行 Web 测试、类型检查、构建及仓库 `pnpm check`。

## 可逆性

改动不涉及迁移。恢复旧组件组合和样式即可回退，不影响已有 Run 事件或 Thread Context。
