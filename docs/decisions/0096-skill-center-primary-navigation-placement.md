# ADR-0096：Skill Center 主导航入口位置

- 状态：已接受
- 日期：2026-08-03
- 决策者：Runtime 维护者
- 关联任务/PR：Skill Center 入口布局调整
- 替代关系：细化 ADR-0044 与 ADR-0094 的 Web 导航布局

## 背景

ADR-0094 已在工作台侧栏提供技能中心入口，但初版把入口放在可滚动任务列表之后。任务数量增加时，技能中心会远离主要操作区，也无法与“新建会话”共同表达工作台的全局操作。用户要求把技能中心固定放在新建会话下方、任务列表上方。

## 决策驱动因素

- 技能中心和新建会话都是全局操作，不从属于某个任务；
- 入口位置不能随任务数量变化；
- 桌面端和移动导航应复用相同 DOM 顺序；
- 不改变技能中心的权限、安装语义和 Sandbox 边界。

## 备选方案

### 方案 A：放在新建会话下方

把技能中心作为第二个全局入口，随后才展示任务标题和任务列表。层级明确，且入口位置稳定。

### 方案 B：继续放在任务列表之后

不需要修改，但长任务列表会使入口远离顶部主操作区，并把全局能力视觉上混入任务导航。

### 方案 C：放入独立设置菜单

能减少侧栏入口数量，但会增加发现和安装技能的操作层级；当前工作台也没有承载该入口的通用设置菜单。

## 选择

采用方案 A。只要当前 API 装配了完整 Skill Center 能力，就在 `ThreadCreate` 后立即渲染技能中心按钮，并在按钮后渲染任务标题与任务列表。

## 理由

该顺序直接体现“全局操作在前、任务导航在后”的信息层级，同时保持技能中心现有的按能力显隐、弹窗行为和移动端关闭导航行为。方案 B 无法解决入口随任务列表下沉的问题；方案 C 为一次位置调整引入了额外导航结构。

## 影响

### 正面影响

- 技能中心入口在任意任务数量下都紧邻新建会话；
- 桌面端和移动端使用一致的导航顺序；
- 不需要新增 API、状态或样式契约。

### 负面影响与成本

- 侧栏顶部的全局入口区域增加一行高度；
- 熟悉旧位置的用户需要适应一次入口移动。

### 安全、数据与运维影响

- 不改变身份认证、用户安装关系、目录数据或对象存储；
- 不触发 Sandbox，也不扩大 Skill Center 的能力范围；
- 无数据迁移和额外运维配置。

## 验证

- Web 组件测试断言 `thread-create` 的下一个同级元素是 `skill-center-entry`，且其后是任务标题；
- 在本地工作台分别以桌面视口和移动导航人工确认入口可见、顺序正确且仍可打开技能中心。

## 可逆性与回退

改动仅调整 React 元素顺序，可在任意时间把按钮移回任务列表之后；不涉及数据写入或不可逆迁移。

## 后续工作

- 技能中心引入新的全局入口时，继续遵守全局操作与任务导航分组边界。
