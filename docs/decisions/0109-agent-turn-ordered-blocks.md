# ADR-0109：Agent 回合采用有序内容块投影

- 状态：已接受
- 日期：2026-08-04


## 背景

运行事件包含多段思考、模型正文和工具调用。旧页面分别合并全部思考与全部正文，并把持久化的每条 assistant 消息渲染成独立头像，既丢失过程顺序，也容易让用户误认为一次任务由多个 Agent 分别回答。

## 决策

- 以一次 Run 作为一个 Agent 回合，头像和名称只属于回合。
- 前端按事件顺序投影 `thinking`、`answer` 和 `tool` 内容块。
- 每段回答作为执行阶段边界；思考、读取、命令等低信息过程合并进同一个默认折叠区，展开区只列出已经执行结束的项目，不推测后续步骤。
- 折叠摘要始终停留在最后一个已完成动作；存在运行中动作时显示当前动作，不展示“已完成 N 项”等计数噪声。
- 展开后的思考与工具使用同一行式视觉语言；思考行仍可二次展开查看正文，但不再使用独立的大块状态样式。
- 创建与修改文件属于高价值事实，携带真实文件路径并在对话中直接展示，不纳入过程折叠。
- 写入、修改、交付事件分别从 `path`、`name` 等真实参数生成标题；`deliver_file` 与 `publish_artifact` 也必须显示实际交付物名称。
- 工具块通过 `callId` 原位更新状态；服务端从文件工具参数生成安全 `presentation`，前端不接触原始参数。
- 只有 `exec_command` 增加可选 `user_facing_purpose`。模型仅在说明执行目的能帮助用户理解时填写；真实命令仍是执行和审计依据。
- 没有标题或目的的未知工具完成后不再单独显示含义不明的“已完成”，只作为执行阶段中的一项。
- 交付物继续归属于整个 Run，并位于回合内容之后。

## 影响

用户可以按真实顺序阅读“回答—执行阶段—回答”，同时不会看到重复头像或成排的低信息状态。命令目的属于辅助展示，不参与授权、参数摘要或执行语义；文件名称来自真实参数。该投影可以通过恢复旧分组组件回滚，命令可选字段向后兼容既有调用。

## 验证

通过 Pi Adapter 测试覆盖安全展示投影和命令可选字段，通过 Web 单元测试覆盖回答边界分组、只展示已完成项目、文件操作直出和单回合头像，并执行格式、类型及测试检查。
