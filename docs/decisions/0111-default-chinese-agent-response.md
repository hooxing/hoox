# ADR-0111：Agent 默认使用中文回答

- 状态：已接受
- 日期：2026-08-05
- 决策者：Runtime 团队
- 关联问题：中文产品界面中的 Agent 回答语言不稳定

## 背景

Runtime 的固定 Platform Harness 尚未规定默认回答语言。即使用户、界面和工具说明均使用中文，模型仍可能根据
推理内容、Skill 指令或训练偏好切换为英文，导致同一产品中的回答语言不一致。

回答语言属于稳定的平台交互约定，不应作为用户或 Run 级动态内容注入，否则会破坏 system prompt 的字节稳定性
和 Provider 上下文缓存。

## 备选方案

### 仅依赖模型根据用户语言自行判断

无需修改 Prompt，但不同模型和任务下的行为不稳定，实际运行已经出现中文请求得到英文回答。

### 通过每次 Run 的动态上下文指定语言

可以按请求控制，但会把稳定产品规则变成请求级事实，并增加 Prompt 组合和缓存的不确定性。

### 在固定 Platform Harness 中声明默认语言

同一能力配置下保持字节稳定，同时允许用户明确要求其他语言，不限制翻译等合法任务。

## 决策

选择第三种方案：

- 在固定 Platform Harness 末尾增加“使用中文进行回答，除非用户明确要求使用其他语言”；
- 用户明确指定其他语言时，以用户要求为准；
- Runtime Prompt 版本从 `runtime-system-prompt.v6` 升级为 `runtime-system-prompt.v7`；
- 不向请求级上下文、Skill 目录或工具 Schema 注入语言配置。

## 影响

- 新建 Run 默认得到中文回答，跨模型行为更一致；
- 翻译、外语写作等明确语言请求不受影响；
- 新旧 Worker 在滚动更新期间可能分别产生 v6 与 v7 Prompt，可通过 Prompt 版本和摘要诊断；
- Prompt 固定前缀发生一次版本化变化，v7 后相同能力配置仍可复用上下文缓存。

## 验证

- Prompt Builder 测试验证 v7 固定 Harness 包含默认中文及用户显式覆盖规则；
- Golden Prompt 快照验证完整输出、版本和摘要同步变化；
- Prompt Builder typecheck、单元测试、格式和 lint 作为提交门禁。

## 可逆性与回退

该改动不涉及 Schema 或持久数据。回退代码并恢复 v6 即可撤销，但 Agent 回答语言将再次由模型自行判断。
