# ADR-0114：Skill Front Matter 元数据预填

- 状态：已接受
- 日期：2026-08-05

## 背景

受管 Skill 发布表单要求规范键、显示名称、描述、许可证、发布者、版本、兼容性和来源等元数据。标准 Skill 的根级 `SKILL.md` 通常已经用 YAML Front Matter 声明 `name`、`description` 和 `license`，要求管理员重复录入既低效又容易产生不一致。

另一方面，浏览器目录选择器不会暴露可信的本地仓库地址、提交 SHA 或发布者身份。系统不能为了减少输入而伪造来源和版本，也不能把客户端解析结果提升为服务端可信输入。

## 备选

1. 保持全部字段人工填写。实现简单，但重复劳动和录入偏差持续存在。
2. 浏览器选择文件后解析根级 `SKILL.md`，仅预填可验证的声明字段，所有字段仍可编辑，服务端继续执行完整校验。
3. 服务端只接收文件并替管理员生成全部发布元数据。交互最短，但无法可靠推断来源、版本和发布者，并会削弱现有溯源边界。

## 选择

采用方案 2。管理 Web 在文件进入网络前读取根级、严格 UTF-8、最大 64 KiB 的 `SKILL.md`，解析受限的 YAML Front Matter 标量：

- 标准 `name` 预填规范键和显示名称；规范键经过确定性规范化。
- `description` 预填描述。
- `license` 为单个许可证标识时预填许可证字段；以 `Proprietary` 开头时映射为 `LicenseRef-Proprietary`，完整声明仍保留在 `SKILL.md` 和包内许可证文件中。
- 若包显式声明 `display_name`、`publisher`、`version`、`compatibility`、`source_url`、`source_revision` 等扩展标量，在通过本地形状检查后也可预填。
- 发布者、版本、兼容性和来源无法可靠推断时保持为空，必须由管理员确认。

解析器不执行通用 YAML 标签、锚点或对象反序列化。预填只是便利功能，创建请求、确定性包摘要和服务端发布校验保持不变。

## 影响

- 正面：标准 Skill 通常可自动填写规范键、显示名称、描述和许可证，减少重复输入。
- 负面：受限解析器不覆盖所有 YAML 语法；复杂 Front Matter 需要人工填写。
- 安全：文件只在浏览器本地解析，不新增上传接口；来源与发布身份不得由文件路径或目录名冒充。
- 兼容：没有 Front Matter、编码异常或入口不在根级时显示稳定提示，不阻止管理员手动录入。

## 验证

- 单元测试覆盖标准 `docx` 形状、Proprietary 映射、折叠描述、扩展字段和无入口失败。
- 组件测试验证选择目录后表单值和审阅提示可见。
- 既有 API 与包校验测试证明服务端契约未放宽。

## 可逆性

删除管理 Web 的预填解析器和提示即可回退；请求协议、数据库和已发布数据均未改变。
