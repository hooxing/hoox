# ADR-0115：系统兼容性、可选上游来源与 Skills CLI 导入边界

- 状态：已接受
- 日期：2026-08-05

## 背景

标准 Agent Skill 通常只在 `SKILL.md` Front Matter 声明 `name` 和 `description`。上传者无法可靠判断自由文本“兼容性”，本地目录也不暴露可信的仓库 URL 或 Git commit。把这些字段设为普通上传必填会诱导用户填写猜测值，降低而非提高数据质量。

生态中广泛使用 `npx skills add owner/repo` 从 Git/GitHub 来源发现并安装多个 Skill。该 CLI 的目标是向本机 Agent 的项目或全局目录写文件，可创建符号链接或副本，并带有独立遥测和更新语义；它不是平台发布审核 API。

## 备选

1. 继续要求上传者填写兼容性、来源 URL 和 revision。实现不变，但字段没有可靠证据。
2. 普通上传由系统设置格式兼容性，来源可选并以包摘要标识实际字节；Git 导入时再自动记录 URL 和不可变 revision。
3. 在管理 API 进程内直接执行用户粘贴的 `npx -y skills add ... -g --all`。接入最快，但会执行浮动 npm 代码、写宿主全局目录、扩大网络和文件权限，并绕过发布队列的包边界。

## 选择

采用方案 2，并拒绝方案 3 的直接进程内执行：

1. 创建请求的 `compatibility`、`sourceUrl`、`sourceRevision` 改为可选。
2. 未声明兼容性时由管理 API 固定为 `Agent Skills 标准格式`；运行工具、系统包和模板能力属于后续结构化依赖检查，不由上传者猜测。
3. 本地上传可以不声明上游来源。数据库保存空来源，实际文件身份继续由规范包 SHA-256 和每文件摘要保证。
4. 来源字段移入“高级溯源信息”，名称改为“上游仓库地址”和“上游提交/版本”。
5. 后续仓库导入器兼容官方 Skills CLI 的 GitHub shorthand、完整 Git URL和特定 Skill 选择语义，但必须固定已审计的 CLI 版本或直接实现等价只读解析，在隔离临时目录中禁用遥测、禁止写全局 Agent 目录。
6. 仓库导入只创建 `restricted` 草稿，自动记录规范仓库 URL、解析后的 commit SHA 和包摘要；批量导入不得自动审核或发布。

## 影响

- 普通目录上传少填三个没有可靠证据的字段。
- 已有带来源的客户端继续兼容，响应仍以字符串返回来源，未声明时为空字符串。
- `skill_versions.compatibility` 继续保持非空，公开目录协议不变。
- Git 批量导入可以复用生态来源表达，但必须作为独立受限导入能力实现，不能给管理 API 增加任意命令执行入口。

## 验证

- 协议测试覆盖最小创建请求和空来源响应。
- API 测试验证默认兼容性及空来源持久形状。
- 包校验和数据库迁移测试覆盖空来源、长度、空白及控制字符约束。
- 管理 Web 组件测试验证普通提交不发送三个可选字段。

## 可逆性

若不存在空来源发布事实，可回滚数据库约束并恢复请求必填；迁移会在发现空来源事实时失败关闭，避免不可逆数据截断。默认兼容性只是普通字符串，可通过后续结构化兼容模型替代。
