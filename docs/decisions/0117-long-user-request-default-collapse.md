# ADR-0117：超长用户请求默认折叠

- 状态：已接受
- 日期：2026-08-06
- 决策者：Runtime 团队
- 关联问题：ADR-0116 修复横向溢出后，数千字符用户请求仍占据过多纵向空间
- 替代关系：补充 ADR-0116，不改变其可收缩布局边界

## 背景

ADR-0116 保证超长用户请求始终位于可视区域内，但完整展示数千字符的 JSON 或工具 Schema 会让单条用户消息占据
数个屏幕，用户必须滚动很远才能看到 Agent 回答。用户消息顶部的“你的请求”标签也重复表达了右对齐气泡已经明确的身份。

通过 Chrome DevTools 对同类内容在 ChatGPT Web 中的折叠状态进行测量：折叠正文最大高度为 264px，行高 24px，
底部使用 48px 渐隐遮罩，展开按钮高度为 24px。该尺寸约保留 11 行内容，既能帮助识别请求，又不会遮挡后续回答。

## 决策驱动因素

- 默认视图应优先展示任务开头和 Agent 回答；
- 用户输入必须完整保留，并能原地展开和收起；
- 短消息不能出现无意义的展开按钮；
- 已持久化消息与发送中的消息应使用相同规则；
- 控件必须暴露明确的展开状态并支持键盘操作。

## 备选方案

### 方案 A：按固定字符数截断文本

实现简单，但等宽 JSON、中文、英文和多行文本的实际高度差异较大，字符数不能准确代表可见行数；还需要拼接展示文本，
容易误导复制和阅读。

### 方案 B：保留完整 DOM，按 264px 视觉高度折叠并测量溢出

正文始终完整存在，折叠态通过 `max-height`、`overflow: clip` 和 48px 渐隐实现。组件测量 `scrollHeight`，只有实际
超过折叠高度时才显示按钮；初始渲染同时使用保守的字符数和换行数判断，避免长消息先完整闪现。

### 方案 C：所有用户消息默认折叠

交互一致，但短问题也需要额外点击，降低普通会话的可读性。

## 选择

选择方案 B，并移除用户气泡中的“你的请求”标签：

- 折叠正文高度固定为 264px，底部 48px 渐隐；
- 超过 600 字符或 11 个显式文本行时，首帧默认按长消息处理；挂载后以实际 `scrollHeight` 校正；
- 折叠按钮显示“展开”，展开后显示“收起”，并通过 `aria-expanded` 暴露状态；
- 已持久化用户请求和待处理用户输入共用同一个消息组件；
- 短消息完整展示且不出现折叠按钮。

## 理由

该方案复用 ChatGPT 已验证的视觉高度，同时使用真实布局测量避免字符截断造成的误判。完整文本不被修改，展开状态只属于
浏览器视图，不进入 Thread 或 Run 数据模型。移除冗余标签后，气泡能多展示一行实际请求内容。

## 影响

### 正面影响

- 长请求默认只占约 316px 气泡高度，后续 Agent 内容更快进入视口；
- 用户可随时原地查看和收起完整输入；
- 短消息和现有右对齐视觉保持简洁；
- 不影响复制、持久化和发送内容。

### 负面影响与成本

- 每条用户消息挂载时需要一次高度读取，并在宽度变化时重新判断；
- 展开状态刷新后恢复默认折叠，不跨会话持久化；
- 渐隐区域中的部分文字在折叠态不可直接阅读，需要点击展开。

### 安全、数据与运维影响

- 不改变 API、数据库、权限、日志或模型输入；
- 不新增依赖，不执行用户文本，也不把文本发送到第三方；
- ResizeObserver 不可用时仍保留首帧启发式折叠。

## 验证

- 组件测试覆盖移除“你的请求”、长消息默认折叠、短消息不显示按钮以及展开/收起状态；
- 样式契约测试覆盖 264px 最大高度、48px 渐隐和 24px 控件高度；
- Web 测试、类型检查、格式检查、lint 和生产构建通过；
- 在本地 785px 视口使用原 6487 字符请求验证，默认气泡高度接近参考尺寸，展开后全文可见。

## 可逆性与回退

删除用户消息折叠组件和对应样式即可恢复 ADR-0116 的完整纵向展示。没有数据迁移或不可逆状态。

## 后续工作

- 如未来需要跨刷新记忆展开状态，应单独评估 Thread 级 UI 偏好存储，不扩展当前消息协议。
