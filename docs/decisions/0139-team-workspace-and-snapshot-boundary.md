# ADR-0139：团队工作空间、任务分支与跨空间文件快照

## 状态

已接受（试验版）。

## 背景

个人任务、团队任务、云盘文件和 Skill 原先都依赖单一 TenantScope。团队版如果只在前端增加分组，会造成团队退出后仍可借旧引用读取文件、团队任务多人并发覆盖同一上下文、以及团队运行隐式使用成员个人 Skill 等权限错误。

产品同时要求：左上角“新建会话”始终代表个人空间；侧栏增加默认折叠的团队入口；用户可加入多个团队但界面不能同时铺开全部团队；个人任务可发布到团队；团队任务可以并行发展；团队文件可以被个人任务使用；最后一名 Owner 既可转移所有权，也可选择解散团队。

## 决策

### 单一活动工作空间

客户端任一时刻只有一个活动 Tenant。团队入口是默认折叠的切换器，只显示当前选择的团队及一个下拉列表，不为每个团队常驻渲染任务树。左上角“新建会话”会先回到个人 Tenant；团队新对话只能从已选择团队的入口创建。

`X-Tenant-ID` 仍只是租户选择器。API 每次都以 JWT/开发 principal 的 UserId 重新读取有效 Membership，选择器本身不构成授权。

### 任务发布与分支

“个人任务转团队”实现为“发布到团队”：在目标团队创建新的 Thread，保留来源关系并复制当前可见的 user/assistant 消息快照；源个人 Thread 不变，双方之后不做双向同步。

团队任务的“新建分支”同样创建独立 Thread。每个分支有自己的 Workspace、上下文流和执行队列，可以并行运行；同一 Thread 内仍保持串行输入语义，避免并发写共享上下文。

首个试验版只复制 V2 上下文中可见的 user/assistant 文本，不复制工具轨迹、Run、Workspace revision 和来源 Tenant 的 Resource 引用。超过 5000 条可见消息时失败关闭，由后续异步复制任务替代。

### 成员与解散

角色为 Owner、Admin、Member。Owner 可调整全部角色；Admin 只能管理普通成员，不能授予 Owner。最后一名 Owner 不能被普通移除或降级，但可显式解散团队。解散先撤销团队目录，再在同一事务中撤销全部 Membership；Tenant 和历史事实保留为不可访问的审计数据。

创建者退出团队后，其创建的团队任务仍属于团队。读取任务只要求当前访问者 Membership 有效，不再要求任务创建者仍为有效成员。

### 云盘与退出语义

云盘同时展示“个人云盘”和“当前团队云盘”两栏，两者分别在自己的 Tenant 下查询。

个人任务不能保存指向团队 Blob 的长期跨租户引用。选择团队文件加入个人任务时，API 先复核来源团队 Membership，读取稳定对象，再通过个人资源上传协议创建不可变个人副本。退出团队后：

- 已经复制并在对话中使用的个人副本继续可用；
- 团队云盘不再可见；
- 新对话不能再次选择或导入该团队文件。

### 团队 Skill

Skill 目录仍是全局只读内容，安装关系从用户全局迁移为 Tenant 级安装。个人 Tenant 保留迁移后的个人安装；新团队从空策略开始，不继承任何成员的个人 Skill。团队 Owner/Admin 可安装、配置和卸载，Member 可读取并在团队 Run 中使用。Run 创建时只快照当前 Tenant 的启用 Skill。

## 数据与安全边界

- `team_member_directory` 只负责跨 Tenant 的用户可见索引，Membership 始终是授权事实源。
- 团队成员、任务分支和 Tenant Skill 表均启用 FORCE RLS。
- 团队目录写入与成员角色变化只经 ADR-0147 的独立 Team Coordinator 连接完成；普通 Runtime 仍不能更新 Membership 授权列。Skill 管理和解散继续受数据库角色最小列权限约束。
- Thread 来源只保存不可变标识，不建立跨 Tenant 级联删除关系。

## 影响

优点：个人与团队权限链清晰；退出语义可验证；任务并行不需要放弃单 Thread 串行不变量；团队运行不会泄漏成员个人 Skill。

代价：发布到团队是快照而非移动；跨空间文件会占用两份逻辑资源；当前团队创建后需要相应 Worker 分片才能执行；超大或旧版上下文尚不能直接分支。

## 后续

后续版本补充邀请链接和待接受状态、团队重命名、所有权转移专用流程、异步大任务发布、资源配额、审计日志、团队级模型/工具策略，以及 Worker 对动态团队 Tenant 的调度。

## 验证

领域测试覆盖团队创建、角色变化和解散 Owner 撤销；迁移测试覆盖团队目录、分支来源和 Tenant Skill RLS；API 测试覆盖开发租户切换、团队目录/解散、独立任务分支，以及退出团队前后文件导入语义；Web 类型检查和组件测试覆盖现有个人流程的兼容性。

## 可逆性

界面入口与 API 路由可独立关闭。团队表可在开发/测试环境通过成对迁移回退；已产生的团队安装与协作事实在生产环境不应通过回退删除。发布出的 Thread 和复制到个人空间的 Resource 是独立事实，不随功能开关自动合并或删除。
