# ADR-0141：标签式云盘与跨空间范围搜索

## 状态

已接受（试验版）。

## 背景

ADR-0139 将个人云盘和当前团队云盘设计为并排两栏。这个布局只有一个团队时直观，但团队数量增加后只能继续增加子窗口或在并排面板中叠加更多选择器，既压缩文件列表，也让搜索范围不清楚。

侧栏团队区还同时存在标题上的“切换团队”提示和展开区内“新建团队对话”按钮。团队选择已经由展开后的下拉框负责，重复入口占用了任务列表空间。

## 决策

### 单内容区标签云盘

云盘对话框改为“个人云盘”和“团队云盘”两个标签，共用一个内容区，不再并排渲染两个文件面板。团队标签始终只展示一个已选团队，通过单一下拉框切换团队；团队数量不会增加常驻文件子窗口。

标签只控制日常浏览。个人与团队文件仍分别通过自己的 Tenant API 读取，Resource 身份、下载授权和退出团队后的不可见语义不变。

### 独立的跨空间搜索

搜索栏独立位于标签上方。用户可以选择以下范围：全部空间、仅个人云盘、全部团队或某个指定团队。搜索请求通过显式 Tenant API 并行读取所选空间，不修改当前对话的活动 Tenant。

搜索结果合并到一个滚动列表，并在每个任务上标明个人或具体团队来源；不同 Tenant 的 Thread 或 Resource 标识仍以来源空间组成复合键，不能被误合并成同一对象。每个来源继续使用既有查询边界。

跨空间搜索只扩大可发现范围，不扩大可引用权限：

- 个人对话可以直接选择个人文件，也可以把仍有权限的团队文件导入为个人不可变快照；
- 团队对话只能选择当前活动团队的文件；个人文件和其他团队文件可搜索、下载，但不能直接作为该团队对话的附件；
- 所有下载和导入操作仍由服务端复核当前 Membership。

### 团队新增对话入口

团队标题右侧改为常驻“新增对话”按钮；标题主体只负责展开或折叠团队任务。展开区移除重复的“新建团队对话”按钮，团队切换继续由下拉框负责。

## 影响

优点：云盘在任意团队数量下都保持单一文件视图；搜索范围明确；跨空间结果在一个列表内保留来源；团队新增对话入口在折叠状态下也可直接使用。

代价：全空间搜索会按可访问空间发起多个只读请求；统一排序时仍必须保留 Tenant 来源；当前仍没有服务端统一搜索索引。

## 验证

- 组件测试覆盖个人/团队标签、团队单面板切换、范围选项以及个人与多个团队的并行搜索。
- 团队侧栏测试覆盖标题右侧“新增对话”入口，并确认展开区不再出现重复按钮。
- Web 类型检查、格式检查、Lint 和组件测试作为本地门禁。
- 浏览器复验云盘标签、范围搜索、团队切换以及侧栏折叠和新增对话布局。

## 可逆性

界面可以恢复为并排两栏；显式 Tenant API、文件事实和授权模型无需回退。跨空间搜索没有写入新的服务端索引或持久状态，关闭入口即可停止使用。
