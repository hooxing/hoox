# ADR-0146：团队目录个人作用域与失效 Tenant 自愈

- 状态：已接受（试验版）
- 日期：2026-08-10
- 决策者：Runtime 团队
- 关联任务/PR：`codex/team-edition-prototype`
- 关联决策：ADR-0016、ADR-0131、ADR-0132、ADR-0140

## 背景

Web 客户端用一个活动 Tenant 驱动团队对话、文件和技能请求。旧实现也把该 Tenant 隐式附加到“我的团队”目录和创建团队请求，并让成员管理请求依赖当时的全局活动值。用户退出、解散当前团队，或可丢弃测试库重建后，页面可能仍持有已经不存在的 Team ID。此时团队目录自身先被 RLS 拒绝为 404，用户无法通过刷新目录切换或恢复到个人空间，后续上传也会持续发往失效 Tenant。

团队目录的授权事实是当前 User 的有效 Membership 集合，不属于某一个 Team；成员管理的授权事实则是 URL 中明确指定的目标 Team。两者不应依赖可能过期的 UI 全局状态。

## 备选方案

### 方案 A：遇到 404 时要求用户刷新整个页面

不采用。页面重载不保证清除客户端状态，也把正常的退出、解散竞态变成用户手工恢复流程。

### 方案 B：服务端忽略团队目录请求携带的错误 Tenant

不采用。它会弱化统一认证边界，并掩盖其他真正需要 Tenant 一致性的错误请求。

### 方案 C：客户端为不同控制面显式选择作用域并在目录刷新时收敛状态

采用。目录和创建团队请求明确不发送 `X-Tenant-ID`；成员管理和解散请求明确发送 URL 中的 Team ID；目录成功刷新后，如果活动 Team 已不在结果中，客户端同步清除 API 与界面的活动 Tenant。

## 决策

1. `GET /v1/me/teams` 与 `POST /v1/teams` 始终使用个人身份，不携带活动 `X-Tenant-ID`。
2. 成员读取、添加、改角色、移除与团队解散请求，以 URL 中的 `teamId` 作为显式 `X-Tenant-ID`，不读取隐式活动值。
3. 团队目录刷新成功后，若当前活动 Team 不再存在，Web 同时清除 `RuntimeApi` 与 React 状态中的活动 Tenant，并回到个人对话作用域；不得自动把待发送任务转投另一个团队。
4. 团队选择器和云盘团队标签可选中目录中的第一个有效团队，但只有用户明确选择团队任务或团队对话后，才把它设为活动 Tenant。
5. API 继续严格校验所有需要 Team 作用域的请求；本决策不允许服务端忽略或猜测不匹配的 Tenant。

## 理由

把个人目录、目标 Team 管理和活动工作区分开，可以让退出、解散和测试数据重建后的状态确定收敛，同时保留 RLS 的失败关闭语义。显式作用域也避免一个后台 UI 状态把请求错误发送到另一个仍然有效的团队。

## 影响

- 已失效团队不会再阻塞团队目录刷新、创建团队或回到个人空间；
- 团队管理请求与路径 Team 保持一致，即使侧栏同时查看其他团队也不会串租户；
- 活动团队失效时，当前未发送输入仍留在编辑器，但作用域回到个人空间，必须由用户明确重新进入团队后再发送；
- 团队目录仍只返回当前用户可见的 Membership，不新增跨租户数据能力。

## 验证

- API 客户端测试断言目录与创建请求不含 `X-Tenant-ID`，管理与解散请求只携带路径目标 Team；
- Web 组件测试模拟目录从旧 Team 切换为新 Team，断言活动 Tenant 被清除且选择器收敛到有效目录；
- 在可丢弃测试库重建后刷新团队中心，旧 Team 不再令 `/v1/me/teams` 和上传请求持续返回 404；
- 受影响 Web 测试、TypeScript、格式和 Lint 全部通过。

## 可逆性

客户端改动可直接回退，不涉及数据库迁移。但回退会重新引入失效 Tenant 无法自愈和管理请求依赖隐式状态的问题；若服务端未来提供独立的个人控制面令牌，应新增 ADR 替代本决策，而不是在现有 Team RLS 中放宽校验。
