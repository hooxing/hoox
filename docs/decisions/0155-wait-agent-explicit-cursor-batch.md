# ADR-0155：wait_agent 返回显式游标批次

- 状态：已接受
- 日期：2026-08-12
- 决策者：Cube Runtime 维护者
- 关联任务/PR：`fix/subagent-control-contract`
- 替代关系：补充 ADR-0122

## 背景

`wait_agent` 使用调用方提供的 `after_sequence` 读取新 mailbox 消息，Supervisor 已正确过滤旧消息。但返回值是裸数组，调用模型需要自行扫描最大 sequence，且空数组无法区分超时、调用取消或无等待读取。把游标改成隐式消费状态会破坏重放和并行等待的确定性。

## 决策驱动因素

- 保持显式、无副作用的游标协议；
- 降低模型漏传或算错下一游标的概率；
- 工具重放和并行 wait 不得互相消费消息；
- 空结果应明确表示是否超时。

## 备选方案

### 方案 A：Runtime 隐式记忆上次读取位置

会引入消费状态、并行竞争和恢复持久化问题，不采用。

### 方案 B：继续返回裸数组

协议简单，但调用方容易重复读取且无法直接得到下一游标，不采用。

### 方案 C：返回批次 envelope

返回 `updates`、`nextAfterSequence` 和 `timedOut`，下一次调用仍由调用方显式传回游标。

## 选择

采用方案 C。`nextAfterSequence` 等于本批最后一条 sequence；没有新消息时保持调用方传入的 `after_sequence`。只有实际等待到期限且未被 signal 取消时，`timedOut` 才为 true。

## 理由

批次 envelope 保留事件流的无状态读取语义，同时把容易出错的最大序号计算交给 Runtime。它不会产生消息确认或消费副作用。

## 影响

### 正面影响

- 父 Agent 可直接复用 `nextAfterSequence`；
- 空结果具有明确超时语义；
- 重放、恢复和并行等待仍保持确定性。

### 负面影响与成本

- `wait_agent` 返回结构从数组变为对象；
- 调用方和测试需要读取 `updates`。

### 安全、数据与运维影响

不新增数据、权限或迁移。mailbox 保持追加写和非消费式读取。

## 验证

- Supervisor 测试覆盖有消息批次、游标推进和超时空批次；
- RunWorker 测试更新为读取 `updates`；
- Pi 工具测试验证 envelope 原样返回；
- 执行受影响类型检查和测试。

## 可逆性与回退

可回退为裸数组，但调用方必须同步回退。无持久数据影响。
