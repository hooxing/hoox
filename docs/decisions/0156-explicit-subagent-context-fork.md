# ADR-0156：spawn_agent 必须显式选择上下文 fork

- 状态：已接受
- 日期：2026-08-12
- 决策者：Cube Runtime 维护者
- 关联任务/PR：`fix/subagent-control-contract`
- 替代关系：修改 ADR-0122 中默认继承全部历史的选择

## 背景

`spawn_agent.fork_turns` 支持 `none`、`all` 或最近 N 个父 Agent turn，但此前字段可省略且默认 `all`。在长 Thread 中，隐式继承全部历史会增加 token 成本、延迟和无关上下文，也可能把子任务不需要的信息传播给子 Agent。父 Agent 已经能够根据任务显式选择 fork 策略。

## 决策驱动因素

- 上下文传播应是显式、可审计的选择；
- 默认行为不能扩大子 Agent 获得的信息范围；
- `none`、`all` 与最近 N turn 的语义应保持确定；
- 不引入不可解释的自动裁剪或隐藏 token 策略。

## 备选方案

### 方案 A：保持可选并默认 all

兼容现状，但继续产生隐式信息传播和成本，不采用。

### 方案 B：可选并默认 none

满足最小上下文原则，但省略字段仍可能是模型疏忽，审计时无法区分主动选择和默认，不采用。

### 方案 C：改为必填

每次 spawn 必须明确提供 `none`、`all` 或最近 N turn。

### 方案 D：增加 auto token 裁剪

需要定义模型预算、裁剪算法和恢复快照，当前不采用。

## 选择

采用方案 C。工具 schema 将 `fork_turns` 改为必填；Runtime 不再提供默认值。缺失或非法值通过现有 schema 参数桥形成稳定失败回执。

## 理由

显式选择同时满足最小信息传播、成本可控和审计清晰。调用成本只增加一个短字段，不需要新的持久状态或裁剪算法。

## 影响

### 正面影响

- 不再无意继承全部父对话；
- 每个子 Agent 的上下文来源可从工具调用直接审计；
- fork 语义保持简单确定。

### 负面影响与成本

- 省略 `fork_turns` 的旧调用会失败，需要调用方补齐；
- 模型提示和测试必须同步更新。

### 安全、数据与运维影响

不改变已创建 Agent 的持久 fork 值，不需要数据库迁移。新调用必须显式授权上下文传播范围。

## 验证

- Pi 工具测试验证合法显式值正确映射；
- 测试验证缺失字段不调用控制面并形成失败回执；
- 执行 pi-adapter 类型检查、测试、格式和 lint。

## 可逆性与回退

可恢复为 optional 并重新提供默认值；无数据迁移影响。

## 后续工作

- 暂不实现 auto token 裁剪。

## 实施记录

- 2026-08-12：将 `fork_turns` 改为必填并移除默认值。
