# ADR-0165：合并分支后的 Mem0 迁移顺延到 0045

- 状态：已接受
- 日期：2026-08-12
- 决策者：Runtime 团队
- 替代关系：仅替代 [ADR-0153（Mem0 持久闭环）](0153-mem0-durable-ingestion-and-user-turn-retrieval.md) 中 Mem0 Outbox 使用 0043 版本号的实施细节，不改变其数据和运行语义

## 背景

当前修复分支已经发布并应用 `0043_agent_mailbox_terminal_status` 与 `0044_subagent_current_task`。合并 `origin/main` 的 Mem0 闭环后，源码同时出现 `0043_memory_ingestion_outbox`，迁移装载器按设计以“迁移版本 43 重复”失败。在已存在数据库中，0043 和 0044 已形成持久迁移记录，不能通过改写或重排历史版本解决。

## 备选方案

### 方案 A：把既有子 Agent 0043/0044 迁移重新编号

会导致已应用数据库的迁移名称、校验和与源码不一致，除非篡改迁移记录或重建数据库，不可接受。

### 方案 B：让迁移装载器允许同版本多个名称

会破坏版本主键、执行顺序与回退目标的单值语义，并掩盖分支集成冲突，不可接受。

### 方案 C：将尚未应用的 Mem0 迁移顺延到 0045

保留已发布历史，Mem0 Outbox 仍在所有既有迁移之后原子安装，改动范围仅限文件名、测试和文档引用。

## 决策

采用方案 C：把 `memory_ingestion_outbox` 的 up/down 文件从 0043 顺延为 0045，并同步契约测试、开发说明与 [ADR-0153（Mem0 持久闭环）](0153-mem0-durable-ingestion-and-user-turn-retrieval.md) 的实施版本引用。

## 影响

- 已应用 0043/0044 的数据库可直接继续迁移到 0045，无需修改迁移记录或业务数据。
- 尚未使用 Mem0 迁移的新数据库会按 0043、0044、0045 的确定顺序初始化。
- 如果任何外部运维脚本硬编码 Mem0 为 0043，需要同步改为 0045。

## 验证

- 迁移装载测试不再报告重复版本。
- `memory-ingestion-migration.test.ts` 从 0045 文件读取并继续验证 RLS、幂等、claim fencing 与非空回退保护。
- 对当前真实开发库执行 `pnpm db:migrate:up`，确认从 0044 前进到 0045。

## 可逆性

在 0045 尚未应用前，可恢复旧文件名，但会重新产生当前分支的重复版本错误。0045 应用后只能按既有破坏性迁移规则在 Outbox 为空时回退，不能把记录伪装为 0043。
