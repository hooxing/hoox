# ADR-0166：团队任务导航的浏览器偏好与空会话切换边界

## 状态

已接受（试验版）。

## 背景

ADR-0140 确定团队区域默认折叠，并要求个人与团队任务投影稳定共存。实际使用发现两个局部状态边界不完整：团队区域的展开状态只存在于 React 组件内，刷新后必然回到折叠；在已经进入某个团队空间后重复点击“新增对话”，工作区切换逻辑仍会清空当前团队任务投影，而 Tenant 并未变化，因此列表会消失且没有新的依赖变化触发重载。

## 备选

1. 保持纯内存状态，并在每次新建团队对话后强制重新请求团队任务。实现直接，但刷新仍丢失展开偏好，而且重复网络请求掩盖了错误的同空间切换语义。
2. 将展开状态放入服务端用户配置，并让服务端同步所有设备。可以跨设备，但需要新增公开协议和持久化模型，超出当前侧栏交互修复范围。
3. 使用浏览器 `localStorage` 保存展开偏好；同一 Tenant 内创建空会话只清除当前选择，不清空已经加载的任务投影。跨 Tenant 时仍清空活动工作区投影，等待目标 Tenant 的显式读取结果。

## 决策

采用方案 3。团队区域每次折叠或展开时写入固定键，组件初始化时读取该键；浏览器拒绝存储时静默退化为当前页面内状态，不能阻断导航。

工作区切换区分“Tenant 改变”和“同 Tenant 清除选择”。只有 Tenant 改变时清空活动 `state.threads`，避免旧空间内容短暂混入目标空间；同 Tenant 点击新增对话时保留任务投影，只把主内容区切换为空会话。

## 影响

- 刷新同一浏览器页面后保持用户最后一次团队区域展开或折叠选择。
- 重复点击团队“新增对话”不会让团队任务列表消失，也不会增加补偿式列表请求。
- 偏好只在当前浏览器配置中生效，不跨设备同步；清理站点数据会恢复默认折叠。
- 不改变 Tenant、Thread、Run 或服务端数据的所有权和安全边界。

## 验证

- 组件测试模拟卸载和重新挂载，验证展开状态从 `localStorage` 恢复。
- 工作台测试连续两次点击团队新增对话，验证已加载团队任务保持可见。
- 执行 Web 包测试、类型检查、格式和 lint 校验。

## 可逆性

删除固定浏览器键的读写即可恢复默认折叠；恢复同空间清空投影的旧逻辑也不涉及数据迁移，但会重新引入列表消失问题。两项修改均不写入服务端数据，可随时回退。
