# ADR-0167：移动云盘空间与团队选择布局

## 状态

已接受（试验版）。

## 背景

云盘对话框同时提供跨空间搜索、个人/团队浏览切换以及当前团队选择。桌面端可在一行内容纳搜索框、搜索范围和操作按钮，但手机端沿用相同结构后，搜索范围被挤入搜索框内部的第二行，个人/团队标签仍表现为桌面下划线标签，当前团队名称与下拉框也横向争抢宽度。结果是“选择空间”和“选择团队”缺少清晰层级，较长团队名容易压缩标签或控件。

## 备选

1. 仅缩小字号和间距，继续保持所有控件横向排列。改动最小，但不能解决长团队名、窄屏触控尺寸和层级混乱。
2. 手机端隐藏搜索范围和团队选择，改用默认空间。界面更简洁，但会移除现有能力并让权限范围不透明。
3. 保留全部能力，把搜索输入与按钮组成一行，将搜索范围作为带可见标签的独立整行控件；个人/团队切换改为分段选择器，当前团队也改为标签在上、全宽下拉框在下。

## 决策

采用方案 3。桌面端仍使用搜索区双列布局，搜索范围保持紧凑；宽度不超过 640px 时，搜索区改为纵向布局并显示“搜索范围”标签。个人云盘与团队云盘使用等宽分段按钮，当前团队选择使用独立可见标签和至少 44px 高的全宽下拉框。

所有原有搜索范围值、标签切换语义、团队切换回调和权限边界保持不变。团队下拉框增加明确的可访问名称，避免视觉标签与表单控件关系仅依赖布局推断。

## 影响

- 手机端的搜索空间、浏览空间和当前团队形成三个清晰层级。
- 空间与团队下拉框获得完整宽度和触控高度，长名称不再与相邻文字争抢空间。
- 桌面端搜索范围从搜索输入框内部拆成相邻独立控件，结构更稳定。
- 不改变文件查询协议、Tenant 权限、选中文件行为或服务端数据。

## 验证

- 组件测试验证“搜索范围”可见标签存在，团队下拉框具有“选择团队”的可访问名称并继续触发原回调。
- 执行云盘组件测试、Web 类型检查、构建和 lint。
- 在 393px 宽视口复验搜索范围、分段空间选择和全宽团队选择控件。

## 可逆性

改动仅涉及云盘对话框 DOM 分组、可访问标签和响应式样式。删除新增包装与移动端规则即可恢复旧布局，不涉及数据迁移或协议回退。
