# ADR-0171：对已发布的 Mem0 迁移执行受限谱系换号

- 状态：已接受
- 日期：2026-08-13

## 背景

Mem0 Outbox 曾在并行分支中以 `0043_memory_ingestion_outbox` 发布并应用到开发数据库。合并另一条已经占用 0043、0044 的分支后，源码把同一迁移顺延为 0045，但迁移表仍保存旧版本号和基于版本号计算的旧 checksum。严格迁移器因此在应用 0046 前失败，Worker 随后因个性化表不存在而让所有 Run 在 `claimed` 阶段进入恢复。

## 备选

1. 手工修改迁移表或重建开发数据库。短期直接，但操作不可复用，也会绕过源码中的安全审计。
2. 放宽所有已应用迁移的 checksum 校验。能够继续迁移，但会失去篡改检测，无法接受。
3. 在同一个迁移事务中只识别已知旧版本、名称和 checksum，把该记录换号为源码中内容相同的 0045，再执行完整严格校验和后续迁移。

## 决策

采用方案 3。迁移器只接受历史 `0043_memory_ingestion_outbox` 的固定 checksum，并同时校验当前 0045 的固定名称和 checksum。0045 已被占用、更新未唯一命中或任一指纹变化时均失败关闭。谱系换号、0043/0044 补迁移、0046 迁移、ACL 刷新和迁移记录写入共享一个事务。

## 影响

- 已经应用旧 0043 Mem0 迁移的数据库可以无损前进到当前 Schema。
- 未命中已知指纹的数据库仍保持原有严格拒绝语义。
- 迁移记录中的版本号会从旧 43 改为当前 45；业务表和数据不重写。
- 以后不得通过重命名已发布迁移解决版本冲突，应新增显式兼容迁移或谱系记录。

## 验证

- 单元测试覆盖已知指纹换号、未知 checksum 不处理和目标版本占用失败。
- 对当前远端开发库运行向前迁移，确认 43 至 46 的记录与源码一致。
- 关闭记忆启动 Worker，重新运行 GAIA 纯文本题和三题样本。

## 可逆性

换号与后续迁移在同一事务中，失败会整体回滚。成功后如需回退，正式 down 流程会按当前 46→45→44→43 顺序执行；不得手工恢复旧 43 记录。
