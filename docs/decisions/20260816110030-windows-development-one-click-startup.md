# ADR-20260816110030：Windows development 非首次一键启动边界

- 状态：已接受
- 日期：2026-08-16
- 决策者：Runtime 维护者
- 关联任务/PR：本地开发一键启动脚本
- 替代关系：无

## 背景

完整 development 拓扑需要 MinIO、API、Agent Worker、Scheduler、Web、Skill Admin API 和 Admin Web。首次配置还包含依赖安装、数据库角色 bootstrap、迁移和开发身份初始化，但日常重启重复执行这些写操作既慢，也会扩大脚本权限与失败面。

## 决策驱动因素

- 日常启动必须是一条命令或可双击入口；
- 非首次启动不得隐式安装依赖、迁移数据库或修改开发身份；
- 启动前必须发现外部依赖故障和端口冲突；
- 不得为方便启动而强制终止不属于本次启动的进程；
- 各常驻进程需要独立可见的终端，便于开发者观察日志并使用 `Ctrl+C` 停止。

## 备选方案

### 方案 A：单个 PowerShell 后台运行所有进程

窗口数量少，但日志会混杂，单个进程退出难以识别，停止时也容易误伤其他子进程。

### 方案 B：启动脚本完成准备并为每个进程打开独立窗口

脚本幂等启动 MinIO、构建工作区、执行 Worker 只读预检、检查监听端口，再分别启动所有应用。实现稍多，但故障边界和日常操作最清晰。

### 方案 C：启动时重复首次初始化

能够掩盖未初始化环境，但会让日常启动持有数据库管理能力并执行写操作，不符合最小权限和失败关闭要求。

## 选择

采用方案 B。新增 `scripts/start-development.ps1` 和根目录双击入口 `start-development.cmd`。默认启动完整开发拓扑；`-CoreOnly` 只启动核心 Runtime，`-SkipBuild` 仅供确认 `dist` 已是最新时使用，`-NoBrowser` 禁止自动打开页面。

脚本明确不执行依赖安装、数据库迁移、角色 bootstrap 或开发身份初始化。缺少 `.env`、命令、外部依赖、构建产物或空闲端口时失败关闭。

## 理由

独立窗口保留现有开发命令的日志和中断语义。把首次初始化排除在脚本外，可以避免普通开发重启获得管理数据库和身份数据的副作用。端口冲突只报告而不自动清理，避免终止其他仓库或用户进程。

## 影响

### 正面影响

- 完整开发环境可以通过双击或单条 PowerShell 命令启动；
- 启动顺序、预检和健康检查固定且可重复；
- 日常启动不修改数据库身份或 Schema。

### 负面影响与成本

- 默认会打开六个进程窗口；
- 默认全量构建会增加启动时间；
- 脚本仅面向 Windows PowerShell 开发环境。

### 安全、数据与运维影响

- 脚本读取本机 `.env`，但不输出秘密值；
- 不执行迁移和身份写入；
- 不自动终止端口占用者；
- MinIO 使用现有 Compose 数据卷，不执行 `down -v`。

## 验证

- PowerShell AST 解析无语法错误；
- `tests/start-development-script.test.ts` 验证完整拓扑、非首次边界和端口冲突失败关闭；
- `corepack pnpm format:check` 与 `corepack pnpm lint` 通过；
- 人工运行时由 API、Web 和 Skill Admin HTTP 健康检查确认就绪。

## 可逆性与回退

删除 `scripts/start-development.ps1`、`start-development.cmd`、对应测试和文档即可回退。脚本不迁移数据，因此没有数据回滚步骤。

## 后续工作

- 如需统一停止，可在确认 PID 所有权和子进程树语义后另行增加停止脚本。
