# ADR-20260816160557：工作台本地账号入口与侧栏用户菜单边界

## 状态

已接受，2026-08-16。

## 背景

Hoox 工作台此前直接以固定的 `dev-user-a` 开发身份调用 API，没有登录、注册或退出界面，也没有稳定展示当前用户信息的入口。团队创建与管理入口分散在团队切换器内部，侧栏底部缺少可扩展的用户设置区域。

当前仓库的生产认证边界仍是外部身份系统签发 JWT；API 没有注册、密码校验、令牌签发或用户资料接口。直接把浏览器表单伪装成生产认证会破坏既有安全边界，而为本次界面需求同时引入完整身份服务会显著扩大数据库、密钥、会话撤销和部署范围。

## 备选方案

### 方案 A：只增加静态登录注册页面

实现最小，但表单无法建立或恢复任何会话，用户菜单和退出行为也无法形成可验证闭环。

### 方案 B：在浏览器内提供本地工作台账号壳

登录、注册、退出和用户资料在当前浏览器内形成闭环；密码使用带随机盐的 PBKDF2-SHA-256 摘要保存，不上传明文。业务 API 暂时继续使用已有的 `dev-user-a` 开发身份，并明确该账号壳不能替代生产认证。

### 方案 C：同步实现服务端注册、密码认证和 JWT 签发

可以形成真实产品身份闭环，但需要新增公开未认证端点、密码策略、账户恢复、邮件验证、令牌签发与撤销、限流、审计、数据库迁移和生产密钥管理，超出本次界面与导航改造范围。

## 选择

采用方案 B：

1. 未建立本地会话时展示 Hoox 登录/注册页面；保留“使用本地开发身份继续”入口，以兼容现有开发 API。
2. 注册账号只保存在当前浏览器；密码以随机盐和 120,000 次 PBKDF2-SHA-256 派生摘要保存，不保存或上传明文。
3. 会话导航最底部固定展示头像、用户名和邮箱；点击后向上展开用户设置菜单。
4. 团队中心和当前团队管理进入用户菜单，团队切换器只负责切换团队和创建团队会话。
5. 退出登录只清除本地会话并返回登录/注册页面，不修改服务端业务数据。
6. 本实现不改变生产 JWT 验证规则，也不宣称完成生产身份闭环。后续接入真实身份提供商时，替换账号存储与会话来源，保留账号页面和侧栏菜单组件。

## 影响

- 首次打开工作台会先看到登录页面，不再自动进入主界面。
- 本地开发人员可以直接使用固定开发身份，也可以创建仅用于界面资料和本机登录验证的本地账号。
- 本地账号资料不会改变 API 当前使用的 `dev-user-a` principal；不同本地账号之间仍共享同一开发后端身份和数据边界。
- 团队创建、加入和管理入口集中到侧栏底部用户菜单，后续团队相关设置可继续在该菜单扩展。

## 验证

- 单元测试覆盖首次无会话、会话持久化、退出、注册后重新登录、用户菜单展开、团队管理入口和退出回调。
- Web 应用测试覆盖团队目录刷新改为从用户菜单进入团队中心。
- 执行 `pnpm --filter @aisay/web typecheck` 与 `pnpm --filter @aisay/web test`。
- 在 `http://127.0.0.1:4173/` 验证登录、注册切换、本地开发身份登录、侧栏底部用户信息、弹出菜单及团队中心入口。

## 可逆性

前端账号壳、样式和菜单入口可以用单个提交回退，不涉及数据库迁移。后续服务端身份系统上线时，应保留视觉组件，删除浏览器账号密码存储，并把 `AccountProfile` 与会话动作接到受信任的服务端认证结果。
