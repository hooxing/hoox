# ADR-20260816165004：开发工作台使用服务端本地账号认证

## 状态

已接受，2026-08-16。替代 ADR-20260816160557 中“浏览器账号壳与业务 API 固定复用 `dev-user-a`”的账号存储和认证结论；侧栏用户菜单的视觉与团队入口结论继续有效。

## 背景

前一阶段为快速补齐登录、注册和侧栏用户菜单，仅在浏览器保存本地账号资料与密码派生摘要，而所有业务请求仍固定发送 `Authorization: Bearer dev-user-a`。因此，新注册用户虽然看到自己的用户名，服务端 principal 与个人 Tenant 仍属于开发账号 A，必然能看到开发账号 A 的任务。

生产 API 已采用外部 HS256 JWT，并明确依赖外部身份系统。当前需求是修复本地 development 工作台的数据隔离，不应借机把未完成邮件验证、找回密码、风控和密钥轮换的自建账号系统暴露到生产。

## 备选方案

### 方案 A：继续保留浏览器账号，只为每个账号选择不同固定开发 Token

无需数据库迁移，但固定 fixture 数量有限，无法支持任意注册用户，也没有可信的密码验证和会话撤销。

### 方案 B：在 development API 内实现服务端本地账号、个人 Tenant 和不透明会话

注册事务原子创建 User、个人 Tenant、owner Membership、密码派生材料和会话；登录由服务端校验密码并签发随机令牌。生产装配不注册这些路由，仍保持外部 JWT 边界。

### 方案 C：直接实现生产级自建身份系统

可以统一开发与生产身份，但需要邮件验证、找回密码、多因素认证、限流、审计、密钥管理、合规和运维能力，超出当前开发工作台范围。

## 选择

采用方案 B：

1. 新增 `user_accounts` 与 `user_sessions`。密码只保存随机盐和 `scrypt-v1` 派生值；会话只保存 SHA-256 摘要，不保存可直接使用的 Bearer Token。
2. 注册在单个 PostgreSQL 事务中创建 User、个人 Tenant、owner Membership、账号和首个会话，邮箱使用规范化值建立唯一约束。
3. development API 条件注册 `/v1/auth/register`、`/v1/auth/login`、`/v1/auth/me` 和 `/v1/auth/logout`；production 装配不提供本地账号端点。
4. 固定 `dev-user-a|dev-user-b` 继续作为显式开发 fixture；只有未命中固定 Token 时才委托本地会话解析器。
5. Web 登录注册改为调用 API，并将返回的动态 Token 用于后续所有业务请求。退出会撤销服务端会话并清除浏览器会话。
6. 本地会话有效期固定为 30 天。浏览器 `localStorage` 仅保存资料、过期时间和不透明会话令牌，不再保存密码或密码摘要。

## 影响

- 每个新注册用户拥有独立 User、个人 Tenant 和 owner Membership，任务列表与其他用户通过现有 TenantScope 和 RLS 隔离。
- 老的 `hoox.local-account.v1` 与 `hoox.local-session.v1` 浏览器数据不再被读取，用户需要重新注册或登录。
- 数据库迁移 0048 增加认证状态与 Runtime 角色最小权限；Team Coordinator 明确无权访问账号和会话表。
- 本地 Bearer Token 存储在 `localStorage`，仍受同源 XSS 风险影响；这是回环 development 工作台的限制，不能作为生产浏览器认证方案。
- 未实现邮件验证、密码找回、登录限流、多因素认证和全设备会话管理；生产发布仍必须接入外部 OIDC/身份系统。

## 验证

- 协议测试覆盖注册、登录与会话响应约束。
- 认证服务测试覆盖邮箱规范化、重复注册、密码错误、会话解析和退出撤销。
- Fastify 路由测试覆盖 development 条件暴露注册端点。
- 迁移测试覆盖密码/令牌不明文持久化、RLS 与回滚顺序。
- Web 测试覆盖后端注册登录、动态 Authorization、会话持久化及退出。
- 受影响包执行 typecheck、测试、格式与 lint 门禁。

## 可逆性

Web 可回退到固定开发身份，但会重新出现多账号共享任务的问题。代码回退前应先停止写入新账号；迁移 0048 的 down 脚本会删除本地账号和会话数据，因此只能在确认这些开发数据不再需要时执行。生产 JWT 路径未改变，可独立于本地账号能力继续演进。
