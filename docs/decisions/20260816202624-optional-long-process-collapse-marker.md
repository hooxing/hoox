# ADR：将最终答复阶段标志收窄为可选的长过程折叠工具

- 状态：已接受
- 日期：2026-08-16

## 背景

首版 `begin_final_answer` 只强调“任务已经完成、无需其他工具”，模型容易把它理解为所有任务的通用结束步骤。实际验证中，模型既会在直接知识问答中调用，也可能先输出一份完整答复，再调用阶段标志并根据回执重复生成第二份答复。这增加了延迟与 token 消耗，也偏离了“只在过程较长时帮助用户直接看到结论”的产品目的。

本次不改变两阶段生成协议，也不修改 Active History 投影；只收窄模型可见的工具语义和名称。

## 备选方案

1. 只在系统 Harness 中增加使用说明。约束会远离工具定义，模型仍可能依据名称把它当作通用结束工具。
2. 保留 `begin_final_answer` 名称，只修改描述。兼容改动较小，但名称本身仍暗示每次最终答复都应调用。
3. 更名为 `collapse_process_for_final_answer`，并在工具描述中明确可选条件、禁止场景和独占调用协议。

选择方案 3。

## 决策

- 主 Agent 只暴露 `collapse_process_for_final_answer`，不再暴露 `begin_final_answer`；子 Agent 仍不具备该能力。
- 工具只用于本轮最终答复之前已经累积较多过程性消息、工具执行说明或中间结果，并且折叠能明显提高结论可读性的场景。
- 直接回答、简短任务或几乎没有过程内容时不得调用。
- 调用前必须完成任务并确认不再需要其他工具；调用所在 assistant 轮次不得输出可见文本，也不得同时调用其他工具。
- 工具成功后，下一条 assistant 消息只输出一次独立、清晰、完整的最终答复。
- 工具仍使用严格空参数和字节稳定的固定回执，不注入任何请求级动态数据。
- Worker 的阶段事件、Thread Context `phase` 以及 Active History 投影保持不变，只把阶段标志识别名称切换为新工具名。
- Web 对新旧工具名都保持隐藏，以兼容已经持久化的历史运行事件。

## 影响

- 工具名称、描述和 capability manifest 摘要发生变化，部署后的首次请求会形成新的缓存前缀；同一能力配置下随后仍保持字节稳定。
- 旧名称不再提供给模型，避免继续强化“所有最终答复都要调用”的错误倾向。
- 两阶段协议仍会增加一次固定工具轮和后续模型采样；本次主要降低不必要调用及先写答案再重复生成的概率，不承诺消除模型违反协议的所有情况。
- 删除新工具并恢复旧名称、描述与识别条件即可回退；历史事件无需迁移。

## 验证

- 工具单元测试断言可选用途、禁止直接回答、独占调用和只输出一次的稳定描述。
- Pi Session 测试覆盖根 Agent 的新工具清单以及工具后继续输出标准 assistant message。
- Worker 测试覆盖新名称对应的开始、提交、续写和取消语义。
- Web 测试覆盖新名称隐藏以及旧历史名称的兼容隐藏。
