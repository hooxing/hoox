# ADR-20260818001636：收敛模型网络诊断到内部轨迹查看器

- 状态：已接受
- 日期：2026-08-18
- 决策者：Runtime 团队
- 关联任务/PR：`codex/reclaim-code-entropy` 熵回收
- 替代关系：部分替代 ADR-0062 中“Web 保留模型报文读取协议和状态投影”的实施边界

## 背景

ADR-0062 已从普通用户工作台移除右侧活动栏以及模型网络报文入口，但当时没有继续删除 Web 内部的读取和状态投影。当前生产界面不渲染这些数据，`model-wire-trace-view.tsx` 没有生产调用方，Web 仍会在每轮 Run 轮询中请求模型网络报文首页、维护游标和去重状态，并用测试独自维护已不可达的诊断视图。

此后 ADR-20260815182655 及其后续决策已经建立 development-only、仅回环监听的内部轨迹查看器。该查看器直接读取本地不可变诊断镜像，能够关联内部轨迹和原始模型报文，也明确禁止接入普通用户 Web。服务端诊断 API、持久化、采集和保留清理仍有独立运维与排障价值，不属于本次删除范围。

## 决策驱动因素

- 普通用户 Web 不应持有或轮询没有可见消费者的敏感诊断数据；
- 同一诊断能力不应同时维护一个可用的内部查看器和一个不可达的用户 Web 投影；
- 必须保留服务端诊断协议、持久化格式、采集、保留清理与内部查看器；
- 删除应覆盖 Web 私有 API 客户端、状态、轮询、死视图和专属测试，不能留下同步胶水。

## 备选方案

### 方案 A：保留隐藏投影

继续让 Web 请求并维护模型报文分页，等待未来可能恢复入口。它不改变现状，但每轮产生无用户价值的请求和状态同步成本，测试也继续验证不可达实现。

### 方案 B：恢复普通工作台诊断入口

重新挂载模型报文视图，使现有投影重新有消费者。该方案恢复可见能力，但扩大敏感 Prompt、工具参数和模型正文的披露面，违背内部查看器的 development-only 边界。

### 方案 C：删除 Web 隐藏投影，保留诊断事实源和内部查看器

普通工作台只轮询用户可见的 Run、事件、Artifact、Thread Context 和连续性状态；模型报文继续由服务端和内部轨迹查看器提供。

## 选择

选择方案 C。删除 `@aisay/web` 内的模型报文类型、规范化、请求方法、Reducer 状态、轮询分支、不可达视图、无行为兼容属性及专属测试。服务端 `/model-wire-traces` API、PostgreSQL/对象存储记录、Worker 采集器、本地不可变镜像和 `@aisay/trajectory-web` 保持不变。

## 理由

全仓消费者检查确认，模型报文 Web 视图只有自己的测试导入；活动栏测试使用本地空函数模拟已删除组件；状态字段只被隐藏轮询与测试消费。`@aisay/web` 是私有应用，不发布组件或客户端 API。独立内部轨迹查看器已经提供受控诊断入口，因此删除不会减少当前用户能力或维护者的诊断能力，反而消除一条无消费者的数据路线。

## 影响

### 正面影响

- 普通工作台不再为每个轮询周期发起一至两个模型报文请求；
- 删除一套不可见的分页、去重、尾游标追赶和正文查看状态；
- 测试重新聚焦用户可见行为，不再保留跳过的活动栏回归场景；
- 敏感诊断数据继续限定在服务端授权边界和 development-only 内部查看器。

### 负面影响与成本

- 若未来要在普通工作台恢复模型报文入口，需要重新设计授权、披露和状态投影，不能直接复用已删除的旧组件；
- Web 私有 `RuntimeApi` 不再提供模型报文读取方法，仓库外若绕过私有应用边界深层导入将无法兼容。

### 安全、数据与运维影响

- 不迁移、不删除任何持久数据，也不改变服务端 API、采集开关、保留期或清理语义；
- 普通浏览器减少敏感诊断数据暴露和请求流量；
- 维护者继续通过 `pnpm dev:trajectory` 启动回环内部查看器。

## 验证

- 全仓搜索确认 Web 生产源码不再引用模型报文客户端、状态、视图和活动栏兼容属性；
- Web 组件测试验证恢复 Run 后仍读取并展示可见的事件与 Artifact 投影，且不要求诊断客户端能力；
- 执行 `corepack pnpm --filter @aisay/web typecheck`；
- 执行 `corepack pnpm --filter @aisay/web test` 与 `corepack pnpm --filter @aisay/web build`；
- 执行仓库 `format:check`、`lint`、相关 typecheck，并检查 `git diff --check`。

## 可逆性与回退

本改动没有数据迁移，可以整体回退对应提交。回退只会恢复 Web 隐藏请求和死视图，不影响服务端与内部查看器。若未来重新提供用户可见诊断，应新增 ADR 重新评估身份、授权、审计、正文披露和分页语义，而不是长期恢复无界面的投影。

## 后续工作

- 无。本次只收敛已经由内部查看器承接的 Web 残留，不扩大诊断能力。
