# ADR-20260818090007：定时 Run 在线发现与触发消息边界

- 状态：已接受
- 日期：2026-08-18

## 背景

定时任务通过后台 Worker 向既有 Thread 追加输入并创建新 Run。用户停留在一个已经终态的任务页面时，现有 Web 只轮询当前活跃 Run，不会发现后台创建的新 Run，因而必须手动刷新。

同时，首版把 `scheduled_for` 作为“计划执行时间”拼入模型可见消息。该时间已经是 `scheduled_task_occurrences` 的控制面审计事实，默认注入会污染用户对话、增加模型上下文，并让调度延迟看起来像任务语义。

## 备选

1. 使用 SSE/WebSocket 推送 Thread 新 Run。实时性最好，但需要新增连接恢复、Tenant 授权和服务端广播边界。
2. Web 在用户可见且当前 Run 非活跃时，低频查询最新 Run。复用现有 API，改动小，但会产生少量空查询。
3. 保持手动刷新。不增加请求，但定时任务体验不完整。

触发消息方面：

1. 总是注入计划时间。模型可见，但重复控制面事实。
2. 默认只发送任务名称与指令，计划时间留在 occurrence 审计数据中；任务语义确实需要时间时由用户指令明确要求。

## 决策

1. Web 在选中 Thread、页面可见且当前 Run 不处于 `queued/running` 时，每 2.5 秒读取一次最新 Run。发现新的 Run ID 后切换到现有 Run 轮询与 Thread Context 刷新链路。
2. 后台发现失败不覆盖当前页面错误，不打断输入；切换 Thread 或进入活跃 Run 时立即取消该发现循环。
3. 定时触发消息不再注入 `scheduled_for`。消息只包含定时触发标记、任务名称和用户指令。
4. `scheduled_for` 继续保存在 occurrence，供幂等、审计、延迟指标和未来 UI 展示使用。

## 影响

- 用户停留页面即可看到定时任务创建的新消息和执行进度。
- 空闲页面会产生每分钟约 24 次轻量最新 Run 查询；页面隐藏或 Run 活跃时停止。
- 模型上下文不再包含调度控制面时间；需要“按当前日期生成日报”等能力时，应由运行时日期上下文或用户指令明确表达。
- 后续可用 SSE/WebSocket 替代轮询，不改变数据库事实或消息协议。

## 验证

- Web 测试覆盖终态页面发现外部新 Run。
- 持久化测试覆盖触发消息不包含计划执行时间，同时 occurrence 迁移仍保留 `scheduled_for`。
- 类型检查、格式检查和 Lint 作为提交门禁。

## 可逆性

可单独移除 Web 发现循环并恢复手动刷新；也可恢复消息时间字段。数据库结构和既有 occurrence 无需迁移。
