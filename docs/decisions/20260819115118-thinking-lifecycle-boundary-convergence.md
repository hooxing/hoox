# ADR-20260819115118：思考生命周期在正文与工具边界收敛

- 状态：已接受
- 日期：2026-08-19
- 决策者：Runtime 团队
- 关联任务/PR：页面同时出现多个“正在思考”的回归修复
- 替代关系：细化 ADR-0072 与 ADR-0089 的思考完成兼容边界

## 背景

一次 Agent Run 可以包含多次模型请求和工具往返，因此保留多段思考记录是正常行为。但部分
OpenAI-compatible Provider 或 Pi 事件流不会在正文开始前稳定发布 `thinking.completed`。Web 会话投影在
收到 `message.delta`、工具事件或最终答复阶段事件时直接清除活动思考索引，却没有先把对应思考块从
`running` 改为 `completed`。索引清除后，后续 `message.completed` 已无法找到旧块；下一轮思考开始时，
页面便同时存在多个 `running` 思考块，并显示多个“正在思考”。

该问题只存在于 Web 事件投影。持久化 Run 事件、Thread Context、模型请求、工具调用和 Provider 原始输出
均没有并发思考语义变化。

## 决策驱动因素

- 一个 Run 可以保留多个历史思考块，但任意时刻最多只能有一个活动思考块；
- 显式 `thinking.completed` 仍是首选终态，同时必须兼容缺少该事件的 Provider；
- 正文输出、工具执行和最终答复阶段都证明此前思考已不再是当前动作；
- 不修改持久化事件或模型协议，避免把展示兼容逻辑扩散到 Runtime 边界。

## 备选方案

### 方案 A：只接受显式 thinking.completed

保持现状，只在收到 `thinking.completed` 时关闭思考。实现最简单，但已经证明会因上游缺少显式终态而留下
陈旧的运行状态，不能满足单一当前状态约束。

### 方案 B：在语义边界推断思考完成

在 Web 投影收到新思考、正文、工具、Runtime 兜底、最终答复阶段或消息终态时，先把旧活动思考标记为
`completed`，再推进后续块。底部当前状态投影采用同一规则，在正文或工具开始时立即退出“正在思考”。

### 方案 C：像内部轨迹查看器一样合并全部思考

把同一 Run 的所有推理合并成一段。这能隐藏状态泄漏，但会丢失思考、阶段性正文和工具调用之间的真实顺序，
也不符合用户工作台保留多轮过程的既有决策。

## 选择

采用方案 B。Web 会话投影增加统一的活动思考收敛操作，并在以下事件边界调用：

- 新的 `thinking.started`；
- `message.delta` 与 `message.completed`；
- `tool.*`；
- `runtime.notice`；
- `finalization.started`。

显式 `thinking.completed` 继续调用同一收敛操作。底部 Run 当前状态在正文、工具或最终答复阶段开始时同步结束
思考状态。历史思考正文仍按原顺序保留，只有状态由陈旧的 `running` 修正为 `completed`。

## 理由

正文或工具已经开始时，前一段思考不可能仍是页面当前动作。把这些事件作为兼容终态不会伪造新的模型内容，
只根据已经发生的后续事实修正展示状态。与合并全部思考相比，该方案保留多轮模型和工具循环的时间顺序；与
只依赖显式终态相比，可以适配实际存在的不完整事件序列。

## 影响

### 正面影响

- 页面任意时刻最多显示一个“正在思考”；
- 缺少 `thinking.completed` 的事件流仍能在正文或工具开始时正确收敛；
- 多轮思考历史、正文和工具调用顺序保持不变；
- 底部当前状态不会在正文已经输出时继续显示“正在思考”。

### 负面影响与成本

- Web 投影需要维护一个统一的收敛辅助函数和额外边界测试；
- 如果未来协议允许思考与正文真正并行流式输出，需要重新定义单一当前状态，而不能沿用本决策。

### 安全、数据与运维影响

不修改数据库、API、事件 Schema、模型 Prompt、Provider 请求、工具权限或租户边界；不新增配置、依赖和
迁移。修复只影响本地确定性的 Web 展示投影。

## 验证

- 事件投影测试覆盖 `thinking.delta → message.delta → message.completed → thinking.delta`，验证旧块完成且仅
  新块保持运行；
- 事件投影测试覆盖思考后直接进入工具调用；
- Run 当前状态测试验证正文开始显示“正在回复”、工具开始显示对应工具动作；
- 工作台组件测试验证页面最多出现一个“正在思考”；
- 执行 Web 测试、类型检查、格式检查与 lint。

## 可逆性与回退

该改动没有数据迁移，可通过恢复 Web 投影原有的索引清除逻辑回退。回退后已有持久化事件仍可读取，但缺少
显式思考终态的 Run 会再次显示多个活动思考。

## 后续工作

- 通过模型网络诊断观察不同 Provider 缺少 `thinking.completed` 的频率；
- 若 Pi 后续保证所有内容块转换均发布明确终态，仍保留 Web 兼容边界以支持历史事件。
