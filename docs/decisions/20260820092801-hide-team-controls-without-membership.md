# 无团队成员关系时隐藏团队操作

- 日期：2026-08-20
- 状态：已采纳

## 背景

团队能力接口可用并不代表当前用户已经创建或加入团队。此前个人任务头部仍会显示“发布到团队”，云盘也会展示跨空间搜索文案、搜索范围选择器和仅含“个人云盘”的空间标签。这些控件在团队目录为空时没有可执行目标，并会误导用户认为存在团队空间。

## 决策

以当前已加载的团队目录是否非空作为团队界面的展示边界：

- 个人任务只有在至少存在一个团队且支持任务分支接口时才展示“发布到团队”；
- 云盘没有团队来源时使用个人文件搜索文案，隐藏搜索范围选择器和空间标签栏；
- 云盘存在团队来源时保留跨空间搜索、范围选择和个人/团队标签切换。

后端权限校验和已有发布逻辑保持不变，界面条件只负责避免呈现没有有效目标的入口。

## 备选方案

1. 保留控件，点击后提示先创建或加入团队。该方案会暴露当前不可执行的操作，且不能解决云盘冗余的团队文案与控件。
2. 只依据团队 API 是否存在。该条件描述的是部署能力，不描述用户成员关系，正是本次问题的来源。

## 影响

团队目录为空时界面更接近纯个人版；用户创建或加入团队并刷新目录后，相关团队入口会随状态恢复。该改动不改变 API、数据模型和权限边界，可通过撤销条件渲染恢复。

## 验证

- 云盘组件测试覆盖无团队时的个人搜索文案、范围选择器和标签栏隐藏；
- 工作台测试覆盖分支接口存在但团队目录为空时不显示“发布到团队”；
- 原有多团队云盘测试继续覆盖团队控件和跨空间搜索。
