# Pi 模型目录为后台配置提供可覆盖的初始值

- 状态：部分已替代（模型配置流程与目录加载位置；Pi 初始值与 Run 快照语义继续有效）
- 日期：2026-08-20
- 决策者：Runtime 维护者
- 关联任务/PR：参考 DeepSeek Harness 重做模型供应商管理
- 替代关系：细化 ADR-20260820090402 的模型目录录入方式；模型保存即启用流程见 ADR-20260825180549，Provider 列表与统一可编辑模型表单见 ADR-20260826115031，Pi 初始值与 Run 快照语义继续有效

> 目录加载位置由 [ADR-20260906001531](20260906001531-pi-kernel-and-shared-model-catalog.md) 部分替代：控制 API 与浏览器共用 Protocol 窄入口中的生成快照和查询实现。公开元数据、可编辑初始值、Revision/Run 事实源及认证和独立降级约束继续有效。

## 背景

后台首版要求管理员逐项填写模型名称、推理能力、输入能力、上下文窗口和最大输出。这些字段大多已经存在于当前锁定
版本的 Pi Provider 模型目录，重复填写既容易出错，也使新增 Provider 的操作界面过于密集。

但 Pi 目录是随依赖版本更新的参考数据，不是本平台已经发布的配置事实。若 Worker 在运行时重新读取 Pi 并覆盖管理
配置，会让相同 revision 的含义随依赖升级漂移；自定义 OpenAI-compatible Provider 还可能复用 Pi 已知模型 ID，
却使用不同的 endpoint 或能力限制。

## 备选方案

### 方案 A：Worker 始终直接使用 Pi 最新目录

录入最省事，但管理员覆盖会失效，已发布 revision 无法保持稳定，故不采用。

### 方案 B：只允许内置 Provider 使用 Pi，自定义 Provider 全部手填

实现简单，但自定义网关代理已知模型时仍需重复录入相同能力，故不采用。

### 方案 C：Pi 目录只生成可编辑草稿，发布后以平台 revision 为准

内置 Provider 可从对应 Pi Provider 载入连接元数据和模型目录；自定义 Provider 可按模型 ID 或名称跨 Pi 目录查询并
复制模型元数据。所有字段在提交前都能修改，最终只保存解析后的显式值。

## 选择

采用方案 C，并固定以下边界：

1. 控制 API 从当前精确锁定的 `@earendil-works/pi-ai` 构建只读目录，返回 Provider ID、名称、Base URL 和模型能力。
2. 当前 Worker 只支持 `openai-completions` 动态 Provider，因此目录接口只暴露该 API 的 Provider 与模型；增加其他
   Pi API 必须单独扩展 Worker 协议并新增 ADR。
3. 内置 Provider 编辑器按 Provider ID 获取模型；自定义 Provider 可按模型 ID 或名称跨 Provider 查询。匹配结果只
   填充模型字段，不静默覆盖自定义 Provider 的地址。
4. Pi 字段是草稿初始值。管理员可以修改名称、启用状态、默认模型、推理与图片能力、上下文窗口和最大输出。
5. 发布后的 Provider revision 继续保存全部显式模型字段，Worker 不在运行时重新查询 Pi；Run 快照语义保持不变。
6. 模型目录接口受后台认证保护，不接收或返回 API Key，也不发起 Provider 网络请求。真实 `/models` 可用性仍由现有
   探针验证。

## 理由

该方案把“减少录入成本”与“配置可审计、可复现”分开：Pi 提供可信的默认元数据，管理员保留最终决定权，发布事实
不随依赖目录漂移。自定义 Provider 按模型名复用元数据，同时不会被错误地改写 endpoint。

## 影响

- 控制 API 新增 Pi Provider 列表和模型查询接口；
- 管理页面改为紧凑 Provider 列表、按需展开编辑器和可折叠模型高级设置；
- Pi 目录未命中时仍允许手工添加模型；
- Pi 依赖升级可能改变新草稿的默认值，但不影响已有 revision 和 Run。

## 验证

- 目录单元测试覆盖 API 过滤、Provider 查询、跨 Provider 的模型名/ID 排序和返回上限；
- API 测试覆盖认证、查询边界和响应中无秘密值；
- Web 测试覆盖内置 Provider 载入、自定义模型查询、自动填充后覆盖以及提交显式值；
- Worker 既有测试继续证明只消费 revision 中的显式模型配置。

## 可逆性与回退

目录接口和管理页面可以独立回退，不需要数据库 down migration。已由新页面创建的 revision 使用与
ADR-20260820090402 相同的显式结构，旧页面和 Worker 仍可读取。回退只会失去自动填充能力，不会改变已发布配置。
