# 浏览器内置 Pi 目录与后台配置服务独立降级

- 状态：部分已替代（模型配置流程与目录加载位置；离线目录与独立降级边界继续有效）
- 日期：2026-08-20
- 决策者：Runtime 维护者
- 关联任务/PR：后台不可用时仍需浏览 Provider 与模型元数据
- 替代关系：细化 ADR-20260820095113 的目录交付方式；模型保存即启用流程见 ADR-20260825180549，后台持久化事实源与离线目录边界继续有效

> 目录加载位置由 [ADR-20260906001531](20260906001531-pi-kernel-and-shared-model-catalog.md) 部分替代：控制 API 与浏览器共用 Protocol 窄入口中的生成快照和查询实现。公开元数据、可编辑初始值、Revision/Run 事实源及认证和独立降级约束继续有效。

## 背景

管理页面原本通过后台控制 API 读取 Pi Provider 目录。开发环境的 PostgreSQL、Sandbox 和 MinIO 依赖另一台机器的
uu 端口映射；端口映射不可用时，后台控制 API 无法启动，页面虽然已经实现 Provider 选择器，却只能显示“目录暂不
可用”。这把不需要数据库和网络的公开静态元数据，错误地绑定到了持久化服务可用性。

Pi 目录仍不能成为运行时配置事实。管理员的启用选择、字段覆盖和发布 revision 必须继续由后台保存并审计；前端也不
能在后台故障时伪造保存成功。

## 备选方案

### 方案 A：维持目录完全由后台 API 提供

服务边界单一，但后台或 PostgreSQL 故障会阻止管理员查看公开静态目录，开发预览也无法验收模型配置交互，故不采用。

### 方案 B：浏览器运行时直接打包 Pi Provider 实现

可以始终读取最新目录，但会把服务端 Provider 工厂、协议适配与可能的 Node 依赖带入浏览器包，扩大体积与安全边界，
故不采用。

### 方案 C：从精确锁定的 Pi 版本生成无秘密值的前端目录快照

构建仓库中保留只含 Provider 名称、公开 Base URL 和模型能力字段的生成文件。页面默认直接展示该快照；后台可用时
仍优先读取接口，网络或 5xx 故障时模型查询降级到快照。保存、探测和发布始终调用后台。

## 选择

采用方案 C，并固定以下边界：

1. 生成脚本只读取精确锁定的 `@earendil-works/pi-ai`，只保留 Worker 已支持的 `openai-completions` 模型；
2. 生成物不包含 API Key、Secret Ref、管理员选择、探测结果或任何部署地址中的凭据；目录本身按公开静态资产处理；
3. Provider 目录在模型页面默认展开，后台控制服务不可用时仍能选择内置 Provider、按模型名检索并修改初始值；
4. 后台返回 401/403 等权限错误时，API 客户端不得把错误静默降级为本地查询；只有连接失败或可重试 5xx 才降级；
5. 创建草稿、探测和发布没有本地替代路径，继续失败关闭并展示后台不可用；
6. 根级工程检查验证生成物与当前锁定 Pi 版本一致，升级依赖后必须重新生成并提交快照。

## 理由

该方案把“公开目录的可浏览性”和“受控配置的持久化”分离。用户可以在外部基础设施暂时不可用时看到并验收完整交互，
同时不会误以为配置已经保存。生成快照避免把 Pi 的服务端实现打入浏览器，并通过精确版本与漂移检查保持来源可追踪。

## 影响

- 后台页面生产包会增加模型目录静态数据体积；
- 页面离线展示的数据与生成时锁定的 Pi 版本一致，依赖升级需要刷新生成物；
- 后台可用时接口仍可作为目录响应来源，已有 API 契约不变；
- 数据库 revision、审计、秘密管理和 Worker 运行时语义均不改变。

## 验证

- 生成检查证明前端快照与当前 Pi 依赖一致；
- Web 单元测试覆盖 Provider 列表、按名称检索、协议过滤、连接故障降级和权限错误不降级；
- 控制台测试覆盖后台 overview 失败时仍直接展示 DeepSeek 与 Provider 数量；
- 浏览器人工验收确认 3003 不可用时目录可见，而错误横幅继续准确提示保存服务不可用。

## 可逆性与回退

可删除生成物和前端降级逻辑，恢复为纯后台目录，不涉及数据库迁移。由页面创建的 revision 仍是原有显式配置结构，
不依赖快照即可读取和运行。回退只会重新失去后台故障时的目录浏览能力。
