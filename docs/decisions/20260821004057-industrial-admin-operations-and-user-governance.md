# 工业化后台的信息架构、运营统计与用户治理边界

- 状态：部分已替代（后台配置工作流与用户交互；剩余有效范围见替代关系）
- 日期：2026-08-21
- 决策者：Runtime 维护者
- 关联任务/PR：把现有配置页扩展为可指导配置、可运营、可审计的平台后台
- 替代关系：扩展 ADR-20260819165254 的后台控制面范围，不改变配置 Revision 与 Run 快照事实源；第 2 条的探针域名白名单展示要求被 ADR-20260826155935 替代

- 被部分替代：[ADR-20260906195752](20260906195752-admin-task-oriented-configuration-and-publication.md)。配置指导与记忆多步启用、用户原因输入由新决策替代；真实统计、受限用户目录、权限及停用后会话撤销继续有效。

## 背景

后台首版已经能版本化模型、记忆和运行参数，但页面主要呈现字段名称。即使维护者了解项目，也需要回到源码和 `.env`
才能确认记忆服务实际使用 Mem0、哪些密钥必须配置、何时探测、发布后影响哪些 Run。总览虽然已有 Run、沙箱、记忆队列、
定时任务和 Skill 的真实聚合统计，却没有用户和对话口径，也没有独立的数据运营视图。

项目已经有本地产品账号、Session、Thread 和 Run 事实。后台若另建一套运营数据会产生漂移；若直接授予控制服务跨 Tenant
读取业务表和密码字段，又会破坏既有 RLS 与最小权限边界。用户停用还必须立即影响认证，并留下不可变审计。

## 备选方案

### 方案 A：只优化前端文案，用户和对话继续由 SQL 临时查询

改动小，但运营能力不可复用、无权限契约、无审计，后台仍不是日常工作入口，故不采用。

### 方案 B：后台直接获得所有业务表 SELECT/UPDATE

开发简单，但会同时暴露密码散列、盐、Session 摘要和对话正文，控制服务一旦失陷影响面过大，故不采用。

### 方案 C：配置知识前置到页面，运营数据经受限投影读取，用户状态经最小列权限治理

页面明确服务用途、配置前置、失败含义和发布流程；统计继续从 Migrator 拥有的聚合视图读取；管理员用户目录只投影账号
资料和计数，不含凭据或正文。状态变更仅允许更新 `user_accounts.status`，停用时撤销 Session，并写独立审计。

## 选择

采用方案 C，并固定以下边界：

1. 后台信息架构分为运营驾驶舱、数据运营、用户、模型、记忆、Skills 和运行配置；页面标题与说明使用业务语义，不把
   内部字段名当作唯一说明。
2. 记忆页明确当前实现是 Mem0 Platform，说明异步写入和按租户/用户作用域检索的数据流，并展示
   `MEM0_API_KEY`、`MEM0_SCOPE_HMAC_KEY` 与探针域名白名单的配置状态。页面永不读取或回显秘密值。
3. 用户与对话统计直接扩展 `admin_runtime_statistics`：用户总数、24 小时新增、7 日活跃、停用数，以及 Thread 总数、
   24 小时新增/活跃和归档数。页面必须同时展示统计口径，不把 Thread 数描述成消息数。
4. `admin_user_directory` 是带安全屏障的管理员专属投影，只返回 userId、邮箱、显示名、状态、时间和聚合计数；不得包含
   密码算法、密码盐、密码散列、Session Token 摘要或对话正文。
5. 用户目录和状态变更只允许 `admin` 角色。管理员不能停用自己；停用账号后认证查询立即拒绝该账号并删除现有 Session；
   恢复账号不会恢复旧 Session。
6. 控制数据库角色只获得用户表 `user_id` 的列级 SELECT、`status/updated_at` 的列级 UPDATE 和 Session DELETE，不能获得
   用户表完整 SELECT。每次真实状态变化写入 `admin_user_account_audits`，请求继续使用幂等键。
7. 运行配置页提供离线可读的部署配置地图，区分部署 Secret/基础设施连接、后台 Revision 和运行时检测三类真源，并按 P0/P1
   标注配置顺序；开发和生产分别以 `.env.example`、`deploy/production.env.example` 为契约，不在网页复制一份可漂移的默认值。
8. PostgreSQL 或后台服务不可用时，页面展示无法读取真实数据的原因，不使用演示数字冒充统计；静态配置说明仍可浏览。

## 理由

该方案让后台成为“知道系统如何工作的人可以直接完成配置和运营”的入口，同时复用已有事实源。受限投影满足跨 Tenant
运营所需的可见性，最小列权限和领域层角色检查限制误用范围。显式统计口径避免运营人员把技术指标误解为业务指标。

## 影响

- 新增用户目录、用户状态变更 API 和独立用户治理审计；
- 本地账号增加 `active/disabled` 状态，登录和资料解析只接受 active 账号；
- 停用用户会删除有效 Session，是有意的外部行为变化；
- 统计协议新增用户和对话分组，后台 API 与 Web 必须同步部署；
- 后台角色授权和 RLS policy 增加，但仍不获得密码材料或对话正文；
- 模型、记忆和运行配置的 Revision、发布与 Run 快照语义不变。

## 验证

- 协议测试拒绝用户目录中的额外凭据字段，并要求状态变更原因；
- 领域测试覆盖 admin-only、管理员不能停用自己和规范化查询；
- API 测试覆盖认证 actor、幂等键、查询边界和响应无凭据材料；
- 迁移测试覆盖安全屏障视图、RLS、最小权限、统计字段及不可逆回退保护；
- Web 测试覆盖 Mem0 配置说明、离线配置地图、统计口径、用户搜索和带原因的停用操作；
- PostgreSQL 集成门禁在 uu 端口映射可用时验证真实 RLS、Session 撤销和统计投影。

## 可逆性与回退

若尚无用户状态审计且所有账号仍为 active，可执行 down migration，移除目录、状态列并恢复旧统计视图。出现任何停用记录
或用户审计后，down migration 失败关闭，必须先由维护者确认数据语义，不能静默丢失治理事实。前端页面可独立回退，但新
统计协议与数据库迁移需保持同步。
