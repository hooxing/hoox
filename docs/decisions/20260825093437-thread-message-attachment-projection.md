# ADR-20260825093437：Thread 消息附件使用结构化展示投影

- 状态：已接受
- 日期：2026-08-25
- 决策者：Hoox 维护者
- 替代：无
- 被替代：无

## 背景

统一输入已经用 Resource/ResourceVersion 引用保存附件，并把模型需要的只读路径追加到最新 user turn。Thread 对话 API 为避免向用户暴露 Runtime 文件事实，会在返回正文前删除这段追加内容；结果是 Web 在发送后只能恢复文本，刚上传的图片和文件会从消息气泡中消失。

## 约束

- 安全与租户边界：附件展示必须重新使用当前 `TenantScope` 解析 Resource，不得信任消息正文中的名称或路径，也不得把对象存储键写入公开协议。
- 数据与迁移：现有 Thread Context 正文已经包含 Runtime 追加的 Resource 路径，修复不能要求回填历史记录或修改 Canonical Context。
- 兼容性：旧客户端必须可以忽略新增字段；附件不可用时仍应返回消息正文。
- 运维与故障恢复：页面刷新后必须能够从持久事实恢复附件展示，不能只依赖浏览器内存中的 `File`。
- 性能与成本：单条输入最多 20 个附件，展示解析必须保持该既有上限。

## 备选方案

### 方案 A：只保留浏览器本地预览

发送后把 `File` 的 Object URL 留在待处理消息中。实现局部，但刷新、切换任务或待处理消息转为持久消息后预览仍会消失，不能满足恢复语义。

### 方案 B：把完整附件对象写入 Thread Context 正文

Worker 在 `user_message` body 中新增附件元数据。新消息可直接读取，但历史数据仍需迁移或兼容解析，并会让模型事实与用户展示投影耦合。

### 方案 C：从现有文件事实生成结构化 API 投影

API 从 Runtime 追加段提取 Resource/ResourceVersion 身份，再通过 Resource Catalog 按当前租户重新解析规范名称、媒体类型和大小；正文继续隐藏内部文件事实，Web 使用结构化字段渲染文件卡片和图片预览。

### 暂不实现

继续让附件在发送后消失，会让用户无法确认模型实际收到的文件，也会使刷新后的对话记录不完整。

## 决策

采用方案 C。`ThreadContextMessageDto` 对 user 消息增加可选 `attachments` 数组，仅包含 Resource/ResourceVersion 身份、规范名称、媒体类型和大小。API 必须先重新授权解析，再输出附件；单个历史附件已删除或不可见时只省略该附件，不阻断正文读取。Web 对图片类型通过历史文件 inline 预览授权入口取得短期 URL 并内联展示，其他文件展示稳定文件卡片；待处理输入使用提交成功时已经解析的同一元数据，避免发送后的视觉跳变。

## 理由

该方案复用现有持久事实和租户授权，不需要数据库迁移，并同时覆盖发送后、轮询收敛后和页面刷新后的展示。相比修改 Canonical Context，它保持模型上下文、持久历史和用户展示投影之间的现有边界；相比纯本地预览，它具备可恢复性。

## 影响

### 正面影响

- 用户消息持续展示本轮附件，图片可以直接确认。
- 历史消息无需回填即可恢复结构化附件。
- 模型可见文件路径仍不会出现在用户正文中。

### 负面影响

- Thread Context 读取会为附件执行额外的 Resource 授权解析。
- 图片预览需要额外请求一个短期 inline 地址；失败时降级为文件卡片。

### 安全与隐私

- 消息正文只用于恢复不可变身份，公开元数据以当前 Tenant 下重新解析的 Resource 为准。
- 不公开 Blob key、物理对象键或长期 URL。
- 已删除或不再可见的附件不会因历史正文而重新获得访问权限。

### 数据、兼容与迁移

- 公开响应只增加可选字段，旧客户端兼容。
- 不修改数据库 Schema，也不重写历史 Thread Context。

### 运维与可观测性

- Resource 依赖的非 `NOT_FOUND` 故障仍按现有 API 故障语义暴露；单文件不存在不影响消息正文。

## 验证

- Resource 单元测试验证从当前和旧版附件事实恢复不可变引用，并忽略非法行。
- API 契约测试验证正文隐藏文件事实、附件按当前租户重新解析并输出结构化元数据。
- Web API 和组件测试验证附件字段跨分页保留、待处理消息显示文件卡片、图片使用受控 URL 渲染。
- 执行受影响包 typecheck、测试、格式、lint 与 `git diff --check`。

## 可逆性

可以删除新增可选协议字段和 Web 渲染逻辑，数据库与持久正文无需回滚。若后续决定把附件作为 Thread Context 原生结构化事实，可保留当前解析作为历史兼容层，再由新 ADR 替代本决策。

## 后续验证

- 部署后确认图片附件在发送、刷新和任务切换后持续可见。
