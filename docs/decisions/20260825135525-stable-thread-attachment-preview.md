# ADR-20260825135525：Thread 图片预览按不可变附件身份保持稳定

- 补充：[ADR-20260825093437：Thread 消息附件使用结构化展示投影](20260825093437-thread-message-attachment-projection.md)

## 背景

Web 会在 Run 活跃期间轮询 Thread Context。每次响应都会生成新的消息和附件投影对象，同时应用入口在每次渲染时重新绑定历史文件预览方法。图片组件把完整附件对象和该临时函数作为副作用依赖，并在副作用重启时先清空已经解析的短期预览地址。因此即使 ResourceVersion 没有变化，普通输入状态更新或轮询收敛也会让图片反复退回加载占位，再重新请求和显示，用户看到持续闪烁。

## 约束

- ResourceVersion 是附件授权和内容版本的不可变身份；规范名称、媒体类型和大小属于同一投影的展示元数据。
- 短期预览地址仍由当前 Tenant 的受控入口按需签发，不能改为公开地址或持久化到消息事实。
- Run 轮询必须继续刷新消息和执行状态，不能为了消除闪烁停用或降低关键状态轮询。
- 真正切换到不同 ResourceVersion 时必须重新解析预览，失败时继续降级为文件卡片。

## 备选方案

### 方案 A：每次轮询后保留占位动画

只调整动画或过渡样式可以降低视觉冲击，但仍会重复签发预览地址、重复加载图片，并掩盖不必要的副作用重启。

### 方案 B：全局缓存短期签名 URL

按 ResourceVersion 在应用级缓存预览地址可以减少请求，但需要处理签名过期、Tenant 切换、登出和缓存清理，扩大敏感短期地址的生命周期与所有权范围。

### 方案 C：稳定装配函数，并按 ResourceVersion 身份驱动组件副作用

应用入口只在 API Client 变化时绑定一次预览方法；图片组件保留最新展示投影，但加载副作用只依赖 `resourceId + versionId`、预览能力和稳定加载函数。普通父组件渲染或等价轮询投影不清空现有地址，身份变化时仍重新加载。

## 决策

采用方案 C。预览加载函数在工作台装配层按 API Client 记忆化；附件组件以 `resourceId + versionId` 作为预览生命周期身份，并通过引用读取该身份对应的最新投影。等价消息刷新不得清空或重新请求图片预览，ResourceVersion 或加载能力变化时按现有失败语义重新解析。

## 理由

该方案直接消除副作用依赖中的临时对象身份，不改变轮询、授权入口或签名 URL 生命周期。它把预览生命周期对齐到系统已经定义的不可变 ResourceVersion 身份，避免引入跨租户缓存和过期管理，同时保留真实附件变化时的正确刷新行为。

## 影响

### 正面影响

- 输入框状态变化和 Run 轮询不再使已展示图片闪烁。
- 同一 ResourceVersion 不再重复请求短期预览地址，减少 API 和对象存储签名开销。
- Thread Context 轮询频率与消息收敛语义保持不变。

### 负面影响

- 附件组件依赖 ResourceVersion 内展示元数据不可变；若未来允许原地修改媒体类型或内容，必须为该变化创建新 Version 或重新定义预览身份。
- 预览地址仍是组件内状态，组件真正卸载后再次进入消息会重新签发。

### 安全与隐私

- 不新增全局或持久缓存，短期签名 URL 仍只存在于当前组件生命周期。
- Tenant 授权、文件类型白名单和预览失败降级沿用既有受控入口。

### 数据、兼容与迁移

- 不修改公开协议、数据库 Schema 或持久消息。
- 仅收窄 Web 副作用触发条件，对旧数据和旧客户端无影响。

### 运维与可观测性

- 等价轮询期间的预览请求数量下降；真实 ResourceVersion 切换或组件重建仍会产生新请求。
- 预览接口错误仍按现有 UI 降级处理，不改变 API 错误契约。

## 验证

- 组件测试使用新分配但 ResourceVersion 相同的消息投影重新渲染，验证预览只加载一次且图片持续存在。
- 工作台测试在图片显示后触发父组件输入状态更新，验证装配的预览函数保持稳定且不重复请求。
- 执行 Web 定向测试、typecheck、格式、lint 与 `git diff --check`。

## 可逆性

可以恢复为每次渲染绑定函数和按完整对象驱动副作用，不涉及数据回滚；但会重新引入重复请求和闪烁。若未来需要跨组件缓存，应由新 ADR 明确签名过期、Tenant 隔离和清理策略后替代本决策。
