# ADR-20260826155935：自定义 Provider 探测直接使用已保存地址

- 状态：已接受
- 日期：2026-08-26
- 决策者：Runtime 维护者
- 关联任务/PR：移除模型与记忆 Provider 探测的静态域名白名单
- 替代关系：替代 ADR-20260821004057 第 2 条的探针域名白名单展示要求，以及 ADR-20260825164722 中依赖白名单恢复探测的部分；其他身份、凭据、Revision 和启用边界不变

## 背景

模型配置页允许管理员添加任意 OpenAI-compatible 自定义供应商，包括自行部署的 New API 网关。控制服务同时要求部署者
把每个供应商主机预先写入 `ADMIN_CONTROL_PROVIDER_HOST_ALLOWLIST` 并重启服务，否则探测会在发送请求前失败。该门禁
使页面保存的合法 HTTPS 地址不能独立决定探测目标，新供应商、供应商新域名和临时网关都需要额外修改部署配置。

实际故障中，已保存的 DeepSeek 配置、Revision 凭据和默认模型可以直接完成文本生成请求，但由于主机未进入静态白名单，
页面仍只得到统一的探测失败结果。静态白名单没有改善模型协议兼容性，却破坏了自定义 Provider 的主要使用路径。

## 备选方案

### 方案 A：保留静态白名单并改善错误提示

可以明确告诉管理员需要修改哪个环境变量，但新增自建网关仍必须修改部署并重启，核心操作链没有改善。

### 方案 B：在管理页面维护动态域名白名单

可以避免修改环境变量，但会新增第二套网络目标状态、授权流程和持久化语义。Provider 地址与白名单可能漂移，仍然不能做到
保存后直接测试。

### 方案 C：探测直接使用 Revision 中经过校验的 Provider 地址

删除静态域名白名单。模型与记忆配置继续只接受无用户信息的 HTTPS URL；探测继续禁止重定向、限制超时和响应正文大小，
并只发送固定的最小测试内容。

## 选择

采用方案 C：

1. `admin-control-api` 不再读取或暴露 `ADMIN_CONTROL_PROVIDER_HOST_ALLOWLIST`；开发、Demo 与生产配置契约同步删除该变量。
2. 模型探测将 `chat/completions` 解析到 Revision 保存的 `baseUrl`，记忆探测直接请求其 `baseUrl`，不再按主机名二次授权。
3. Provider 配置继续由领域层要求无凭据 HTTPS URL；探测继续使用 `redirect: "error"`、有界超时、固定测试文本和有界响应读取。
4. 管理页面不再把域名白名单列为部署前置，也不要求自建网关先经过额外配置。

## 理由

Provider 地址已经是管理员显式保存并审计的配置事实。再维护一份静态域名列表会产生两个目标真源，并把正常的供应商切换变成
部署操作。保留 HTTPS、无 URL 凭据、禁止重定向、超时和响应大小限制，足以表达当前探测职责；如果未来需要通用网络出口策略，
应由部署网络层统一实施，而不是在模型配置功能中维护供应商名单。

## 影响

- DeepSeek、New API 和其他自定义 OpenAI-compatible HTTPS 地址保存后可以立即测试，无需修改环境变量或重启控制服务；
- 记忆 Provider 同样不再依赖静态主机列表；
- 控制服务可以向管理员配置的任意 HTTPS 主机发起固定探测请求，部署方如需限制出口，应使用防火墙、代理或网络策略；
- 已保存 Revision、加密凭据、探测记录、启用状态和 Run 快照均不迁移；
- 旧部署继续设置已删除变量时会被严格环境解析视为未知配置，升级时必须删除该变量。

## 验证

- Provider 探针测试覆盖任意自定义 HTTPS 主机、路径拼接、禁止重定向、固定文本请求和响应结构校验；
- 进程配置测试和开发、生产环境契约确认不再要求或声明旧变量；
- Admin Web 测试确认部署地图与 Mem0 配置说明不再展示白名单；
- 使用已保存的 DeepSeek Revision 执行真实文本探测并确认返回健康状态。

## 可逆性与回退

该变更不涉及数据迁移。若必须恢复应用层出口限制，需要新增决策并恢复配置、进程解析、页面提示和探针校验；回退前应确认
所有正在使用的自定义 Provider 主机已经进入恢复后的策略，否则会重新造成保存成功但探测失败。
