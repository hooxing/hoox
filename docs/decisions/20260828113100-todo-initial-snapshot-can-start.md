# ADR-20260828113100：Todo 首次快照允许原子进入执行状态

- 状态：已接受
- 日期：2026-08-28
- 决策者：项目维护者
- 关联任务/PR：移除 `todo_write` 两段式初始化
- 替代关系：部分替代 ADR-0113 中“首次创建时所有项均为 pending”的约束

## 背景

`todo_write` 是 Agent 按任务复杂度自主使用的可选执行清单，不是 Run 启动门禁。原协议却要求首次快照全部为 `pending`，而工具说明同时要求开始步骤时更新为 `in_progress`。Agent 在创建清单时自然会把第一项直接标为执行中，Runtime 因此必然拒绝第一次调用；调用方必须先写一次全 `pending`，再立即提交内容相同、仅状态不同的第二个快照。

两次写入的最终状态与一次原子写入等价。额外的中间快照不提供新的安全、审计或恢复保证，反而增加模型调用轮次、失败机会和无业务价值的事件。

## 决策

1. 首次 Todo 快照允许使用 `pending`、`in_progress` 和 `completed` 的任意合理组合，同时继续限制最多一个 `in_progress`。
2. 首次快照可以直接把当前步骤设为 `in_progress`，也可以在 Agent 中途开始使用 Todo 时记录此前已完成的步骤。
3. 后续快照继续保持既有不变量：已完成项不能删除、改写或回退；调整结构或把执行中步骤退回 `pending` 时必须提供 `explanation`。
4. 不额外禁止首次快照全部为 `completed`。Todo 是可选进度事实，这种快照虽然通常没有必要，但不破坏状态一致性，也不值得新增一条只增加失败率的仪式性校验。

## 影响

- 创建清单并开始第一步从两次工具调用收敛为一次原子调用。
- Agent 可以在任务已经部分完成后再创建清单，并准确反映当前进度。
- 快照版本、`todo.updated` 事件、API 投影和 Web 展示格式保持不变。
- 不修改数据库 Schema，也不影响没有 Todo 的 Run。

## 验证

- Domain 测试覆盖首次快照同时包含 `completed` 与单个 `in_progress`，并继续覆盖多 `in_progress`、完成项不可变和结构调整说明。
- Pi Adapter 测试覆盖首次调用直接提交 `in_progress`，并断言工具说明不再要求全 `pending` 初始化。
- 运行受影响包的类型检查、测试、格式检查、Lint 与 `git diff --check`。

## 可逆性与回退

该改动只放宽写入校验，不改变持久化格式。若未来发现首次状态需要额外约束，应基于可证明的不一致风险新增 ADR，而不是恢复无状态收益的两段式初始化。
