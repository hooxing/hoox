# ADR-20260828120133：任务输入附件支持粘贴与可视预览

- 状态：已接受
- 日期：2026-08-28
- 决策者：Runtime 团队
- 关联任务/PR：任务输入框附件体验优化
- 替代：无
- 被替代：无

## 背景

任务输入框只能通过文件选择器添加本地附件，已选择附件仅显示文件名。截图、剪贴板图片和从桌面复制的文件需要先落盘再选择，图片与普通文件也缺少可快速辨认的视觉信息。历史图片已经具备受授权的短期预览地址，但任务输入阶段没有复用。

## 约束

- 粘贴纯文本必须继续进入文本框，只有剪贴板中存在文件时才拦截默认粘贴。
- 本地附件仍在提交时沿用既有上传协议，不能因预览提前上传或改变资源所有权。
- 本地预览不得持久化浏览器对象 URL；历史图片只能使用既有授权预览接口。
- 本地文件与历史文件继续共享最多 20 个附件的限制，并按稳定文件身份去重。

## 备选方案

### 方案 A：粘贴后立即上传并使用服务端地址预览

可以统一预览来源，但会在用户尚未提交任务时产生孤立资源、失败恢复和清理责任。

### 方案 B：本地文件使用浏览器对象 URL，历史图片使用既有预览接口

不改变提交和持久化边界；图片可以显示缩略图，非图片按媒体类型或扩展名显示图标。组件卸载或文件移除时释放对象 URL。

### 暂不实现

继续只显示文件名，用户仍需通过文件选择器添加剪贴板内容，也难以在发送前确认图片是否正确。

## 决策

采用方案 B。任务输入表单接收冒泡的粘贴事件：剪贴板包含文件时将其合并到待发送附件并阻止默认插入；只有文本时保持浏览器原行为。图片附件显示缩略图，其他附件显示与图片、音频、视频、表格、压缩包、代码或文档类别对应的图标。历史图片通过现有 `previewHistoryFile` 能力加载预览；失败时降级为图片图标，不阻断发送。

文件选择和粘贴共用去重与数量限制逻辑，历史文件占用同一 20 个附件上限。预览仅用于发送前确认，不改变上传时机、请求协议和 Resource 归属。

## 影响

- 正面：截图和复制文件可以直接粘贴；发送前能辨认图片内容和普通文件类型。
- 负面：图片缩略图会增加少量浏览器内存和历史预览请求；不支持的媒体类型统一降级为文档图标。
- 安全与隐私：本地图片不离开浏览器直到用户提交；对象 URL 在对应组件清理时释放。历史预览继续经过既有授权接口。
- 数据、兼容与迁移：不新增数据库迁移，不修改上传 API；旧浏览器缺少对象 URL 能力时降级为图标。
- 运维与可观测性：历史预览失败不显示额外错误，也不影响附件提交；服务端上传与错误观测保持不变。

## 验证

- Web 组件测试覆盖粘贴图片和压缩文件、阻止默认粘贴、图片对象 URL 预览、文件类型图标、发送按钮启用和对象 URL 释放。
- Web 组件测试覆盖历史图片通过授权接口加载预览。
- 受影响 Web 包执行测试、typecheck、格式和 lint 检查。

## 可逆性

可以移除粘贴处理、缩略图和类型图标，恢复原文件名标签；没有持久数据需要迁移。历史预览接口本身已被其他附件展示使用，不依赖本决策存续。
