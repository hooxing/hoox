# ADR-20260831143740：后台托管 SMTP 邮箱验证码并限制身份插件表面

## 状态

已接受，2026-08-31。补充 [ADR-20260824125500](20260824125500-embedded-identity-session-exchange-and-admin-configuration.md) 的邮箱密码边界；原决策中的身份配置加密、动态加载和 Hoox Session Exchange 保持不变。

## 背景

邮箱密码注册已经能够创建 Better Auth User 并立即交换 Hoox Session，但没有证明注册者拥有所填邮箱。Better Auth 数据表预留了 `email_verified` 和 Verification 存储，现有管理面也能安全保存 Provider 与短信秘密，因此邮箱验证应复用同一身份边界，而不是再增加独立身份服务或把 SMTP 密码放入环境变量、浏览器状态或普通日志。

Better Auth 的 Email OTP 插件同时注册邮箱验证、密码外登录、找回密码和邮箱变更端点。当前产品只要求邮箱所有权验证；直接暴露完整插件会无意增加密码外登录和账户恢复协议，超出当前管理策略与界面契约。

## 选择

1. Admin Control 的“身份与登录”配置增加邮箱验证码开关、发件人名称与地址、SMTP 主机、端口、安全模式、用户名和密码。SMTP 密码与既有 Provider、短信秘密一起使用 `BETTER_AUTH_SECRET` 派生的 AES-256-GCM 密钥加密；读取响应只返回 `smtpPasswordConfigured`，留空提交保留原密码。
2. SMTP 支持隐式 TLS 和 STARTTLS。隐式 TLS 直接建立加密连接；STARTTLS 必须完成协议升级，二者都要求 TLS 1.2 及以上并验证服务端证书，不提供明文 SMTP 或忽略证书错误的选项。
3. 启用邮箱验证码前，邮箱密码登录必须启用，且发件人地址、SMTP 主机、端口、用户名和密码必须完整。旧身份配置读取时补齐“邮箱验证码关闭、465 端口、隐式 TLS”的兼容默认值，不修改已经执行的身份迁移。
4. 邮箱密码注册启用验证后使用 6 位数字 OTP；OTP 有效期 10 分钟、最多尝试 5 次、在 Verification 表中哈希保存，发送端点每分钟最多请求 3 次。注册不会创建可交换的 Hoox Session；验证成功后 Better Auth 才建立 Cookie Session，Web 随后交换 Hoox Session。
5. 邮箱验证码关闭时，新建 Better Auth User 在数据库创建钩子中标记为已验证，避免这些账号在管理员以后开启验证时被无故锁定。功能上线前已经存在且 `email_verified=false` 的邮箱密码账号，在开启验证后的下一次登录必须通过发信邮箱完成验证。
6. Hoox 只开放 Email OTP 插件的“发送邮箱验证 OTP”和“验证邮箱 OTP”入口。默认验证链接、默认验证邮件、密码外邮箱登录、OTP 找回密码、邮箱变更及其他插件端点在内嵌身份边界返回拒绝响应，不能仅依靠前端隐藏。
7. `POST /v1/auth/exchange` 在邮箱验证开启时查询当前 Better Auth User 是否具有 `credential` 账号；具有密码凭据但邮箱未验证时拒绝交换。手机号和仅 OAuth 身份不因临时或第三方邮箱的验证状态被阻断。
8. SMTP 投递失败不签发 Hoox Session。管理员修正发信配置后，用户可以从验证页面重新发送验证码；秘密值不得进入错误正文、审计载荷或浏览器响应。

## 放弃的方案

- 仅发送点击链接：实现更简单，但不符合当前注册页面要求的数字验证码交互。
- 直接开放 Email OTP 插件全部端点：会隐式增加密码外登录和账户恢复能力，且没有相应后台策略、风控与用户界面。
- 只在前端等待验证码：无法阻止直接调用 Session Exchange，不能形成服务端安全边界。
- 把 SMTP 配置放入 `.env`：不满足管理员在后台按版本、幂等键和审计原因动态发布发信邮箱的需求。

## 影响

- API 生产依赖增加固定版本 Nodemailer；其 SPDX 许可证为 MIT-0。许可证策略显式允许 MIT-0，生产供应链、许可证清单和 SBOM 必须包含该依赖。
- 发信邮箱切换随身份配置版本立即生效，不需要重启 API；已有 Better Auth 实例在版本变化后由缓存重建。
- 邮箱验证码只证明邮箱所有权，不提供找回密码、多因素认证或邮箱变更能力。
- 邮件服务不可达、认证失败、TLS 失败或收件方拒收都会使本次发送失败；Hoox 不降级为未验证注册。

## 验证

- 身份包测试覆盖 SMTP 配置完整性、秘密保留和加密、TLS Transport 参数、OTP 插件选项、邮件内容以及关闭验证时的用户创建钩子。
- API 测试覆盖密码外 OTP 端点拒绝、非验证用途发送拒绝、未验证 credential 身份交换拒绝，以及 OAuth/手机号身份兼容。
- Web 测试覆盖注册后不提前持久化会话、验证码验证后交换 Session、重新发送入口和后台 SMTP 配置提交时不回显密码。
- 协议、类型检查、格式、Lint、供应链生成与相关应用测试作为交付门禁。

## 可逆性

关闭邮箱验证码即可恢复原邮箱密码登录行为，已验证状态保留。回退代码前应先关闭该开关；SMTP 配置和加密密码可以继续保留在身份配置中，旧版本读取 JSON 时会忽略新增字段。若需要彻底移除，应先停止验证码发送并通过新的迁移或管理命令清理相关 Verification 事实，不能修改既有迁移。
