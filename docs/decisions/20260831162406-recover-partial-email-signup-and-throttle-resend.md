# ADR-20260831162406：恢复邮箱注册部分成功并限制验证码重发

## 状态

已接受，2026-08-31。补充 [ADR-20260831143740](20260831143740-admin-managed-smtp-email-verification.md) 的 SMTP 失败语义与验证码发送限制；邮箱验证、受限插件表面和 Session Exchange 边界保持不变。

## 背景

Better Auth 的邮箱密码注册先持久化 User 与 credential Account，再等待邮箱验证发送器完成 SMTP 投递。SMTP 首次握手较慢、投递失败或反向代理提前结束请求时，浏览器可能收到失败响应，但账号已经进入未验证状态。用户再次点击注册时会命中防枚举的重复邮箱响应，导致第一次显示“注册失败”、后一次才进入验证码页面；这个反馈既误导用户，也会诱导重复提交。

验证码重发页面此前直接展示浏览器默认按钮。Email OTP 插件虽有按客户端地址和路径的请求限制，但页面没有冷却反馈，也没有按收件邮箱限制直接调用发送端点的请求，不能充分约束同一收件地址被持续骚扰。

## 选择

1. Web 的 Better Auth 注册请求失败后，使用本次提交的同一邮箱和原密码执行一次密码登录探测。只有身份服务明确返回“邮箱未验证”时，才把结果恢复为待验证状态；密码错误、账号不存在或其他失败继续呈现原注册错误。该探测不会签发 Hoox Session，也不会开放密码外邮箱登录。
2. 正常注册完成发信时，验证码页面记录“已发送”；从部分成功恢复时，页面明确说明首次发送状态未确认，不再声称邮件必然送达。两种情况都启动 60 秒倒计时，避免用户因响应不确定立即重复发送。
3. 验证码输入只接受最多 6 位数字。重发按钮使用产品样式、禁用态和秒级倒计时；验证码 10 分钟有效和发送限制作为辅助说明展示。
4. Email OTP 插件对发送端点的客户端地址限制收紧为每 60 秒 1 次。内嵌身份入口另外对规范化收件邮箱的 SHA-256 摘要建立 60 秒持久化冷却，限流键不保存明文邮箱；直接调用接口也必须经过该限制。
5. SMTP 失败、注册部分成功和发送限流都不能降级签发 Better Auth 或 Hoox Session。用户仍须取得验证码并完成邮箱验证。

## 放弃的方案

- 注册失败后始终重新提交注册：无法区分账号尚未创建和已经进入待验证状态，会延续重复提交与错误提示。
- 看到任意注册错误就进入验证码页面：会掩盖格式、数据库和真实注册故障，也无法证明提交的密码属于已创建账号。
- 只增加前端倒计时：可以改善交互，但脚本能够绕过，不能作为防滥用边界。
- SMTP 失败后删除刚创建的账号：跨越身份库与外部邮件系统做补偿删除容易产生竞态，并可能删除已经收到验证码或已经开始验证的身份事实。

## 影响

- SMTP 或代理超时发生在用户已落库之后时，页面会直接进入待验证状态并保留用户输入的邮箱，不再要求再次注册。
- 收件邮箱摘要复用 Better Auth 的持久化限流表，不新增迁移；限流值只保存摘要、计数和时间，不保存 SMTP 密码、验证码或明文邮箱。
- 同一客户端或同一收件邮箱在 60 秒内不能重复请求验证码。限流响应使用 HTTP 429，页面进入相同长度的冷却期。
- 已验证账号、密码错误或真正未创建成功的账号不会因恢复探测获得验证码登录能力。

## 验证

- Web API 测试覆盖注册返回 SMTP/代理错误后，同密码登录明确返回邮箱未验证时恢复为待验证状态。
- Web 组件测试覆盖首次发信成功与状态未确认两种页面、倒计时禁用态、6 位数字输入及验证后交换 Session。
- API 边界测试覆盖收件邮箱摘要限流、HTTP 429、重试时间和限流键不包含明文邮箱。
- Identity 测试固定 Email OTP 发送端点每 60 秒 1 次的插件配置。

## 可逆性

前端恢复探测、页面倒计时和收件邮箱冷却可以独立回退，不改变账号、Verification 或 Session 表结构。回退限流前应确认已有发送端点仍保留服务端频率限制；不得只保留浏览器禁用态。
