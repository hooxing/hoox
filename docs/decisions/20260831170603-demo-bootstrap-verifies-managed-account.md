# ADR-20260831170603：Demo 发布引导直接验证托管管理员邮箱

## 状态

已接受，2026-08-31。补充 [ADR-20260825145416](20260825145416-demo-admin-uses-hoox-session-gate.md) 的管理员初始化流程，并与 [ADR-20260831143740](20260831143740-admin-managed-smtp-email-verification.md) 的普通用户邮箱验证边界并存。

## 背景

Demo 持续部署通过固定的受限账号初始化平台管理员。管理员在后台启用邮箱验证码后，后续发布仍会先调用 Better Auth 注册，再使用密码登录并交换 Hoox Session。若该托管账号尚未验证，密码登录会按产品安全策略返回 403，发布因“Demo 账号登录初始化失败”中止；要求无人值守 CD 从邮箱读取 OTP 既不可靠，也会把邮箱凭据和交互状态引入发布流程。

## 选择

1. 发布脚本接受注册结果后，使用目标主机已有的受限 PostgreSQL 管理连接，按 `demo-account.env` 中的邮箱定位 Better Auth User，并幂等设置 `email_verified=true`。
2. 更新必须恰好返回已验证状态，否则发布失败关闭；随后才允许密码登录、Hoox Session Exchange 和平台管理员提升继续执行。
3. 该例外只适用于目标主机秘密文件托管的固定 Demo 管理员。普通注册、登录和验证码接口不增加绕过参数，浏览器用户仍须取得 SMTP OTP。
4. 发布日志不得输出 Demo 邮箱、密码或生成的 Hoox Session；SQL 继续使用 `psql` 变量传参。

## 放弃的方案

- 在 CD 中轮询并读取邮箱 OTP：需要额外邮箱凭据和不稳定的邮件解析，扩大秘密与失败面。
- 暂时关闭全局邮箱验证再发布：会影响同一时刻的普通用户注册和登录，并修改管理员已发布的身份策略。
- 允许未验证 credential 身份交换 Hoox Session：会破坏产品级服务端验证边界，影响所有调用方。

## 影响

- 开启邮箱验证后，Demo 发布仍可无人值守地初始化或恢复固定管理员。
- 该管理员的邮箱所有权由运维秘密文件和目标主机数据库权限共同担保，而不是由 SMTP OTP 担保；因此该环境只能承载演示数据。
- 不新增迁移，不改变普通账号数据模型或验证状态更新接口。

## 验证

- Demo CD 契约测试固定发布脚本在密码登录前更新 Better Auth User 的邮箱验证状态。
- 发布脚本继续检查注册、验证初始化、登录、Session Exchange 和管理员提升任一步骤失败即停止。

## 可逆性

移除该引导步骤后，必须先确保 Demo 管理员已经通过普通 OTP 完成验证，否则下一次发布会在密码登录阶段失败。已写入的 `email_verified=true` 按普通身份事实保留，不需要回退数据库结构。
