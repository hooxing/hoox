# ADR-20260901003001：共享 Hoox 品牌资产并替代字母占位

## 状态

已接受，2026-09-01。本决策扩展
[ADR-20260818144124](20260818144124-unify-project-identity-as-hoox.md) 的统一项目身份，不替代其命名、包作用域和部署标识结论。

## 背景

Hoox 已统一产品与技术项目名称，但 Web 工作台、账号入口和管理台仍用 CSS 方块中的字母
`H` 作为临时标记，浏览器入口也没有统一站点图标。已确认的品牌系统包含主横版、独立标志、App 图标和单色反白横版；如果各应用分别保存或裁切资产，后续修改会产生版本漂移，并可能让 Demo 的 Web 与 Admin 构建展示不同标识。

字标中的 `X` 具有明确的穿插结构：左上到右下的笔画连续位于上层，左下到右上的笔画在交汇处断开。它不是在完整 `X` 上覆盖两条白线形成的装饰效果。

## 备选方案

### 方案 A：各应用分别保存所需图片

接入直接，但 Web、Admin 和后续入口会复制相同二进制文件，难以证明哪一份是当前真源。

### 方案 B：继续使用 CSS 字母占位

没有静态资产和构建配置变化，但无法形成统一品牌，也不能提供 favicon、README 横版或深色背景版本。

### 方案 C：使用共享静态目录并按场景选择固定版本

四个原始 PNG 只保存在 `runtime-ts/public/brand/`，Web 与 Admin Web 的 Vite
构建共同复制该目录。小尺寸界面和 favicon 使用 App 图标，README 使用主横版，其余版本保留给独立标志和深色背景场景。

## 选择

采用方案 C，并规定：

1. `runtime-ts/public/brand/` 是当前品牌二进制资产的单一真源。
2. Web 与 Admin Web 使用同一绝对 `publicDir`，运行期基于各自 `BASE_URL` 读取
   `brand/` 路径，确保根工作台和 `/admin/` 子路径都由自身构建产物提供资产。
3. 用户侧栏、账号入口、管理台侧栏和两个浏览器入口统一使用 `hoox-app-icon.png`。
4. README 展示主横版；独立标志和反白横版保留为明确命名的正式版本。
5. 当前提交只承诺高分辨率 PNG；在没有经过几何复核的矢量真源前，不从栅格自动追踪并宣称为正式 SVG。

## 影响

- Demo 镜像构建 Web 与 Admin Web 时会包含同一组品牌文件。
- 原有字母 `H` 占位不再承担产品标志；文字名称和“你说，它做。”宣传语保持不变。
- 品牌文件名成为 HTML 与组件引用的静态接口，更名必须同步修改构建、界面、测试和参考说明。
- PNG 增加仓库和 Demo 镜像体积，但避免应用间重复源文件；构建产物仍各自复制静态资源。

## 验证

- 契约测试校验四个 PNG 的签名、精确尺寸和最低文件大小。
- Web、账号入口和 Admin Web 组件测试固定 App 图标路径。
- Web 与 Admin Web 构建验证共享静态目录会进入两个 `dist/brand/`。
- 格式、Lint、受影响包类型检查和测试作为提交前门禁。

## 可逆性

界面可以回退为字母占位，Vite 也可以恢复各自默认静态目录；回退时应同时移除 favicon、共享资产、参考说明和构建契约，不能留下失效的 `/brand/` 引用。已公开缓存的 PNG 路径可继续保留，不影响业务数据或数据库结构。
