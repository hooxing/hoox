# ADR-20260901104943：共享 UI 主题 Token 与渐进迁移边界

- 日期：2026-09-01
- 决策者：Hoox 维护者
- 关联 Issue / PR：无
- 替代：无
- 被替代：品牌色与通用操作的映射由
  [ADR-20260901155352](20260901155352-brand-green-scarcity-and-action-separation.md) 部分替代；共享主题包与渐进迁移边界继续有效

## 背景

Web 工作台在单一 `styles.css` 中维护大量相近灰色、灰绿色、圆角和阴影，Admin Web
又在 Ant Design `ConfigProvider` 与自身样式中维护第二套视觉值。两端都已引用共享品牌目录，
但没有共享颜色、排版、间距、表面和状态语义。继续按页面修补会让同一个“主要操作”“功能边框”
或“错误状态”产生多个实现，也无法集中验证对比度。

[Hoox UI 重构实施计划](../plans/20260901-hoox-ui-refactor.md)提出两种所有权方案：独立主题包，
或由单一真源生成两端样式。首个实施切片还必须允许未迁移页面保持当前行为，不能要求一次性重写
两个应用。

## 约束

- 安全与租户边界：主题层不得读取账号、Tenant、Thread、Run 或请求级数据，也不得执行宿主机操作。
- 数据与迁移：本决策不修改数据库、API、领域状态或持久化语义。
- 兼容性：Web 与 Admin Web 的路由、构建入口和现有业务类名继续可用；局部页面允许渐进迁移。
- 运维与故障恢复：主题包必须随应用构建进入静态产物，不依赖运行期网络、数据库或动态调色服务。
- 性能与成本：主题层保持为无运行期依赖的 CSS，不为静态 Token 引入组件框架或客户端生成器。
- 交付范围与时间：先迁移 Web 应用外壳；Admin Web 先加载同一 Token，Ant Design 映射在管理台切片中完成。

## 备选方案

### 方案 A：独立 `@hoox/ui-theme` CSS 包

共享包只拥有原始色阶、语义角色、字体、间距、圆角、阴影、透明度和动效刻度。Web 与
Admin Web 在本地样式前导入同一 CSS，业务组件继续由各应用拥有。优点是依赖方向明确、无运行期
生成成本、可由普通 CSS 和测试直接验证；代价是迁移期会暂时存在旧字面量。

### 方案 B：生成脚本向两个应用写入主题文件

单一配置可生成 Web CSS 与 Ant Design 映射，能够自动同步多种输出；但会增加生成产物、构建顺序
和事实源定位成本，且首个切片尚没有必须由生成器解决的多格式需求。

### 暂不实现

继续在两个应用内分别修改颜色和尺寸，短期文件更少，但新页面会继续复制视觉值，后续暗色模式、
对比度修复和 Admin 迁移都需要跨文件人工同步。

## 决策

采用方案 A，新建 `runtime-ts/packages/ui-theme`，并规定：

1. `theme.css` 是当前原始视觉刻度与 Light 语义映射的唯一事实源，原始颜色使用固定 HSL 值。
2. 功能样式引用 `surface`、`text`、`border`、`action`、`focus` 和 `status` 语义角色，不直接引用原始色阶。
3. 共享包不包含业务组件、领域状态、路由和应用级布局；Web 与 Admin Web 继续拥有各自组件。
4. Web 与 Admin Web 必须在应用样式前导入共享主题。迁移按页面或外壳切片推进，旧样式不得覆盖已经迁移组件的语义角色。
5. 首个切片迁移 Web 侧栏、顶栏、导航、账号入口容器、通用按钮、Composer 和运行状态徽标；功能中心与 Admin Ant Design 主题映射后续迁移。
6. 暗色模式在 Light 语义稳定后新增映射，不通过交换色阶端点或 CSS 滤镜实现。

## 理由

独立 CSS 包满足两个应用共用单一静态真源的当前需要，同时避免把业务组件或 Ant Design 依赖引入
共享层。语义角色让组件表达用途而不是色值，能够集中验证普通文字 4.5:1、功能边框 3:1、
Focus 与状态表达。渐进边界允许每个切片独立测试和回滚，不让视觉重构扩大到领域行为。

生成方案在需要同时产出 TypeScript、CSS 和设计工具格式时仍可重新评估；当前只有 CSS 消费者，
提前增加生成链路的维护成本高于收益。

## 影响

### 正面影响

- Web 与 Admin Web 获得同一组品牌、表面、文字、功能边框和状态语义。
- 对比度与必需 Token 可在共享包内自动验证。
- 页面迁移可以独立提交和回滚，不要求一次性改写 6000 余行应用样式。

### 负面影响

- 渐进迁移期间，未迁移页面仍包含旧颜色、字号、圆角和阴影字面量。
- Admin Web 已加载共享 Token，但 Ant Design `ConfigProvider` 在对应切片完成前仍保留现有映射。
- CSS 自定义属性属于两个应用的全局静态接口，更名需要同步更新消费者和测试。

### 安全与隐私

- 主题包只包含静态 CSS，不接触用户数据、凭据、网络和宿主机能力。

### 数据、兼容与迁移

- 不涉及数据库迁移、API 或领域数据。
- 应用构建增加一个 workspace CSS 依赖；现有类名在完成对应切片前保持兼容。

### 运维与可观测性

- 构建失败时不会回退到远程主题；依赖解析失败会直接使应用构建失败。
- Token 契约测试提供必需角色和对比度证据，视觉基线在各页面迁移时补充。

## 验证

- `runtime-ts/packages/ui-theme/theme.test.ts` 校验必需语义角色、普通文字与状态文字 4.5:1、功能边框 3:1。
- Web 样式测试校验外壳宽度、正文宽度、语义 Token 引用和发送按钮禁用态。
- Web 组件测试校验运行状态同时包含图形与文案。
- Web 与 Admin Web 的 Typecheck、测试和 Vite 构建验证 workspace CSS 能被两个入口解析。

## 可逆性

在未形成第三方主题扩展接口前，可以逐个恢复应用的主题导入和已迁移选择器，再删除共享包及
workspace 依赖。回退不涉及持久数据。若后续公开 Token 名称或生成多种衍生主题，应新增替代 ADR，
保留兼容别名和迁移窗口。
