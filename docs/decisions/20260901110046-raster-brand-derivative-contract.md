# ADR-20260901110046：固定品牌栅格衍生资产与入口尺寸

- 状态：已接受
- 日期：2026-09-01
- 决策者：Hoox 维护者
- 关联 Issue / PR：无
- 替代：无
- 被替代：无

## 背景

[共享 Hoox 品牌资产并替代字母占位](20260901003001-shared-brand-assets-and-product-surfaces.md)
接受了四个高分辨率 RGB PNG 和共享静态目录，但这些文件都已合成背景，不能直接用于透明表面、
单色场景、小尺寸 favicon、Apple Touch、PWA Maskable 或 Open Graph。浏览器运行期缩放
1254px App 图标也不能固定 16–48px 下的锐化结果。

当前没有经过几何复核的 SVG 真源。自动描摹会改变双钩负空间、两个 `O` 的相向开口或 `X` 断笔，
因此需要在不宣称获得矢量真源的前提下补齐可验证的栅格接口。

## 约束

- 安全与租户边界：静态资产不包含用户、租户、环境或生产数据。
- 数据与迁移：不涉及数据库和对象存储迁移。
- 兼容性：现有四个 PNG 文件名、像素内容和引用继续可用；新增文件名成为公开静态接口。
- 运维与故障恢复：透明化或缩放失败时必须继续使用现有四个源 PNG，不得发布缺失标志的构建。
- 性能与成本：浏览器入口使用目标尺寸文件，避免下载和实时缩放 900KB 级源图。
- 交付范围与时间：本切片只接受栅格衍生物，不接受自动描摹 SVG。

## 备选方案

### 方案 A：提交固定尺寸栅格衍生物

从现有横版、独立标志和 App 图标生产透明、单色、入口图标、PWA 与 Open Graph PNG，保留源文件
不变，并用像素契约测试固定尺寸、Alpha、颜色纯度和安全区。优点是当前即可消费且结果稳定；代价是
衍生文件增加仓库体积，重新生成仍受栅格输入质量限制。

### 方案 B：浏览器运行期缩放或 CSS 去背景

无需新增文件，但小尺寸锐化由浏览器决定，CSS 滤镜无法正确恢复抗锯齿 Alpha，也无法提供
Maskable 安全区和固定 OG 画布。

### 暂不实现，等待正式矢量真源

能够避免栅格衍生，但 favicon、Apple Touch、PWA、透明背景和社交分享入口继续缺失，且矢量交付
时间尚不确定。

## 决策

采用方案 A，并规定：

1. 现有四个 RGB PNG 保持原样，继续作为当前构图和像素输入。
2. `runtime-ts/public/brand/` 新增透明横版、透明独立标志、横版纯黑/纯白、16/32/48px favicon、180px Apple Touch、192/512px PWA、512px Maskable 和 1200×630 Open Graph PNG。
3. Web 侧栏使用透明独立标志；Web 与 Admin Web 的 favicon 和 Apple Touch 入口使用目标尺寸文件。Web PWA manifest 使用固定 PWA 与 Maskable 文件。
4. 透明资产必须包含真实 Alpha 和部分透明抗锯齿像素；单色可见像素只能是纯黑或纯白。Maskable 前景必须落在中心 80% 安全圆内。
5. 自动描摹结果不得加入 SVG 真源。取得原始矢量或完成手工几何复核后，应另行决策矢量所有权与替代关系。
6. 当前衍生物可追溯到明确源文件和像素算法，但仓库尚未固化跨平台、固定 PNG 编码参数的生成器；在生成器通过契约前不得批量覆盖当前文件。

## 理由

固定衍生物让每个消费场景拥有明确画布、色彩类型、Alpha 和锐化结果，避免运行期近似处理。源文件与
衍生物并存可以维持既有静态接口，并让未来矢量真源按文件逐步替换。像素级测试能够证明最重要的
失败语义：不是只有 RGBA 声明，而是真的存在透明边缘；单色没有灰色污染；Maskable 不会被系统裁切。

## 影响

### 正面影响

- favicon、Apple Touch、PWA、Maskable、透明表面、单色和 OG 获得明确文件接口。
- Web 侧栏不再依赖带深色背景的 App 图标裁切。
- 构建与测试能直接发现尺寸、Alpha、颜色类型和安全区回退。

### 负面影响

- 新增 12 个 PNG，仓库和两个前端构建产物体积增加。
- 栅格透明化无法提供真正无损的任意尺寸缩放。
- 当前生成过程使用 Windows GDI+ 默认 PNG 编码器，尚不能保证跨平台字节级复现。

### 安全与隐私

- 文件只包含 Hoox 品牌图形，不读取或嵌入用户数据、凭据和环境信息。

### 数据、兼容与迁移

- 原四个路径继续存在；新增路径在公开后按静态接口维护。
- `manifest.webmanifest` 只声明静态入口，不改变账号、路由和离线数据行为。

### 运维与可观测性

- PNG 契约测试在 CI 解码实际像素，不依赖图像查看器元数据。
- 未来生成器必须固定输入、尺寸、色彩类型、缩放、锐化和编码参数，并以当前像素契约作为最低门槛。

## 验证

- `tests/brand-assets.test.ts` 校验 16 个 PNG 的签名、尺寸、色彩类型和原始文件下限。
- 测试实际解码 RGBA，校验透明/部分透明/不透明像素与纯黑、纯白前景。
- 测试校验 Maskable 前景最大半径不超过 512px 画布的 40%，OG 四角为纸白。
- Web 组件测试固定侧栏透明标志路径；HTML 与 manifest 契约测试固定 favicon、Apple Touch 和 PWA 路径。
- Web 与 Admin Web 构建验证共享静态目录能够复制新增资产和 manifest。

## 可逆性

组件和 HTML 可以恢复旧 App 图标引用，但已公开的新静态路径应继续保留到浏览器缓存、manifest 和
外部引用完成迁移。删除衍生物不涉及业务数据；回退时必须同步恢复测试和品牌参考，不能留下失效路径。
