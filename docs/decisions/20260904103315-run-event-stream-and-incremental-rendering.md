# ADR-20260904103315：持久 Run 事件推送与增量正文渲染

- 状态：已接受
- 日期：2026-09-04
- 部分替代：[ADR-0039](0039-web-local-agent-workbench.md) 的正文短轮询选择，以及 [ADR-0042](0042-local-web-experience-read-contract.md) 的实时流后置选择；同源、授权、事件持久化、分页和 Artifact 边界继续有效。
- 当前说明：[Development API 的 Run 事件](../reference/development-api.md#run-事件)

## 背景与约束

Web 将正文事件、交付物和上下文放在同一次轮询中等待，正常路径就会增加约 1.2 秒的间隔及辅助接口耗时。每次更新重新回放历史事件和解析 Markdown，会使长回复进一步变慢。优化需要覆盖传输与渲染，同时保留 PostgreSQL 中已提交事件作为唯一事实源、Tenant 授权和 Attempt 内 sequence 恢复语义。

## 备选与选择

1. 缩短 REST 轮询间隔：改动小，但增加空请求，且不能解决辅助接口阻塞、全文重算和页面跳动。
2. SSE 携带持久事件页，配合数据库提交通知唤醒补读：复用现有身份、游标和读取事务，适合浏览器单向接收正文。
3. WebSocket 或独立非持久 token 总线：适合双向复用，但引入另一套连接协议；若提前展示未提交文字，还需要定义回滚、更正和进程重启后的差异。

采用方案 2。浏览器以 fetch 读取 SSE，继续使用 Authorization 与 Tenant Header；不把令牌放入 URL。API 每次补读重新认证并确认 Run 归属，通过已有 Tenant 事务读取最新 Attempt。流按有限页读取并服从 Node 流背压；连接定期结束，浏览器按已接收游标续连。旧分页接口保留用于历史、补读及旧服务兼容。

Worker 在原事件写入 SQL 中调用 `pg_notify`，通知随原事务提交，并且只包含 Tenant/Run 的散列路由键。API 每进程使用一条专用 LISTEN 连接。通知不是授权或持久事实，不携带正文；订阅先于初次补读，建立监听后主动唤醒，断线重建和定时补读覆盖通知丢失。没有新增迁移，也不放宽事件、checkpoint 或副作用的提交顺序。

正文消费与 Artifact、Thread 上下文刷新独立。前端首批文字和控制事件立即发布，连续文字按帧合并；事件投影只折叠追加部分。正文与最终回复保持组件身份，滚动仅在用户跟随底部且高度改变时更新。

Markdown 采用 DeepSeek Harness 固定提交 `76fda729799fe9b3848dbe2c211d4b231032b81e` 的纯增量解析器，源码、MIT 许可证与来源进入 `runtime-ts/vendor/deepseek-markdown`。它冻结稳定前缀并处理未闭合代码围栏；Hoox 继续拥有 GFM 语法、链接净化、禁用原始 HTML 和第三方图片请求等策略。跨块引用或脚注退回全文解析以保持语义。没有引入上游会话运行时、传输层或 UI 框架。

## 影响与验证

每个 API 进程最多新增一条常驻监听连接；事件页仍执行授权和数据库读取，不能把模型、数据库或网络的耗时解释成已消除。代理必须允许流式转发。浏览器维护未发布文字的短暂缓冲，但停止或切换任务时丢弃未发布回调，不影响服务端持久事实。

直接验证覆盖 SSE 任意字节分片、通知与初读竞态、Attempt 切换、断线游标、取消、旧服务降级、租户隔离、Markdown 引用与安全行为、稳定 DOM 和长代码解析工作量。真实 PostgreSQL 集成验证事务回滚不通知、提交后可读取事件、幂等重放不重复通知，以及既有 mutation 栅栏和重试。

## 可逆性

可以回退前端到保留的分页接口，并撤去通知和监听装配；数据库事实及已有游标语义不变，不需要数据迁移。新增 SSE 协议的调用方应先切回分页，再移除端点。第三方解析器可整体撤去，恢复既有 ReactMarkdown 全文路径。
