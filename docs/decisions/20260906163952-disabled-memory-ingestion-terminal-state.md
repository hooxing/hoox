# ADR-20260906163952：关闭记忆时使用独立的消费终态

- 状态：已接受
- 日期：2026-09-06
- 替代关系：部分替代 [ADR-0153：Mem0 持久写入与 User Turn 检索闭环](0153-mem0-durable-ingestion-and-user-turn-retrieval.md) 中关闭功能时不登记、不消费的结论；保留成功 Run 原子登记、Provider 两阶段提交、Tenant 隔离和低信任检索边界。
- 当前说明：[维护者开发边界](../maintainers/runtime-development-boundaries.md)

## 背景

Worker 按 Run 固定配置解析记忆提供方。成功 Run 的终态事务仍可登记记忆 Outbox，消费者遇到关闭配置时必须结束本地任务。原实现调用 `complete`，却没有 Provider 事件和提交时间，与数据库的成功约束冲突。维护因此失败，租户调度租约保留至过期，使后续 Run 反复等待重领。

## 选择与理由

为本地跳过增加 `skipped` 终态和受原 claim 栅栏保护的 `skip` 操作。该状态表示配置关闭后停止消费，不表示 Provider 成功或失败。释放 claim 并记录完成时间；已提交的事件与时间保留，未提交的任务两者均为空，不生成虚假的外部事件。

`succeeded` 继续要求 Provider 事件和提交时间。使用 `failed` 会污染失败统计；放宽 `succeeded` 或伪造事件会破坏外部副作用事实；只阻止新增 Outbox 无法收敛已有积压，均不采用。成功事务中的登记方式保持不变，避免引入第二套配置判断。

## 影响与恢复

新增 0059 迁移扩展状态和约束，不修改已发布迁移，不批量改写既有任务。消费者通过现有租约到期重领机制处理 `pending`、`submitted` 和过期 `claimed`。`skipped` 不参与领取、待处理统计或租户下一次调度时间，也不计入 Provider 失败。维护成功后沿用原有 settle 释放租户租约；真正的维护失败继续保留租约重试。

发布顺序为先迁移，再启动新 Worker。应用回退可保留扩展后的 schema；旧消费者会忽略 `skipped`，但仍可能重现关闭配置的原缺陷。数据库 down 在存在 `skipped` 时拒绝执行，不能通过把它改成成功或失败来伪装无损回退。外部已提交事件的停止轮询不等于取消或删除 Provider 数据。

## 验证

消费器测试覆盖关闭配置、陈旧 claim 和持久化失败传播。真实 PostgreSQL 回归覆盖三种待处理来源的跳过、成功约束不放宽、事件信息保留、租约代际栅栏、终态不再领取、维护 settle 后新 Run 可领取，以及存在跳过事实时拒绝回退并保留 FORCE RLS。既有成功 Run 原子登记与 Provider 成功写回测试继续执行。
