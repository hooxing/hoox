# ADR-20260906183557：CI 独立容器并行与兼容汇总门禁

- 状态：已接受
- 日期：2026-09-06
- 决策者：工程团队
- 关系：补充 [ADR-20260903165842](20260903165842-ci-single-build-and-container-cache.md)，保留单次 clean build、独立开发入口和 PR/main 取消策略。
- 当前说明：[CI 合并门禁](../maintainers/runtime-development-boundaries.md#ci-合并门禁)

## 背景

2026-09-06 审查最近三次 main CI，总耗时分别为 8 分 47 秒、9 分 39 秒和 9 分 32 秒。完整工程检查占 311–322 秒，随后串行构建 Pi Prompt 镜像占 163–196 秒；生产 Job 中三个容器 Gate 串行占 409–416 秒。Pi 已命中依赖缓存，继续调整安装缓存不足以消除串行等待。证据：[最近运行](https://github.com/hooxing/hoox/actions/runs/34026081211)、[第二次运行](https://github.com/hooxing/hoox/actions/runs/34007004045)、[第三次运行](https://github.com/hooxing/hoox/actions/runs/33975102152)。

容器各自在固定基础镜像内安装并构建源码；宿主机门禁脚本只依赖 Node.js 内置模块，因此不依赖工程 Job 的输出。拆分不需要复制工作区构建产物，但必须保留既有必需检查名称和失败关闭语义。

## 备选与选择

- 保留串行、只加缓存：能够减少冷安装，但不能消除独立门禁的等待，Pi 的近期数据已证明缓存命中后仍有明显构建成本。
- 拆分工程内部 build/typecheck/test 并传递产物：增加产物完整性与 clean workspace 证明成本，继续沿用前一 ADR 的拒绝理由。
- 并行运行独立容器，保留兼容汇总检查：选择此方案。工程内部继续一次构建复用，Pi 独立运行；生产静态检查与三角色容器矩阵并行。

## 决策与不变量

1. 保留“工程基线校验”和“Production 静态与容器 Gate”作为稳定的汇总检查名。汇总使用 `always()`，显式要求所有直接依赖结果为 `success`；失败、跳过和取消不能变成成功。生产矩阵关闭 fail-fast，使其他角色继续给出诊断，但不放宽汇总结果。
2. clean workspace、跨平台进程和 M4 黑盒检查内容不减。Pi 和生产镜像的构建与执行不依赖宿主机 pnpm 安装；运行时检查仍使用仓库内门禁脚本。
3. 生产镜像使用 Buildx `load` 和各角色独立的 GitHub Actions 缓存 scope，避免角色间覆盖缓存；脚本接收本次构建的不可变本地镜像 ID。缓存遵循 [Docker 官方后端说明](https://docs.docker.com/build/cache/backends/gha/)，不引入远端镜像发布或宿主工作区产物缓存。
4. 接收预构建镜像只改变镜像获取与清理所有权。上下文 canary、入口、用户、只读文件系统、供应链文件和失败关闭验证继续执行。外部镜像只允许本地 inspect，非法 ID 或缺失镜像直接失败且不删除；未提供镜像时继续本地构建，清理合法构建输出。
5. 汇总检查不替代仓库管理员配置分支保护。工作流调整保留现有检查名，远端 ruleset 仍需明确要求其成功。

## 影响与验证

并行缩短关键路径，但增加同时占用的 Runner 数和重复基础层下载；缓存导入、导出也有开销，不能把估算当成实际提速。容器安全断言、迁移和部署协议不变。

工作流契约测试覆盖独立依赖图、两个汇总检查的结果要求、完整角色矩阵及镜像输出接线；镜像测试通过真实 Gate 入口和模拟 Docker 结果覆盖本地构建、预构建、探针执行、失败关闭与清理所有权。格式、lint、类型检查、完整工程检查和 Actions 语法检查用于本地验证；实际容器行为与墙钟收益由后续 CI 运行验证。本机 Docker 引擎不可用时，不把模拟测试写成真实容器 Gate 通过。

## 可逆性

无持久化变更。若缓存不稳定，可移除 Buildx 预构建和镜像参数，脚本恢复自行构建；若并行 Runner 成本不可接受，可把容器步骤移回原 Job，并保留旧检查名称。回退不能删减原有安全探针或 clean workspace 条件。
