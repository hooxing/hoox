# ADR-20260906195752：后台按管理任务保存配置与发布技能

- 状态：已接受
- 日期：2026-09-06
- 决策者：Runtime 维护者
- 当前说明：[配置参考](../reference/configuration.md)、[身份与会话](../architecture/identity-and-session.md)、[Skill Runtime](../architecture/skill-runtime.md)、[维护者开发边界](../maintainers/runtime-development-boundaries.md)

## 背景

后台把不可变版本、草稿、探测、启用和审计原因直接变成了日常操作步骤。模型修改要区分保存与使用；记忆表单总是从默认值创建新配置；运行参数和部署说明占据管理导航；管理员发布自己上传的技能也要经过提交和复核。管理员填完表单后，仍需判断操作是否真正完成。

不可变事实、权限、审计和 Run 快照解决并发与恢复问题，仍需要保留。但这些内部保证不依赖管理员理解版本号、反复输入原因或手动推进内部状态。

## 备选方案与选择

| 方案 | 取舍 |
| --- | --- |
| 保留全部步骤，仅重新排版或折叠字段 | 无法消除保存后尚未生效、重复审批和技术参数所有权不清的问题 |
| 由浏览器顺序调用保存、探测、启用 | 按钮减少，但部分请求成功后仍留下未启用配置，重试和并发覆盖难以解释 |
| 直接覆盖现行配置并删除版本 | 界面简单，但破坏旧 Run 恢复、密钥绑定和审计事实 |
| 后台提供原子管理动作，内部保留不可变事实；部署参数回归配置文件 | 采用；需要明确兼容入口，并为脱离后台配置的压缩参数建立独立快照 |

## 决策

### 模型与记忆一次保存生效

1. 管理 Web 的模型编辑器只提供“保存并使用”；供应商列表保留“使用”和“测试已保存配置”。编辑器不提供测试旧保存值的按钮。模型 ID 与名称直接编辑，能力参数可在高级设置中修改，目录只提供初始值。
2. `PUT /v1/admin/control/model-providers/current` 和 `PUT /v1/admin/control/memory-providers/current` 在一个服务端事务中创建不可变配置并切换 active。请求携带幂等键及必填 `expectedGeneration`；零值有效，页面不展示该字段。权限或并发检查失败不会留下待启用配置，也不会改变当前配置。
3. 两个保存动作均要求控制面 `admin`。模型密钥继续加密绑定具体配置，编辑时可复用或替换；记忆继续引用部署秘密。模型与记忆的保存或发布均不要求探测通过，包括旧发布接口；模型测试是独立的受限文本调用，测试结果不自动切换配置。
4. 记忆页带入当前配置，按实际 `enabled` 显示开启或关闭，不展示内部标识、Secret Ref、版本和发布链路。记忆保存要求先接入后台当前模型，因为没有后台模型时 Worker 使用整套部署回退配置，不能将未被 Runtime 采用的记忆配置宣称为生效。
5. 模型与记忆的旧草稿、探测和发布接口保留兼容调用，但旧记忆发布同样不再要求健康探测；网页保存不再调用旧草稿接口。历史配置、探测、activation 与审计不删除；已建立的托管模型或记忆 Run 快照及密钥绑定继续有效。
6. 控制配置、身份和用户操作自动保存审计，网页不要求填写变更原因。身份的期望版本、幂等和秘密加密保留在协议内部。停用账号保留一次明确的会话撤销后果确认；恢复账号可直接执行。审计页显示操作者、动作与结果，不展示内部版本号。

### 运行参数由部署配置拥有

1. 后台移除运行配置导航、部署配置地图和七个运行参数表单；旧 `/settings` 跳转到身份设置。运行设置的创建、发布写路由不再注册，旧配置读取和持久化事实仅为兼容恢复保留。
2. `AGENT_WORKER_MAX_CONCURRENT_RUNS` 默认 `20`、`AGENT_WORKER_USER_MAX_CONCURRENT_RUNS_PER_TENANT` 默认 `2`，均为 `1..100`。Worker 启动时读取，变更需重启，不再读取后台 active runtime settings。用户槽、Worker 槽、Thread 单活跃和数据库短事务占槽边界不变；调低上限不取消在途 Run。
3. 五个 `THREAD_CONTEXT_COMPACTION_*` 数值参数是新 Run 的来源，总开关和执行路径继续由部署配置管理。首次建立 Session 时先解析该次 Run 模型能力，再将压缩输出预算裁剪到该模型的最大输出，将最终实际参数写入 `run_compaction_settings_snapshots`。
4. 独立压缩快照按 Tenant/Run 隔离，即使使用部署回退模型也会建立。恢复优先读取该快照；升级前已绑定后台 `runtime_settings_revision` 的 Run 首次迁入时继续继承旧值。此前没有持久化部署参数的旧 Run 无法重建历史值，只能在首次建立独立快照时采用当前部署值，不能伪造旧快照。
5. 部署回退模型本身尚未持久快照化。使用该模式的 Run 在途时，应先排空再切换为后台托管模型；否则恢复可能首次绑定新模型。恢复时执行输出预算再次按实际模型上限约束，不改写原快照，其他四项保持不变；这能避免旧预算超过新模型能力，但不等于固定部署模型。本决策不补造部署模型历史。
6. 迁移 `0061_run_compaction_settings_snapshots` 建立复合主键、外键和 FORCE RLS。Runtime 仅获 SELECT/INSERT，后台没有此表权限；已有快照时 down 拒绝删除。

### 技能上传后由管理员直接发布

1. 管理员上传包，经既有结构、路径、摘要和对象完整性校验后预览，再一次发布。管理员可直接发布 `draft`、`submitted` 或 `approved`；publisher/reviewer 仍不能发布，既有 submit/review 接口与历史审核事实保留兼容。
2. 页面不要求填写版本或选择推荐版本。省略版本时，服务端根据操作者和幂等键生成稳定的内部版本；显式版本仍兼容旧调用方。页面发布自动设为推荐，升级安装仍由用户显式选择，旧安装不自动追随推荐包。
3. 列表请求 `latestOnly=true`，服务端先按目录唯一身份 `canonicalKey` 选出最新申请，再执行游标分页；publisher 不参与分组，避免只隐藏版本文字却继续展示重复历史包。管理员通过“上传更新”创建替换包，更新锁定技能身份。最新待发布包不代表原已发布包被下架，历史目录和安装继续有效；详情保留“下架当前已发布内容”入口，该操作不发布或修改新上传。
4. 驳回或撤销的历史申请不原地复活。直接发布不创建虚假的审批证据：原 `approved` 申请保留审核者，直接从 `draft/submitted` 发布的申请保持 `reviewed_by=NULL`。发布不是恶意软件扫描或脚本行为验证，包仍受既有 Skill 和工具权限边界约束。
5. 撤销保留一次后果确认并自动保存审计，原因可省略。撤销的精确内容不能继续执行；撤销当前推荐版本时停止该技能的新安装。历史包、安装和 Run 引用不删除。
6. 迁移 `0060_skill_direct_publication` 只放宽 published/revoked 的审核者约束，approved/rejected 的证据约束保留。存在无审核者的 published/revoked 事实时 down 拒绝回退，不能为适配旧约束伪造审核人。

## 影响与验证

管理员的保存或发布成为完整动作，内部版本不再成为表单负担。代价是保存未经测试的外部服务配置可能影响后续新任务；管理员可使用模型列表的测试诊断并修正配置。需要暂存供应商配置的旧 API 调用方仍可使用兼容接口，但日常页面不保留待启用状态。

自动化验证覆盖原子保存的授权、幂等、CAS 与失败回滚；零值 generation、密钥复用、表单失败保留和记忆开关；运行参数 ENV 校验、固定模型能力裁剪、部署模型压缩快照及旧 Run 恢复；Skill 直发权限、历史审核证据、自动版本、最新申请分页及迁移回退保护。真实 PostgreSQL 与对象存储闭环属于集成验证，不能用静态页面或模拟测试替代。

## 可逆性

页面和旧兼容接口可分别回退，不能删除已有配置、审计、密钥、包或 Run 快照。回退到必须审核的旧发布代码前，需要评估新产生的无审核者发布记录；0060 down 在这类记录存在时失败关闭。0061 有压缩快照时也拒绝 down，应用回退应保留扩展 schema，不能把正在恢复的 Run 改用当下配置。恢复后台运行参数真源属于新的配置所有权选择，必须重新处理旧/新 Run 边界，不能仅恢复导航。
