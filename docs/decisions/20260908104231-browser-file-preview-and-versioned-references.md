# ADR-20260908104231：浏览器优先的文件预览与固定版本选区引用

- 状态：已接受
- 日期：2026-09-08
- 部分替代：[ADR-0053](0053-workspace-artifact-preview-media.md) 中 Web 仅使用纯文本弹窗和有限 inline 预览的范围；原 preview/download 安全策略仍有效。
- 当前说明：[文件预览与选区引用](../reference/file-preview.md)

## 背景与约束

用户需要直接查看 Agent 交付的办公文件，并用文字或区域准确表达修改要求。DOCX、XLSX、PPTX 与图片、PDF、文本共同进入首批；可在浏览器完成的解析、渲染和选区不引入服务端转换任务。大小屏共享同一引用协议和草稿，引用必须固定原文件版本。请求事实只能进入最新 user turn，已有 ResourceFS 和视觉附件链路继续承担原文件与截图读取。

## 备选

1. 服务端统一转 PDF：版式入口统一，但增加转换资源、缓存、字体和隔离运维，并损失 Excel 原始行列引用。
2. 直接嵌入浏览器或外部 Office 查看器：开发量较小，但选区回传、隐私边界和大小屏体验不可控。
3. 浏览器分类解析，API 仅负责有界原文件读取和引用授权：保留表格结构，减少后端计算，代价是浏览器内存与 Office 保真度限制。

## 决策与理由

采用方案 3。PDF.js、docx-preview、ExcelJS、PPTX Renderer 按精确版本集成；重型包按需加载，表格独立 Worker，Office 内容使用禁脚本和外部请求的 iframe。新增受控 octet-stream 内容入口，不扩大现有 inline 白名单。

引用使用共享协议中的源身份与选择器；服务端核对原 Artifact/Version、当前 Thread 归属和截图附件权限，自动补入原文件附件。引用事实序列化到最新用户输入中的版本化区段，复用现有持久历史和幂等机制，避免为一次性引用新建批注数据库与额外恢复链路。区段只代表用户提供的内容，不能提升为可信模型指令；页码和摘录不宣称经过服务端 Office 解析校验。

区域截图在用户发送时才上传，选择期间只保留标签页草稿。固定坐标使用原预览页面的归一化坐标，DOCX 同时记录布局尺寸；版本变化不迁移旧引用。OCR、音视频、HTML 元素引用和版本对比待规划。

## 影响与失败语义

- 后端仍有原文件字节读取与转发成本，但不执行文档转换。复核授权后才能返回字节。
- API 兼容已有客户端，旧 preview/download 保持安全白名单和失败策略；无需迁移数据库。
- Office 字体和排版可能不同，Excel 不重算公式，复杂格式明确降级；大文件、坏包或超时失败时保留下载。
- 区域 PNG 复用已有视觉附件输入；原文件、截图和普通附件共享数量预算。拒绝或提交失败不能丢失草稿。
- 新增浏览器依赖进入锁文件；ExcelJS 的 Node 依赖 UUID 固定到修复版 11.1.1。ExcelJS 预构建浏览器包只通过内部 v4 调用生成条件格式 ID，不对用户暴露受公告影响的 v3/v5/v6 buffer 接口。

## 验证与可逆性

验证权限漂移、版本错配、引用结构、原文件自动附件、草稿恢复和真实浏览器的文本层、框选及截图。浏览器夹具使用模拟 API，真实存储和实际模型理解仍需部署环境验收。

前端查看器与新读取入口可回退到原预览；已经持久化的引用区段必须继续作为用户文本保留。若改为独立批注表或跨版本重定位，需新增决策与兼容迁移，不能原地改写历史引用。
