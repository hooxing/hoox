# ResourceFS 受控快照的分块重试与有界并发写入

- 状态：已接受
- 相关：[后端管理 Sandbox 供应商配置与版本固定](20260910005916-managed-sandbox-routing.md)、[E2B Provider 首个 SDK 适配](0176-e2b-provider-first-sdk-adapter.md)

## 背景与选择

E2B 与腾讯云 AGS 不具备 CubeSandbox 的受控 Volume，Worker 需要把 ResourceFS 快照经 Provider 文件 API 写入 Sandbox。原实现按单文件串行写入，每个文件一次请求。

2026-09-10 的 Demo 实测暴露两个问题：一是逐文件串行使总时长等于文件数乘单次往返，127MB、172 个文件的快照在本机实测需要 99.5 秒；二是部署主机到 AGS 上海的数据面偶发停顿，单个 10MB 文件的写入停满 60 秒超时后，整轮准备失败、Sandbox 被回收。同一份快照在小文件路径正常，因此停顿只影响大请求。

采用有界并发写入，并把超过分块大小的文件在远端拆成多个分块请求写入，再用一条命令合并为最终路径；每个分块写入独立重试。分块把一次长请求拆成多个短请求，使链路停顿只影响一个分块，重试会新建连接而不必重传整个文件。

## 备选与理由

- 只调大超时：不改善总时长，且把失败时间从 60 秒放大到分钟级；停顿是连接失效而非单纯慢速。
- 只做并发：改善总时长，但单个大文件的停顿仍会让整轮准备失败。
- 改用更近的 Provider 地域：属于部署选择，不解决链路抖动，且不能覆盖用户既有模板与地域。
- 先做内容去重减少字节数：同一份内容在 history 与 Resource 版本中会重复出现，但去重会改变快照的文件语义与所有权，风险高于收益，本决策不采用。

## 影响

- 快照物化的墙钟时长随并发度下降，不再与文件数线性相关。
- 分块文件的最终路径仍由远端合并产生，校验仍按最终文件摘要执行，Sandbox 看不到分块中间产物。
- 失败语义不变：任一分块在重试耗尽后仍失败，整轮物化失败，staging 被清理，Sandbox 由既有路径回收。

## 验证与可逆性

单元测试覆盖分块合并、瞬时失败重试和重试耗尽后的失败关闭。真实 Provider 验证在同一份 127MB、172 文件快照上对比：AGS 由 99.5 秒降到 29.1 秒，E2B 写入总量 284.6 秒、墙钟 79.9 秒，两者摘要校验全部通过。

分块大小、重试次数、并发度与单次超时都是构造参数，可回退为串行单次写入而不改变持久化格式或公开接口。
