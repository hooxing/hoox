# ADR-20261003011415：PTC 模式与独立受控调用日志

- 状态：已接受（测试分支实验，不表示生产默认启用）
- 日期：2026-10-03
- 决策范围：运行配置、Pi 工具协议、受控副作用与 PostgreSQL 恢复边界
- 当前说明：[工具调用模式](../architecture/tool-calling-modes.md)

## 背景

正常工具调用将每次工具返回都放入模型上下文。PTC 允许模型在程序中循环、筛选和聚合工具数据，只返回必要结果，但也将多个副作用藏在一次模型工具调用内。Hoox 的 Rollout 只允许配对的 tool_call/tool_result，外部副作用必须在真实 started、双栅栏和 durable 开始之后执行。直接套用可自由运行 Python 或宿主 JavaScript 的编排器会扩大能力边界，直接嵌套 Rollout 则会破坏恢复协议。

既有正常模式、受控回执、Run 配置快照和未知副作用 reconciliation 结论继续有效；本决策增加实验模式，不替代这些边界。

## 备选方案

1. 维持正常模式：风险最小，但不能测量程序化聚合降低模型往返和中间数据上下文的效果。
2. 在 Sandbox 执行任意程序并直连服务：隔离可以依赖 Sandbox，却需要额外凭据和网络代理协议，会绕开现有逐次工具授权与回执。
3. 在宿主使用动态函数或 node:vm：实现简单，但不是可靠的能力隔离边界，拒绝。
4. 将内部工具插入模型 Rollout 或伪造成 assistant turn：复用存储结构，却破坏模型实际请求与持久事实一致性、配对和恢复语义，拒绝。
5. capability-only QuickJS WASM 配合独立 durable journal：增加执行器和迁移成本，但能复用每个真实工具的安全边界，并保持模型 Rollout 平坦。

## 决策与理由

采用方案 5。后台同一运行设置版本选择 native 或 ptc，默认 native，不提供 both。Worker 首次解析 Run 配置时固定模式，子 Agent、重试和恢复沿用快照。每次 PTC 运行使用 fresh VM，只有固定 SDK 和 tools broker，不注入请求级动态提示词。串行 broker 优先保护授权与副作用顺序，不引入未经验证的并行工具语义。

外层 run_code 保持原 Rollout 工具对。内部每次调用发布真实 started，独立持久开始后才进入原工具实现及授权，最后固定回执写入 runtime_ptc_dispatches。journal 完整绑定 Tenant/Run/Attempt/agentThread 与双栅栏，要求父调用是当前作用域未闭合 run_code；稳定 trace Blob、唯一键、RLS 和 FK 共同守住结果身份。相同正文 replay，不同正文 conflict，未知写入同键重试；无法确认事实时停止程序续行。

外层未闭合不自动重跑；journal 仅供核对。取消和超时阻止新调用，等待已启动调用收束后释放 VM，不宣称强杀外部操作或回滚副作用。

可选最终答复折叠工具依赖模型直接发出的独占 turn 标记，PTC 内不暴露该展示工具，避免把内部调用误判成模型事实。内部图片暂作为数据，不自动回传视觉输入；这两项限制必须在当前说明中明确。

## 影响

- 正面：可在不扩大宿主 IO 与工具权限的条件下试验程序化聚合，正常模式不变。
- 成本：增加 QuickJS 生产依赖、WASM 加载、独立迁移和核对接口；串行及 fresh VM 不支持共享状态或无限长程序。
- 安全与隐私：不保存程序和全部内部业务结果到 journal；程序主动打印或返回的数据仍进入模型。WASM 隔离不代替依赖审计和容器防护。
- 兼容：旧配置缺字段是 native，非法模式失败关闭，模式纳入工具 Schema/Prompt 能力身份与工厂缓存。migration 0066 是增量结构，不改写已执行迁移。
- 运维：保持默认正常模式。测试分支不覆盖正式 Demo，尚无真实模型性能、质量和多模态等价性结论。

## 验证

真实 WASM 测试覆盖宿主隔离、无损 JSON、同步/微任务循环中断、内存/调用/输出限额和取消收束。工具与 Session 测试覆盖 SDK 稳定、仅 run_code、started→durable→授权→副作用→receipt、非法参数失败及持久化未知不继续。PostgreSQL 集成测试覆盖父作用域、双栅栏、RLS/Blob/幂等约束和内部日志不污染 Rollout。后台和 Worker 测试覆盖旧默认、保存与模式缓存分离。真实模型与生产容器验证不能由这些测试替代。

## 可逆性

后台切回 native 只改变后续首次建立快照的 Run。已快照 PTC Run 在安全排空和核对前必须保留执行器与 journal；已有 journal 是审计事实，不能为代码回退删除数据。完全移除能力需要先排空在途 Run、保留只读核对层并另行制定数据迁移，不自动执行 down migration。
