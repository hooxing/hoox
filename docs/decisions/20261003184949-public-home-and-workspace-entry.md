# ADR-20261003184949：公开首页与工作台分离入口

- 状态：已接受
- 日期：2026-10-03
- 决策者：Hoox 维护者
- 替代：无
- 被替代：无

## 背景

根路径直接装载工作台和身份请求，无法同时作为无需登录的产品与开源介绍入口。公开首页需要展示真实能力和经授权的案例，并随现有 CI/CD 发布，不能增加另一套运维服务。

## 约束

- 首页不得读取用户会话或获取真实任务、账户信息和模型日志。
- 不改变 API、租户边界、身份存储键、任务所有权和数据库结构。
- 工作台登录回调、PWA 与开发启动入口需要指向明确的工作台路径。
- 保留既有静态服务、Nginx、构建和 CI 发布门禁。

## 备选方案

1. 根路径维持工作台，介绍页放在另一路径：兼容最简单，但公开域名不能直接呈现项目。
2. 根据登录状态自动切换根页面：老用户省一次点击，但首页因此依赖身份，并让同一链接含义不稳定。
3. 根路径公开首页，工作台使用 /app：访问意图明确，无新增基础设施，需要同步启动与登录入口。
4. 暂不实现：保留独立原型，但它不是受版本、测试和发布门禁管理的正式页面。

## 决策与理由

采用方案 3。公开首页与工作台按路径选择并分块装载，首页不装载工作台 App 或发起用户 API 请求。已有非根路径继续进入工作台，根路径带 error 的旧登录错误回调保留工作台入口。普通推广参数不改变首页选择。

首页案例使用现有对话与交付组件，仅保留经授权的公开名称和人工编辑摘要；展示标识为固定常量，不复制生产记录。只读交付卡片不提供私有文件操作，工作台默认操作不变。

## 影响

- 根路径从工作台改为介绍页；原来收藏根路径的用户需点击工作台入口。
- 同源身份和草稿继续复用，无数据迁移。进行中的旧 OAuth 成功回调若返回根路径，会先到首页，随后可进入工作台恢复身份；旧错误回调仍可显示错误。
- PWA 和本地启动脚本直接进入 /app，新 OAuth 回调沿用当前工作台 URL。
- 同一镜像包含首页与工作台；既有 SPA 回退和发布检查继续适用，无新的环境变量或依赖。
- 公开首页给出 Apache-2.0、0.x 成熟度、部署依赖和 Skills 权限边界，不承诺无条件生产就绪。

## 验证

路由测试覆盖根路径、推广参数、工作台与旧错误回调；组件测试证明首页不发起 API 请求、公开案例没有账户信息、只读卡片不暴露操作且默认下载行为不变；静态服务测试覆盖 /app 与根路径回退。执行 Web typecheck、构建、受影响测试、格式与 lint，并人工检查桌面和移动布局。

## 可逆性

入口调整不产生数据变更。可恢复根路径工作台，同时保留 /app 兼容入口；同步恢复标题和开发入口即可。PWA 的既有 /app 链接应继续支持，无需清除身份或任务数据。
