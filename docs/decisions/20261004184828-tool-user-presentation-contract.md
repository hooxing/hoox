# ADR-20261004184828：工具设计同时交付模型结果与用户展示契约

- 状态：已接受
- 日期：2026-10-04
- 决策者：Hoox 维护者
- 替代：无
- 被替代：无
- 关联：补充 [PTC 模式与独立受控调用日志](20261003011415-ptc-mode-and-durable-dispatch-journal.md)；当前行为见[工具调用模式](../architecture/tool-calling-modes.md)。

## 背景

PTC 工具链实测及工作台截图显示，内部调用虽然保留生命周期事件，但缺少正常模式已有的用途和对象摘要，用户只能看到“已完成”“已执行命令”等状态。宿主工具错误统一降为通用 PTC 错误后，模型和用户也难以区分参数问题、文件不存在与基础设施失败。

这是跨执行模式、事件协议及前端组件的长期边界：模型能读取工具结果不代表用户能理解执行过程。仅修补某个页面，无法约束后续新增工具。需要明确工具设计同时拥有模型消费和用户展示两个出口，而不把业务结果或宿主诊断直接复制到界面。

## 约束

- 安全与租户边界：展示不能引入额外文件访问或执行权限，不公开源码、完整命令、消息正文、工具输出、凭据、异常栈和底层诊断。
- 数据与迁移：基于真实调用事件，展示不影响授权、受控回执及 durable journal；不修改历史 migration，不回填旧事件。
- 兼容性：正常与 PTC 使用相同投影和组件；新字段可选，旧事件继续采用通用状态。
- 运维与故障恢复：失败不保证副作用未发生，不宣称安全自动重试。内部持久化未知仍必须阻断续行。
- 性能与成本：摘要和错误解析有界；UI 事件不逐次注入模型 Rollout，不破坏固定提示词与 Schema 的缓存稳定性。

## 备选方案

### 方案 A：服务端受限结构化投影，前端只负责呈现

共享工具边界生成 `presentation` 与安全 `failure`。工具实现和模型结果保留原职责，正常与 PTC 共用展示逻辑。优点是语义、隐私和兼容性可以逐层测试；代价是新增工具必须维护展示映射及错误码白名单。

### 方案 B：前端从完整参数、程序或输出推断摘要

可以快速增加信息量，但会扩散敏感数据、重复工具知识，且无法可靠判断程序的真实子调用和副作用。客户端猜测错误还会形成误导性审计信息。

### 方案 C：仅要求模型在正文解释工具行为

实现简单，但说明依赖模型是否遵循指令，不能稳定覆盖运行中状态和失败；PTC 中间数据还可能被迫重新进入模型上下文，抵消其目标收益。

### 暂不实现

继续保留低信息量状态，会使工具失败难以定位，也让每个新增工具重复承担界面设计成本。截图和实测已经表明这不是适合长期保留的默认状态。

## 决策

采用方案 A。每个新增或修改的工具都必须同时评估：

1. **模型出口**：参数、结果、失败、副作用、取消与持久性语义。
2. **用户出口**：开始和运行中说明正在做什么，终态说明完成或失败；在安全范围内提供用途或操作对象。不能以“模型有结果”为由省略界面契约。
3. **失败信息**：只将受控错误码映射为固定提示，未知错误通用降级；禁止拼接任意底层异常。失败提示不能把再次调用等同于安全恢复。
4. **执行模式一致性**：真实子调用拥有独立展示，正常与 PTC 不重复实现参数推断。外层 `run_code` 成功仅代表程序完成，不抹除已捕获的内部失败。
5. **贡献验收**：Schema、用途字段或工具名称变化时，同步更新共享展示映射、错误投影、事件与前端测试，覆盖缺字段、历史事件、失败和重放。缺少安全摘要的未知工具不得编造对象或用途。

当前共享投影由 `pi-adapter` 维护，Web 消费显式字段，不解析原始参数或输出。文件工具展示受限路径，命令工具只展示 `user_facing_purpose`，程序工具展示“编排工具调用”，协作和定时任务展示受控操作名称。后续外部工具接入也须遵守该原则，但不借此 ADR 宣称 MCP 已实现或新增其权限。

动态用途、路径及错误只属于调用参数、结果或展示事件，不进入固定 system/developer prompt 或工具 Schema。

## 理由

真实调用已经提供生命周期事实，共用白名单投影能以最小协议扩展对齐两种模式，同时保持 PTC 中间数据不自动进入模型历史的边界。固定错误码比通用失败更可操作，又避免“为了诊断直接透出宿主异常”的安全退让。

## 影响

### 正面影响

- 用户可以辨认命令用途、文件对象与协作操作，正常和 PTC 展示一致。
- 模型可以在程序内读取安全错误码并决定后续处理，而不是盲目重试。
- 工具贡献的完成标准包含界面信息质量，避免新工具重新退化为通用状态。

### 负面影响

- 展示映射和错误白名单需要随工具契约维护；未知错误仍无法提供完整根因。
- 仅提供受限摘要，不提供完整执行日志或结果预览；需要后续专门设计的能力不能靠扩展字符串绕过边界。

### 安全与隐私

投影只选择明确允许字段，并限制长度。错误只解析有界的真实 Error 自有消息数据字段，不执行访问器或序列化钩子，不透传其正文。允许展示的用途和文件名仍需调用方避免包含秘密；受限投影不是任意字符串的自动脱敏器。

### 数据、兼容与迁移

`presentation` 与 `failure` 是可选字段，旧事件缺字段时仍可展示；无需 migration、历史回填或模型结果结构变更。

### 运维与可观测性

界面错误码支持复测归类，不替代内部受控审计。Todo 偶发失败和子智能体启动 readiness 仍需独立定位；不得因用户可见诊断改善而宣称其根因已修复。

## 验证

- 共享投影测试覆盖用途、对象、未知工具、缺字段、长度和禁止公开的正文。
- 真实 PTC VM 测试覆盖子调用摘要、安全错误捕获、命令非零退出返回及内部失败不被外层成功抹除。
- 错误桥测试覆盖白名单、未知异常、访问器、秘密字段及宿主边界。
- 前端测试覆盖两种模式、历史事件兼容、纯文本错误呈现及增量与重放一致性。
- CI 工程与容器门禁通过后，在 Demo 进行只读烟测，检查用途、文件对象和失败原因展示及刷新后的持久一致性。

## 可逆性

可以回退展示投影、SDK 说明及前端附加信息，已有可选事件字段允许旧前端忽略；不需要撤销数据迁移。不应为 UI 回退删除已有 journal、重跑程序或重试已发生的副作用。长期验收原则若被替代，需新增 ADR 说明新的边界。
