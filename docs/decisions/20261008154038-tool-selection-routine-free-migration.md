# ADR-20261008154038：工具选择约束保持无 routine 的迁移终态

- 状态：已接受
- 日期：2026-10-08
- 当前说明：[工具调用模式](../architecture/tool-calling-modes.md)
- 关系：补充[后台工具选择与 Run 快照边界](20261008150709-admin-tool-selection-and-run-snapshot.md)的数据库实现与降级边界，不改变工具选择语义。

## 背景

0068 使用 SQL 函数解决 CHECK 不能包含子查询的问题，但迁移入口的安全 manifest 禁止目标 Schema 存在 routine。CI 的整批迁移最终检查因此拒绝提交。0068 已提交，必须保留文件和 checksum；不能修改迁移记录或放宽角色安全边界。

## 备选与选择

1. 修改 0068：违反已提交迁移不可变约束，拒绝。
2. 允许辅助函数作为 manifest 例外：扩大安全维护边界，没有必要，拒绝。
3. 新增 0069 内联 CHECK：采用。CASE 拒绝非数组；删除所有已知字符串后的数组必须为空，拒绝未知与非字符串；数组长度必须等于已出现的不同已知名称数量，拒绝重复。空数组有效。

0069 先替换约束再删除旧函数，不改写配置 Revision。迁移入口在同一事务执行全部 pending migration，提交前检查 routine 和 ACL，0068 的函数只作为事务内中间态存在。

## 影响、验证与可逆性

0069 down 恢复 0068 的事务内中间态，随后 0068 down 沿用历史字段保护并删除函数。无工具选择历史时，可以整批回退至 0067 或更早；若存在含 `enabledTools` 的历史 Revision，原有保护拒绝降级并整体回滚。仅回退至 0068 会被迁移入口的安全检查拒绝，约束、函数与迁移记录均恢复到回退前状态。运维不得绕过迁移入口直接执行 down 并提交。

测试冻结 0068 文件及 checksum，比较内联替换之外的完整约束，校验共享目录一致；真实 PostgreSQL 测试覆盖合法与非法 JSON、空名单、历史字段降级保护、事务回滚、整批迁移无 routine、禁止停在 0068 和无数据降级后重建。迁移缺陷修复不改变业务工具开关、Run 快照或代码回滚所需的字段兼容要求。
