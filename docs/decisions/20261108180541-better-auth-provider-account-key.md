# ADR-20261108180541：Better Auth 升级保留历史 issuer 并约束 Provider 账号键

- 状态：已接受
- 日期：2026-11-08
- 部分替代：[内嵌 Better Auth 身份核心](20260824115000-embedded-better-auth-identity-core.md)的固定版本；共进程身份边界、秘密管理和 Provider 范围继续有效。
- 当前说明：[身份、账号与会话](../architecture/identity-and-session.md)

## 背景与约束

生产依赖审计要求升级 Better Auth。固定的 `1.7.7` 不再写入 `issuer`，而已执行的 `0055` 迁移来自 `1.7.1`，要求该列非空并以 `(issuer, account_id)` 唯一定位账号。新版运行时结构校验因此在注册和登录前拒绝数据库。内存 Adapter 验证无法发现这个 PostgreSQL 兼容问题。

上游[1.7 升级说明](https://www.better-auth.com/docs/guides/1-7-upgrade-guide)明确从 `1.7.3` 恢复 `(providerId, accountId)` 账号键。已有迁移不可重写，身份和凭据不可删除、伪造来源或自动合并，RLS 和登录验证必须保留。

## 备选方案

1. 追加向前迁移，保留历史 `issuer` 值、解除非空要求，替换唯一约束，并在冲突时失败关闭。
2. 删除 `issuer` 列：可满足新版结构，但永久丢失历史来源，收窄审计与回退空间。
3. 关闭新版结构校验：既掩盖漂移，也不能解决新增账号不写 `issuer` 导致的插入失败。
4. 暂不升级或退回 `1.7.1`：仍保留已知依赖漏洞，不满足发布审计。

## 决策与理由

采用方案 1，新增 `0070`。迁移先检查重复 `(provider_id, account_id)`；存在重复即中止整批事务，错误不输出身份值。随后仅解除 `issuer` 非空要求，移除旧唯一约束，建立 Provider 账号键唯一约束。新约束同时防止并发重复身份写入。保留所有既有 User、Account、密码、Session 和非空 `issuer` 值，不执行数据重写。

新版结构校验保持启用。Hoox Session 交换、邮箱验证、账号映射和最小数据库权限保持原有职责。

## 影响与失败语义

新账号的 `issuer` 可以为空。重复 Provider 账号键必须先由维护者按身份来源处理，迁移不会自动选择或合并用户。唯一约束需要短暂表锁；迁移失败会由现有发布流程恢复上一应用版本，数据库迁移仍只向前执行。

## 验证

M4 真实 PostgreSQL Gate 使用受限 Runtime 连接验证：保留带历史 `issuer` 的密码账号并成功登录；新版注册、密码登录、Cookie 会话查询成功；重复 Provider 账号键升级失败；存在空 `issuer` 的降级失败。测试清理身份夹具，历史约束重建只在最终回滚的事务内发生。

## 可逆性

尚无空 `issuer` 且旧 `(issuer, account_id)` 没有冲突时，显式测试降级可恢复旧约束。写入不兼容旧键的新账号后，`down` 失败关闭；禁止补造 `issuer`、删除账号或改写迁移记录来强行回退。回退应用版本前必须确认其仍能识别已写入的账号键，不能把镜像回退当作身份数据降级。
