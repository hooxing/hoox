# ADR-20261115122045：首次运行创建管理员与延后模型配置

- 状态：已接受
- 日期：2026-11-15
- 部分替代：[独立控制面](20260819165254-independent-admin-control-plane.md)中所有初始授权仅经数据库运维的结论、[统一管理 API](20260821115221-unified-admin-api-process.md)的浏览器固定开发 Token 前置，以及[身份交换](20260824125500-embedded-identity-session-exchange-and-admin-configuration.md)中按邮箱自动绑定已有本地账号的结论。独立数据库角色、领域授权、会话交换和配置快照继续有效。

## 背景与备选

空安装没有管理员，部署者需要人工操作数据库才能进入后台；Worker 又要求先填入模型秘密，后台配置无法完成启动闭环。

备选包括：通过环境变量预置管理员密码和模型；由安装 CLI 创建账号；通过首次页面创建管理员并复用线上模型编辑器。前两者能解决无人值守安装，但仍让浏览器配置依赖额外手工步骤。公开无授权的网页初始化存在被抢先占用的风险；直接依赖第三方身份登录又会先要求配置身份供应商。

## 决策

采用首次页面与一次性数据库状态。API 使用既有 scrypt 本地账号和 Hoox Session，在锁定唯一安装状态的同一事务中创建账号、个人租户、会话、控制面和 Skill 管理授权。已有管理员包括禁用状态均关闭入口。Runtime 只能从空状态设定当前自身为管理员，不能重置安装记录、删除记录或授权其他用户。迁移后的运维授权仍受信任，必须先获取相同状态行锁；聚合安全视图只公开是否已存在管理员，避免向 Runtime 开放跨用户授权列表。

生产与代理后的初始化需要至少 32 字节的部署安装令牌。开发无令牌只开放字面回环 Host/Origin、直接回环 socket 且无转发标记的访问。安装和本地管理员登录均限速；安装成功永久关闭创建入口，不能靠重启重新提权。已有本地密码账号不能凭邮箱匹配绑定新 Better Auth 身份，避免同邮箱注册接管管理员。

后台和工作台使用同源 Hoox Session；管理 API 向固定主 API 校验会话与有效管理身份，再按既有领域角色授权。身份校验有超时、正文上限且禁止重定向，失败不降级到开发 Token。退出调用主 API 撤销会话。既有 viewer、operator 和 Skill 管理身份仍可进入相应领域。

部署模型参数可全部省略；平台加密根、数据库、S3 与 Sandbox 等基础秘密仍由部署准备。Worker 无模型时持续运行、报告模型未就绪且不领取任务，配置读取失败也不领取；后台模型可用后自动恢复。模型能力仍来自受信配置与 Run 快照，不能使用占位能力执行任务。开发连接测试发送受限 chat/completions，不再依赖非标准的 /models 能力元数据。

## 影响、验证与可逆性

增加安装状态表、安全聚合视图及 Runtime 的受限初始化权限，不引入 SECURITY DEFINER routine。普通用户注册不获得初始化权限。主 API 成为管理会话验证的在线依赖，故障时失败关闭。首次管理员保留本地密码入口，不受后续第三方身份配置关闭影响；显式账号关联尚未实现。

验证覆盖并发安装、事务回滚、重复创建、Runtime 越权、同邮箱接管拒绝、会话校验、页面登录和 Worker 等待后恢复。实际运行还需验证空数据库迁移与本地服务启动。当前配置契约归[配置参考](../reference/configuration.md)，账号语义归[身份与会话](../architecture/identity-and-session.md)。

未初始化时可回退新增迁移；已初始化后安装状态迁移拒绝 down，必须向前修复。回退应用前须保留管理员账号、授权与加密根，不删除安装状态重新开放入口。旧部署回退模型与开发 Token 仍可显式配置，便于渐进升级。
