## 1. 生命周期与权威边界

本文定义尚未实现的 UI 重构目标、实施顺序、资产生产约束和验收门槛，不描述当前界面已经具备的行为。当前品牌文件、构建路径和组件引用仍以品牌资产参考、既有 ADR、代码与测试为准。

本计划已于 2026-09-01 进入“进行中”，依据如下：

1. 维护者授权以本文和现有四枚 PNG 为依据开始重构，既有 Logo 图形不变量继续有效；
2. 共享 UI Token、主题映射和跨 Web/Admin 的所有权边界已由实施 ADR 接受；
3. 首个切片限定为品牌衍生资产契约、共享 Light Token 与 Web 应用外壳，测试与回滚路径见本文验收和实施 ADR。

全部切片实现并验证后，稳定的品牌资产规则迁入品牌参考，稳定的 UI Token 与组件规则迁入新的当前参考；本文转为“已完成”并退出活动计划索引。若后续方案替换颜色、组件体系或资产真源，本文标记为“已替代”并链接替代入口。

## 2. 目标结果

Hoox 以现有黑绿 Logo 为品牌原点，形成一套可复用、可测试、可在 Web 与 Admin Web 共享的 UI 系统：

- 纸白 `#FAF9F8` 承担页面画布；
- 碳黑 `#19191A` 承担主文字与品牌字标；
- 翡翠绿 `#177654` 承担品牌、主要操作和当前状态；
- 组件引用语义 Token，不在功能样式中持续新增相近灰色和灰绿色；
- 工作台优先保证对话、运行状态和主要操作的视觉层级；
- 管理台共享品牌基础，但使用更高的信息密度；
- 品牌资产在横版、独立标志、App 图标、透明背景、反白和小尺寸场景中具有明确真源与生成关系；
- 普通文字、功能边框、键盘焦点和状态表达满足无障碍门槛。

## 3. 不做事项

本计划不改变：

- API、数据库、身份、Thread、Run、Artifact、Skill、Automation 或团队领域语义；
- Web 与 Admin Web 的路由和部署路径；
- 当前四个公开 PNG 文件名，除非后续 ADR 同时定义兼容路径；
- Logo 的双钩负空间 `H`、相向开口 `O` 和断笔 `X` 图形关系；
- 第三方 Vendor、Trajectory Web 或非产品调试页面的完整视觉重写；
- 未经几何复核的自动描摹 SVG；
- 仅为了视觉统一而把成功、警告、错误都改成品牌绿色。

## 4. 现有品牌资源审计

### 4.1 当前资产

`runtime-ts/public/brand/` 当前包含：

| 文件 | 尺寸 | 像素模式 | 背景 | 当前用途 |
| --- | --- | --- | --- | --- |
| `hoox-primary-horizontal.png` | 1916 × 821 | RGB，无 Alpha | 暖白 | README 与浅色横版 |
| `hoox-symbol.png` | 1254 × 1254 | RGB，无 Alpha | 暖白 | 独立黑绿标志 |
| `hoox-app-icon.png` | 1254 × 1254 | RGB，无 Alpha | 深色 | favicon、侧栏与账号入口 |
| `hoox-reversed-horizontal.png` | 1925 × 817 | RGB，无 Alpha | 深色 | 深色横版 |

审计结果表明，现有四个 PNG 都是完整背景合成图，不存在透明像素。主横版背景接近 `#FAF9F8`，独立标志背景接近同一暖白；App 图标和反白横版使用深色背景。现有资源足以确认构图、比例、颜色和图形不变量，但不能直接承担所有透明背景和无损缩放场景。

### 4.2 可以从现有资源生产的资产

以下资产可由现有 PNG 作为输入生产，但生成结果属于栅格衍生物，不是矢量真源：

| 目标资产 | 可行性 | 生产约束 |
| --- | --- | --- |
| 透明背景独立标志 PNG | 可行 | 从暖白底建立 Alpha mask，并执行边缘去白与去污染复核 |
| 透明背景横版 PNG | 可行 | 必须同时处理黑色字标、绿色图形和抗锯齿边缘，不允许简单把单一色值设为透明 |
| 16/32/48px favicon PNG | 可行 | 从 App 图标按目标尺寸单独锐化，不能只由浏览器实时缩放 1254px 原图 |
| 180px Apple Touch Icon | 可行 | 保留深色底与安全区，验证 iOS 圆角裁切后的轮廓 |
| 192/512px PWA 图标 | 可行 | 从 App 图标生成固定尺寸，并验证 maskable 安全区 |
| Open Graph 横版图 | 可行 | 使用完整横版和固定纸白画布生成，不作为界面 Logo 引用 |
| 纯黑/纯白栅格版本 | 可行 | 依据现有轮廓生成单色 mask，必须复核负空间和 `X` 断笔 |

透明化不能采用“把 `#FAF9F8` 全部删除”的简单色键方案。现有 PNG 的抗锯齿像素已经与背景混合，直接色键会在深色背景产生白边；生产过程必须包含 Alpha 估算、边缘去污染、在纸白/纯白/深色/品牌绿四种底色上的像素级检查。

### 4.3 不能直接从现有资源宣称完成的资产

正式 SVG 不能通过自动描摹直接生成并设为品牌真源，原因包括：

- 自动描摹会把抗锯齿和轻微纹理转换成大量无意义节点；
- 双钩的线宽、圆角和对角咬合需要可测量的几何关系；
- 两个 `O` 的开口方向和宽度必须一致；
- `X` 的上层连续笔画与下层真实断笔不能退化为白色覆盖线；
- 自动追踪结果在 16–32px 下可能出现轮廓粘连或断裂。

正式矢量资产应采用以下方式之一：

1. 从 Logo 原始设计文件导出 SVG、PDF 或 AI 矢量真源；
2. 在没有原始矢量时，以现有 PNG 为参考手工重建路径，并由品牌方进行几何复核。

在正式矢量真源被接受前，现有四个 PNG 继续承担既有静态接口，不得被自动追踪结果替换。

## 5. 设计原则

本计划采用 Refactoring UI 的系统化方法，而不是复制其示例蓝色：

1. 先确定可用于真实按钮的主色基准，再建立完整色阶；
2. 灰阶承担绝大多数界面，品牌色只强调品牌、主要操作与当前状态；
3. 通过降低次要内容的颜色与权重建立层级，不依赖无限放大主内容；
4. 固定颜色、间距、字号、圆角、阴影和透明度刻度，禁止组件临时目测；
5. 组件引用 `surface`、`text`、`action`、`border`、`status` 等语义角色，不直接引用原始色值；
6. 深色文字配浅色状态背景是标签和提示的默认处理，实体彩色背景保留给主要操作；
7. 控件边框与装饰分隔线使用不同 Token；
8. 暗色模式重新映射语义角色，不机械反转明暗色阶；
9. 颜色不能作为唯一状态信号，必须配合图标、文案或形状。

目标颜色占比为：中性色 85%–90%，品牌绿 7%–12%，语义状态色不超过 3%。

## 6. 颜色系统

### 6.1 品牌绿色阶

`#177654` 作为 `green-500`，用于主要按钮背景；纸白文字放在该颜色上满足普通文字 AA 对比度。

| Token | 色值 | 用途 |
| --- | --- | --- |
| `green-100` | `#EFFAF5` | 极浅品牌背景 |
| `green-200` | `#D9F2E6` | 选中项和标签背景 |
| `green-300` | `#A9DEC2` | 焦点光晕和装饰 |
| `green-400` | `#45AA7F` | 深色模式品牌色和图表 |
| `green-500` | `#177654` | Logo、主要按钮和主要链接 |
| `green-600` | `#146A4B` | Hover |
| `green-700` | `#115C41` | Active 和深色链接 |
| `green-800` | `#0E4A35` | 浅绿背景上的文字 |
| `green-900` | `#093426` | 最深品牌文字 |

代码中的原始色阶应使用 HSL 表达并固定值，不在运行期调用 `lighten()`、`darken()` 或无约束的 `color-mix()` 生成新色。

### 6.2 暖中性色阶

| Token | 色值 | 用途 |
| --- | --- | --- |
| `neutral-100` | `#FAF9F8` | 页面画布 |
| `neutral-200` | `#F2F0EE` | 侧栏和下沉区域 |
| `neutral-300` | `#E4E1DE` | 装饰分隔线 |
| `neutral-400` | `#C8C4BF` | 禁用边框 |
| `neutral-500` | `#96918B` | 功能性边框 |
| `neutral-600` | `#716D69` | 三级文字 |
| `neutral-700` | `#54514F` | 次级文字 |
| `neutral-800` | `#343332` | 强调文字 |
| `neutral-900` | `#19191A` | 主文字、标题和字标 |

`neutral-300` 只用于装饰分隔线；输入框、复选框等依靠轮廓识别的控件必须使用满足 3:1 非文本对比度的功能边框。

### 6.3 语义状态色

| 状态 | 实体色 | 浅背景 | 深文字 |
| --- | --- | --- | --- |
| 信息 | `#2563C9` | `#EAF2FF` | `#17478F` |
| 成功 | `#21855B` | `#E8F6EE` | `#155C3E` |
| 警告 | `#9A6700` | `#FFF4D6` | `#684600` |
| 错误 | `#B42318` | `#FDECEA` | `#821B13` |

品牌绿与成功色接近，因此运行完成状态必须显示勾选图标和明确文案，不能只依赖色相差异。

### 6.4 语义映射

首个 Token 切片至少定义：

```css
:root {
  --surface-page: var(--neutral-100);
  --surface-sidebar: var(--neutral-200);
  --surface-raised: #fff;
  --surface-sunken: var(--neutral-200);
  --surface-overlay: #fff;

  --text-primary: var(--neutral-900);
  --text-secondary: var(--neutral-700);
  --text-tertiary: var(--neutral-600);
  --text-disabled: var(--neutral-500);
  --text-on-brand: var(--neutral-100);

  --border-subtle: var(--neutral-300);
  --border-default: var(--neutral-400);
  --border-strong: var(--neutral-500);

  --action-primary: var(--green-500);
  --action-primary-hover: var(--green-600);
  --action-primary-active: var(--green-700);
  --action-primary-text: var(--neutral-100);
  --action-subtle: var(--green-200);
  --action-subtle-text: var(--green-800);

  --focus-color: var(--green-500);
  --focus-ring: rgb(23 118 84 / 22%);
}
```

功能组件不得直接引用 `green-500` 或 `neutral-700`；组件应引用语义角色，原始色阶只允许在主题映射层出现。

## 7. 字体、间距与表面系统

### 7.1 字体

通用字体栈：

```css
Inter, "PingFang SC", "Microsoft YaHei", ui-sans-serif, system-ui, sans-serif
```

主要使用 400 与 600 两档字重；Logo 字形只存在于品牌资产中，不作为 UI 字体。

| 角色 | 字号/行高 | 字重 |
| --- | --- | --- |
| 登录页展示标题 | 28/38px | 600 |
| 页面标题 | 20/28px | 600 |
| 区域标题 | 16/24px | 600 |
| 对话正文 | 15/24px | 400 |
| 普通 UI 正文 | 14/22px | 400 |
| 按钮和导航 | 13/20px | 600 |
| 辅助文字 | 12/18px | 400 |
| 微型标签 | 11/16px | 600 |

### 7.2 间距

仅使用 `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px`。不同内容组之间的距离必须大于组内元素距离；页面不能通过给每个元素增加边框代替分组。

### 7.3 圆角

| Token | 值 | 用途 |
| --- | --- | --- |
| `radius-sm` | 6px | 标签、小按钮 |
| `radius-md` | 10px | 输入框、普通按钮、导航项 |
| `radius-lg` | 14px | 卡片、Composer |
| `radius-xl` | 18px | 对话框 |
| `radius-full` | 9999px | 头像和状态点 |

普通按钮不默认使用胶囊形；不能在同一界面继续出现 7、8、9、10、11、12px 等临时圆角。

### 7.4 阴影

只保留按钮、菜单/浮层、对话框三档阴影。已有明显表面明度差异的区域不再同时叠加重边框和重阴影。

## 8. 应用框架目标

### 8.1 Web 工作台

- 桌面侧栏宽度由当前 300px 收敛到 272px；
- 页面背景使用纸白，侧栏使用 `neutral-200`，二者之间只保留轻分隔；
- 顶栏高度固定为 56px，仅显示任务标题、状态和必要操作；
- 对话正文最大宽度 840px，Markdown 长文不能铺满大屏；
- Composer 与正文等宽，使用白色抬升表面、功能边框和轻阴影；
- 发送按钮使用品牌绿实体样式，禁用态使用明确 Token，不对整个按钮简单降低透明度；
- 侧栏小尺寸使用 App 图标或通过复核的独立透明标志，不压缩横版 Logo；
- 非活动导航使用中性色，活动项使用浅绿背景和深绿文字；
- 错误、重试和恢复状态靠近其影响范围展示，不默认占据整个页面顶部。

### 8.2 对话与运行状态

- 用户消息使用轻中性背景，Assistant 正文直接呈现在页面画布；
- 工具调用与运行事件默认折叠为紧凑时间线，不为每条事件创建重边框卡片；
- 运行中、成功、警告、失败同时显示图标、文案和颜色；
- 代码、日志和结构化数据使用等宽字体，但不改变普通正文的字体栈；
- 附件、Artifact 与历史文件保持现有领域语义，只重构视觉层级；
- 长内容限定阅读宽度，表格、代码和 Artifact 预览可以按需要突破正文宽度。

### 8.3 登录与账号入口

- 登录页使用完整横版 Logo；
- 页面使用纸白画布，不使用大面积彩色渐变；
- 表单卡片宽度约 420px，主要提交按钮使用品牌绿；
- 社交登录、密码登录、开发账户和辅助说明分层展示；
- 开发入口必须视觉降级，不与生产登录主操作竞争。

### 8.4 技能、定时任务、云盘与设置

- 技能中心采用分类/筛选与技能列表的主从结构；
- 定时任务采用列表或表格，创建表单进入抽屉或独立表单，不长期占据列表顶部；
- 云盘桌面端采用表格、移动端采用列表；
- 个性化、团队、成员和权限分区展示，危险区域位于末尾；
- 删除与解散操作在普通列表中使用次级样式，进入确认对话框后才使用红色实体按钮。

### 8.5 Admin Web

Admin Web 与 Web 共享颜色、字体、间距、圆角、阴影和状态 Token，但采用更高密度的表格与表单：

- 列表行高 40–44px；
- UI 正文 13–14px；
- 优先使用表格、分区和内联状态，减少独立卡片；
- 不建立另一套蓝色、紫色或纯黑管理主题；
- 现有 Ant Design 外壳的组件覆盖必须从共享语义 Token 派生，不能维护第二套颜色真源。

## 9. 响应式与暗色模式

### 9.1 响应式

- `>=1280px`：272px 侧栏，正文最大 840px，管理页最大 1200px；
- `768–1279px`：侧栏缩至约 240px，复杂页面允许折叠次级面板；
- `<768px`：侧栏改为抽屉，对话框接近全屏，表格转列表；
- `320–390px`：主要操作仍可见，不通过仅隐藏文案保留无意义图标；
- 点击目标至少 40×40px；
- Composer 处理移动端安全区域和软键盘。

### 9.2 暗色模式

暗色模式在浅色语义体系稳定后实施，不交换 `100` 与 `900`：

- 页面不使用纯黑；
- 抬升表面比页面稍亮；
- 品牌操作使用更亮的绿色和深色文字；
- 正文不使用纯白；
- 阴影权重降低，通过明度与功能边框表达层级；
- 反白横版和单色标志按背景选择，不对浅色 Logo 应用 CSS 滤镜模拟反白。

## 10. 代码结构与所有权

### 10.1 共享 UI 基础

实施 ADR 应在以下两种方式中选定一种：

1. 新建 `runtime-ts/packages/ui-theme`，向 Web 与 Admin Web 导出主题 CSS；
2. 保持应用内样式，但由生成脚本从一个 Token 真源生成两端主题文件。

不得手工复制两套同名 Token。共享层只拥有原始色阶、语义映射、字体、间距、圆角、阴影和动效，不拥有业务组件与领域状态机。

### 10.2 Web 样式拆分目标

当前单一 `runtime-ts/apps/web/src/styles.css` 应按职责拆分为基础 Token、全局排版、应用外壳、工作区、表单、浮层和响应式样式。功能组件可以保留局部样式，但不得重新定义主题色阶。

### 10.3 品牌资产所有权

- `runtime-ts/public/brand/` 继续作为正式运行期品牌资产真源；
- 资产生成脚本、临时蒙版和设计中间文件放在 `scripts/` 或仓库外设计源位置，不进入运行期目录；
- 若引入矢量真源，必须在品牌参考中明确哪些文件是手工维护真源、哪些文件是生成衍生物；
- 生成脚本必须固定输入、输出尺寸、颜色空间和压缩参数，保证可复现；
- Web 与 Admin Web 不得各自裁切或派生 Logo。

## 11. 实施切片

### 切片 0：品牌资产生产契约

- 获取原始矢量设计文件，或手工重建并复核 SVG；
- 确定透明、单色、favicon、PWA 和 maskable 版本；
- 增加资产生成脚本和 Alpha/尺寸/安全区测试；
- 更新品牌参考与 ADR；
- 保持当前四个 PNG 路径兼容。

### 切片 1：共享 Token 与静态约束

- 接受共享 UI Token ADR；
- 建立颜色、字体、间距、圆角、阴影与动效 Token；
- 建立 Light 语义映射；
- 增加检查，禁止 Token 文件外新增颜色字面量；
- 不在该切片同时重写全部页面。

### 切片 2：Web 应用外壳

- 替换侧栏、顶栏、导航、账号入口和通用按钮；
- 接入正式小尺寸 Logo；
- 保持现有导航、账号和团队行为；
- 完成桌面、平板与移动端外壳测试。

### 切片 3：对话工作区

- 重构空状态、消息排版、Markdown、工具时间线、附件和 Composer；

- 为运行状态、错误和恢复状态补充视觉与键盘测试。

### 切片 4：功能中心

- 依次迁移技能中心、定时任务、云盘、个性化和团队管理；
- 每个功能在迁移时清理其旧颜色字面量；

### 切片 5：账号入口与 Admin Web

- 重构登录注册表面；

### 切片 6：暗色模式与收口

- 建立 Dark 语义映射；
- 接入反白与单色 Logo；
- 清理遗留颜色、圆角和阴影；
- 将稳定规则迁入当前参考；
- 完成计划并移出活动索引。

## 12. 失败语义与回滚

- 品牌资源生成失败时，构建必须继续使用当前已验证的四个 PNG，不得发布缺少 Logo 的产物；
- 透明化出现白边、黑边、轮廓断裂或小尺寸不可辨认时，该衍生物不得进入品牌真源；
- SVG 未通过几何复核时不得替换 PNG，也不得在文档中宣称其为正式真源；
- Token 迁移中某个页面未完成时，允许页面继续使用旧样式，但不能让旧样式覆盖已迁移组件的语义 Token；
- 单个切片可通过恢复原样式入口和组件类名回滚，不回滚 API、数据库或领域数据；
- 新旧静态资产路径需要并存时，旧路径至少保留到所有构建、README、浏览器缓存和引用测试完成迁移；
- 视觉重构不得借机修改 migration；数据库校验和异常必须按数据库流程单独处理。

## 13. 验收标准

### 13.1 品牌资产

- 所有正式资产能追溯到明确真源或可复现生成步骤；
- 透明资产确实包含 Alpha，纸白、纯白、深色与品牌绿背景无可见污染边；
- 16、24、32、48px 下标志轮廓、负空间 `H` 和 `X` 断笔可辨认；
- SVG 路径经过几何复核，不含自动描摹产生的大量噪声节点；
- Web、Admin Web、favicon、Apple Touch Icon、PWA 与 README 使用规定版本；
- 当前公开 PNG 路径在明确迁移前保持可用。

### 13.2 颜色与层级

- 原始色值只存在于 Token 真源和明确豁免的品牌资产生成脚本；
- 普通文字对比度至少 4.5:1；
- 依靠轮廓识别的功能控件边框至少 3:1；
- 每个页面最多一个同层级实体绿色主要操作；
- 品牌绿不用于普通边框和普通次级文字；
- 状态不只通过颜色表达；
- 页面在大屏上不无限拉宽正文。

### 13.3 交互与响应式

- 全部交互元素可由键盘到达并具有可见 Focus；
- 点击目标至少 40×40px；
- 320px 宽度不出现阻塞操作的横向滚动；
- 200% 缩放下主要内容和操作仍可访问；
- `prefers-reduced-motion` 下移除非必要动画；
- 浅色和暗色主题都通过关键表面的对比度检查。

### 13.4 工程验证

每个实施切片至少执行：

```sh
pnpm format:check
pnpm lint
git diff --check
```

并补充：

- Web 与 Admin Web 的受影响包 Typecheck；
- 直接覆盖组件的 Vitest；
- 品牌资产签名、尺寸、Alpha、安全区和构建复制测试；
- 1440px、1024px、390px 与 320px 关键页面视觉基线；
- Light/Dark、默认/Focus/Disabled/Error 状态矩阵；
- 关键登录、创建任务、发送消息、打开 Artifact 和管理确认流程的回归测试。

## 14. 依赖与开放问题

进入首个实现切片前需要解决：

1. 是否可以取得 Logo 原始矢量设计文件；
2. 若不能取得，谁负责手工重建与最终几何签字；
3. 共享 Token 采用独立包还是单一真源生成；
4. Ant Design 主题 Token 与 Hoox 语义 Token 的映射边界；
5. 暗色模式是否跟随系统、允许用户覆盖，还是首期只提供浅色；
6. 视觉回归使用现有浏览器测试基础还是引入固定版本的截图工具；
7. 旧 PNG 路径在新增透明与 SVG 版本后的兼容保留周期。
