# 文件预览与选区引用

本页供维护 Web 文件交付、输入附件及预览接口的开发者查找当前能力、限制和失败语义。设计取舍见 [ADR-20260908104231](../decisions/20260908104231-browser-file-preview-and-versioned-references.md)。

## 用户流程

交付卡片的“预览”在任务中打开文件。默认直接选择文字，选区附近浮现“引用”按钮，点击后以紧凑条目加入输入框，再填写要求并发送。框选区域和整页引用收在“更多预览操作”中；图片或没有文字层的页面直接提示框选。单元格范围沿用表格坐标选择，再通过浮层引用。预览不提供编辑。选择本身不发请求给 Agent；区域截图只在提交时上传。历史消息的引用卡片重新读取原 Run 的原 Artifact，并恢复引用位置，不自动跳到新交付版本。

宽度至少 1200px 时对话与预览并排，分隔线支持鼠标拖动和方向键调整。较窄窗口使用全屏预览，底部可展开引用条目和修改要求输入区；输入文字与对话共用草稿。引用浮层随滚动、缩放与面板尺寸更新位置，选区离开可见区域或取消选择时隐藏。框选模式隔离滚动手势，选框支持四角拖动调整；加入引用后自动回到阅读模式。查找按需展开，Office 排版说明收在更多操作内。控件、边框和引用条目使用工作台共享主题。关闭预览保留待发送引用；普通阅读位置只在查看器保持打开时保留。

## 支持范围

上传待发送附件、消息附件、交付文件、云盘、文件引用和预览标题共用 `FileTypeIcon`，使用 [File Icon Vectors](https://github.com/dmhendricks/file-icon-vectors) 1.0.0 的 Vivid SVG（MIT 许可）。图标通过精确版本依赖按需打包，无运行时 CDN 请求。已知扩展名优先，缺失或未知时按 MIME 类型回退，无法识别时显示通用文件图标；图标分类不决定预览权限。可显示的图片继续使用缩略图。

| 格式 | 当前预览 | 引用 |
| --- | --- | --- |
| PNG、JPEG、WebP、GIF | 图片缩放；GIF 截图是当前帧 | 矩形区域 |
| PDF | 按页渲染、页码导航、当前页文字查找 | 文本层文字、整页、矩形；扫描页不提供 OCR |
| TXT、Markdown、代码 | UTF-8 文本、Markdown 安全排版、代码基础关键字着色与行号 | 文字、行位置、矩形 |
| CSV、TSV、XLSX | 工作表切换、每屏最多 100 行 × 20 列、基础颜色/加粗/合并单元格 | 单元格坐标与选区文本 |
| DOCX | 浏览器分页近似排版，保留正文、表格、图片 | 文字、整页、矩形；页码为预览页码 |
| PPTX | 浏览器单页渲染、页码切换 | 文字、整页、矩形 |

Office 不承诺与桌面软件逐像素一致；字体可能替换，Excel 公式不重算，未保存公式结果会明确提示。Excel 图表与复杂格式不渲染；PPTX 不播放动画，嵌入 PDF 回退关闭。PDF、PPTX 使用页码导航，尚无缩略图导航。旧 `.doc`、`.xls`、`.ppt` 与加密文件不在支持范围。HTML/SVG 执行预览、OCR、音视频时间段、元素级引用和版本差异对比均待规划。

单文件读取上限为 24 MiB；文本上限 2 MiB；Office 中央目录声明解压量上限 96 MiB、最多 5000 项，不接受 ZIP64 和加密包。XLSX 总行列矩形预算为 10 万单元格，Worker 解析超过 20 秒即终止。上述预算不是针对所有畸形压缩文件的资源隔离保证，复杂 Office 仍可能占用明显的浏览器内存。不能可靠预览时展示失败与重试，下载仍可用。

## 文件读取与隔离

`GET /v1/threads/:threadId/runs/:runId/artifacts/:artifactId/content` 只返回支持格式且已发布的交付物。API 在读取前后核验成员授权、归属、授权修订和固定 Blob 身份，返回 `application/octet-stream`、attachment、no-store、nosniff 与 `X-Resource-Version-Id`，Web 核对版本后才解析。该入口不签发长期 URL，不执行格式转换；原有 preview/download 保持兼容。

PDF、DOCX、PPTX 与文本内容进入只允许 same-origin 的 sandbox iframe；该文档禁止脚本、外部请求、表单提交和主动导航，仅允许内联样式以及 data/blob 图片和字体。Office 在浏览器中移除预览副本的外部关系后再交给渲染器，避免其创建媒体节点时发起外部请求；原文件保持完整。PDF 在父文档的离屏 Canvas 绘制为位图，iframe 内叠加文字层。重型格式按需加载，表格解析运行在可终止 Worker 中。预览数据不会进入持久草稿，区域快照除外。

## 引用契约与持久化

`POST /v1/threads/:threadId/inputs` 可携带最多 8 个 `fileReferences`。每项包含：

- `source`：Thread、Run、Artifact、不可变版本 ID 和名称；服务端用权威名称覆盖客户端名称，引用限当前 Thread。
- `selection`：文字位置、原文和前后文；或页码及归一化矩形与布局尺寸；或工作表、单元格范围和摘录；或整页。
- `snapshot`：可选的已上传 PNG Resource/Version；矩形引用必须携带，大小不超过 2 MiB，并经附件解析器授权。

页码和原文属于用户提供的选区事实，不是服务端解析验证的 Office 内容。服务端验证结构、矩形边界及版本归属，自动将原文件加入附件。Agent 通过现有 ResourceFS 读取原文件，区域 PNG 复用现有视觉附件链路。文字摘录最多 8000 字符；附件和自动补入的原文件仍共用每条消息 20 个附件的限制。

引用由协议包序列化为版本化的 `hoox-file-references-v1` 区段，写入最新 user 消息、位于现有附件事实之前，因此沿用既有输入持久化和恢复机制，无数据库迁移。引用参与请求幂等摘要；system/developer prompt 与工具 schema 不注入请求级数据。Web 仅对结构有效的区段显示引用卡片，非法区段保留为原始文字。此区段是用户内容格式，不构成可信指令或新的授权凭据。

Pi 在模型请求边界将有效引用投影为精简文本：用户原话不加标签，文件只列一次可读取的固定版本路径，多处引用用文件编号关联。模型收到文字原文及必要前后文、预览页码，或工作表与单元格范围，或矩形与布局尺寸及截图文件编号；不单独列 Thread、Run、Artifact、Version、媒体类型和文字偏移。当前输入、后续历史与压缩数据采用相同投影，持久用户事实、界面回看和附件授权仍保留完整内部数据。路径中的资源身份是读取所必需的信息。普通输入保持原样；非法引用或无法关联现有附件路径时保留原文，不猜测文件身份。

待发送引用及截图按账号、Tenant、Thread 保存到当前标签页 sessionStorage，退出账号时清理。存储失败保留内存草稿并提示；成功发送后清除，失败或拒绝保留。短期签名地址、原文件字节不进入草稿。由于 DOCX 可能重新排版，区域恢复同时保留原截图和原布局尺寸供解释，不承诺跨浏览器的视觉位置完全一致。

## 验证

普通 Vitest 覆盖引用编码、坐标边界、CSV 解析、API 权限与版本漂移、原附件补入以及草稿发送/回看。真实浏览器回归使用仓库内合成文件和模拟 API，验证真实解析器、iframe、截图、表格 Worker、历史引用、刷新恢复及小屏输入；它不替代真实对象存储和模型服务端到端验收。

首次执行 `pnpm exec playwright install chromium --only-shell` 安装测试浏览器，再运行 `pnpm test:web:file-preview`。失败截图与 trace 写入 `.tmp/file-preview-results`。合成夹具及可选的 Python 重建脚本位于 `runtime-ts/apps/web/browser-tests`；正常测试无需 Python。
