# v0.1.0 版本说明

本文面向准备安装或升级 Hoox 的自托管用户与集成者，记录 `v0.1.0` 的能力、限制及兼容性约定，不替代仓库 HEAD 的现状文档。

计划发布日期：**2026-11-22**；首个公开 tag：`v0.1.0`。本文是仓库内的发布准备材料，不表示 tag 或 GitHub Release 已发布。变更摘要见 [CHANGELOG](../../CHANGELOG.md#010---2026-11-22)。

公开发布前仍需完成[首次公开发布检查清单](../maintainers/open-source-release-checklist.md)，其中第三方来源摘要与图标授权范围尚待维护者确认，详见[第三方说明](../../THIRD_PARTY_NOTICES.md)。

## 概述

Hoox 是开源、可自托管的云端 Agent 平台。`v0.1.0` 聚焦通过后台配置专属 Agent，并在工作台交付给个人或团队：编写指令、选择模型与工具、绑定 Skill、试跑草稿后发布，无需修改 Hoox 业务代码。Agent 在服务端 Sandbox 执行，不访问终端用户的本地文件系统。

这是 `0.x` 阶段的首个公开版本，适合开发、评估和 Demo，不是完整 Headless 产品，也不构成生产就绪承诺。

## 主要能力

- **Agent 定义与版本**：管理员管理 AgentDefinition 和不可变 AgentRevision，配置 Operator 指令、模型、工具白名单与精确 Skill 版本；个人和团队只有使用权。工作台可选择向当前 Tenant 开放的已发布 Agent；Thread 绑定 Agent，每个 Run 固定当时版本，重试、恢复和子 Agent 继续使用同一快照。见 [Agent 定义与 Run 快照](../architecture/agent-definition.md)和 [Skill Runtime](../architecture/skill-runtime.md)。
- **外部工具**：支持远程 MCP Streamable HTTP，以及带 HMAC 签名的 HTTP 工具运行路径。后台可注册 MCP Server、写入凭据、探测并发布不可变工具批次，也可撤销；Agent 选择精确工具版本后由 Worker 装配到 Session，经 Tool Router 执行。凭据加密保存，不进入 Prompt、工具 Schema 或管理响应。HTTP 导入的限制见下文；接入边界见[后台控制面](../architecture/admin-control-plane.md#外部工具注册边界)和 [HTTP 工具参考](../reference/http-tools.md)。
- **服务集成基础**：Tenant API Key 具有独立集成身份、作用域、到期与吊销控制；认证后仍受 Membership 和 RLS 约束。Webhook 支持 Run 终态事件通知、HMAC 签名、至少一次投递、有限重试和密钥轮换。见[身份与会话](../architecture/identity-and-session.md#服务凭据与集成身份)和 [Webhook 参考](../reference/webhooks.md)。
- **调试与观测**：后台 Run 浏览器展示状态、用量和时间线，查看正文必须有权限并留下审计。Playground 支持草稿运行、实时轨迹和外部工具 Mock。Worker 可配置 OpenTelemetry 追踪与指标导出，默认不启用，也默认不导出正文。见[后台 Run 浏览器](../architecture/admin-control-plane.md#run-浏览器与正文访问)和 [OpenTelemetry 导出](../maintainers/diagnostics.md#导出到-opentelemetry)。
- **开源协作**：提供 Apache-2.0 项目许可证、分层文档、贡献流程、安全策略和社区模板；第三方组件按各自许可证使用，见[第三方说明](../../THIRD_PARTY_NOTICES.md)。

## 已知限制

- **Headless 尚未完整交付**：API Key 与 Webhook 已实现，但 M3 的稳定公开 API v1、终端用户映射、客户端工具和 TypeScript SDK 尚未完成。已有 `/v1` 路径不能据此视为稳定公开 API 契约；API Key 只可访问显式声明作用域的路由。
- **HTTP 工具后台发布未完成**：单端点声明和受限 OpenAPI 片段目前只提供导入预览，没有 HTTP 发布接口；不能把已有签名与执行能力理解为可直接在后台发布任意 HTTP 工具。MCP 不支持由 Worker 宿主拉起 stdio Server。
- **Agent 配置仍有执行缺口**：非默认 `sandboxTemplateId` 尚未接入执行装配，出现该配置时失败关闭，不会静默使用默认模板。
- **运营能力未齐备**：评测集与版本评测对比、按 Agent 的运营指标与成本面板、终端用户反馈、配置即代码、白标和开发者自助发布 Skill 尚未完成。已有 OpenTelemetry 导出不代表这些产品能力已交付。
- **Playground 不是无副作用环境**：Mock 仅覆盖已登记的外部工具；Sandbox 的 `exec_command`、Skill 脚本等仍可联网，可能产生真实外部副作用。需要隔离时，应禁用命令工具或使用无出网的 Sandbox 配置，见[Playground 隔离边界](../architecture/run-execution-and-recovery.md#playground-与正式业务副作用隔离)。
- **部署验证限于开发与 Demo 路径**：仓库没有生产镜像、SBOM 或发布清单；真实身份、目标基础设施联合 readiness、容量、备份恢复与集群回滚仍需验收。详见[生产就绪边界](#生产就绪边界)。
- **文件图标不是开放许可资源**：iconfont 图库 33437 只有仓库记录的 Hoox 商用授权确认，不代表其他项目可自由复用。维护者仍需确认公开分发与下游使用的授权范围，见[第三方说明](../../THIRD_PARTY_NOTICES.md#iconfont-文件类型图标)。

后续能力的目标契约见[可定制 Agent 平台规范](../specs/custom-agent-platform.md)；该规范不是本版已实现能力清单。

## 升级方式

首次安装按[开发环境准备](../development.md)配置依赖和凭据。已有开发或 Demo 安装升级时：

1. 备份 PostgreSQL、对象存储及解密既有配置所需的秘密，确认备份可恢复；不要把秘密放入发布记录。
2. 停止受理新任务并排空在途 Run，再停止相关进程。旧版本受理但缺少 Agent 快照的 Run 不能靠升级自动补齐并继续执行，见[执行与失败边界](../architecture/agent-definition.md#执行与失败边界)。
3. 使用维护者发布的 `v0.1.0` 源码，按仓库固定的 Node.js `24.18.0` 与 pnpm `10.15.1` 执行 `corepack pnpm install --frozen-lockfile` 和 `corepack pnpm build`。
4. 按目标环境为迁移器配置专用权限后执行 `corepack pnpm db:setup`（即 `pnpm db:setup`），引导所需数据库角色并应用迁移。此命令会改变数据库结构与授权，只可由部署者在计划好的目标库执行，不应对共享开发库试跑。
5. 按部署说明启动并检查服务、默认 Agent、历史 Thread、新 Run 和文件交付。保留数据卷的 Demo 升级步骤见 [Demo 持续部署](../operations/demo-cd.md#保留数据卷升级)。

已合并或已执行的迁移不得修改，新变化只能向前追加；checksum 不一致时必须停止，不得改写迁移记录。应用回退不等于数据库可回退；数据或 Schema 不兼容时须按已演练的恢复方案处理，不能盲目执行 down migration。

## 兼容性承诺

- `0.x` 阶段不承诺公共 API、数据库 Schema、配置和部署契约跨版本兼容，也不承诺稳定发布节奏；升级前必须阅读对应版本说明和迁移要求。
- 已发布 AgentRevision 的不可变性与 Run 快照是单次运行的执行契约，不是不同 Hoox 版本之间可无条件恢复或回滚的承诺。
- development 身份、本地账号与测试端点不属于 production 契约；当前也没有长期维护多个发布分支的承诺。安全修复的支持范围以 [SECURITY.md](../../SECURITY.md#支持版本)为准。

## 安全报告渠道

按 [SECURITY.md](../../SECURITY.md#私下报告)使用 GitHub 私有漏洞报告，不要在公开 Issue、PR、日志或截图披露漏洞细节、凭据和用户数据。该入口不可用时，只创建不含漏洞细节的 Issue，请求维护者提供私下沟通渠道。

## 生产就绪边界

`v0.1.0` 提供经过自动化验证的执行、隔离和配置边界，但发布版本号不等于生产验收通过。上线前必须在目标环境完成[生产就绪说明](../operations/production-readiness.md)要求的身份与越权验证、基础设施联合 readiness、容量阈值、备份恢复及回滚演练；仓库测试和 Demo 不能替代这些工作。
