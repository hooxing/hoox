# 模型供应商配置易用性规范

- 状态：草案
- 日期：2026-08-26
- 读者：模型配置页面、控制 API、持久化与 Agent Worker 的维护者
- 范围：OpenAI-compatible 模型供应商的添加、编辑、测试、保存、切换与运行时生效
- 本文性质：目标规范，只定义必须达到的产品与跨模块行为，不包含实施计划

当前实现已经具备模型 Provider、Pi 模型目录和 active 配置等基础结构，但尚未完整满足本文目标。实现完成前，
当前行为仍以[配置参考](../reference/configuration.md)和代码测试为准。本文不引用既有 ADR。

## 1. 目标

管理员必须能够完成以下任务：

1. 添加 Pi 目录中的供应商，也能添加任意符合平台网络策略的 OpenAI-compatible 自定义供应商；
2. 配置 Pi 目录尚未收录的新模型，并自行修正模型能力；
3. 用真实模型请求测试已填写的配置是否可用；
4. 保存多个供应商，并在列表中随时切换当前供应商和默认模型；
5. 切换成功后，无需重启服务，后续新 Run 实际使用新配置；
6. 完成上述操作时不填写变更理由。

## 2. 非目标

首版不包含：

- 非 OpenAI-compatible 协议；
- 自动抓取供应商官网、自动推断模型能力或自动同步 Pi 目录；
- 价格、限流、负载均衡和多个模型同时 active；
- 用图片请求测试视觉能力；
- 在页面展示内部 Revision、版本令牌或审计记录；
- 把新配置强行替换到已经开始执行的 Run。

## 3. 核心概念

- **供应商配置**：显示名称、接口地址、API Key 和模型列表组成的一条持久配置。
- **模型条目**：供应商下可选择的一个模型及其输入、推理和 Token 能力。
- **当前配置**：新 Run 应使用的唯一供应商配置及其默认模型。
- **Pi 目录**：填写供应商和模型初始值的模板，不是可配置模型的白名单，也不是运行时事实源。

系统内部可以继续使用不可见的稳定 ID 和 Revision，但不得要求管理员理解或填写这些字段。

## 4. 页面行为

### 4.1 供应商列表

模型配置首页必须展示已经保存的供应商列表。每一项至少显示：

- 显示名称；
- 接口地址的主机名；
- 默认模型 ID；
- 是否为“当前使用”；
- 最近一次测试状态：未测试、成功或失败；
- 编辑、测试和设为当前三个操作。

列表来源必须是服务端持久数据。页面刷新、Admin API 重启和 Worker 重启后，已保存供应商仍然存在。列表同时只能有
一项标记为“当前使用”；没有当前配置而使用部署回退时，页面必须明确显示“部署配置回退”，不能把某个已保存供应商
误标为当前配置。

### 4.2 添加与编辑供应商

选择 Pi 供应商和添加自定义供应商必须进入同一个编辑器。编辑器只要求管理员处理以下供应商字段：

| 字段 | 规则 |
| --- | --- |
| 显示名称 | 必填，允许正常的中英文和大小写，例如 `DeepSeek` |
| 协议 | 首版固定为 OpenAI-compatible，不要求手工选择 |
| 接口地址 | 必填，必须是符合平台网络策略的无凭据 HTTPS URL |
| API Key | 新增时必填；编辑时留空表示保留原值，填写表示替换 |

`providerKey` 属于内部标识，不得作为表单字段。服务端负责生成稳定 ID；显示名称的大小写不得导致请求在 schema
校验阶段失败。

API Key 是只写字段。保存、列表、测试结果、错误响应和日志均不得返回其明文或密文。

### 4.3 模型编辑

无论供应商是否来自 Pi，模型区域都必须支持：

- 从 Pi 目录选择模型；
- 点击“添加模型”并填写一个 Pi 目录中不存在的模型 ID；
- 编辑已有模型；
- 删除非当前默认模型；
- 选择且只能选择一个默认模型。

每个模型条目至少允许编辑：

| 字段 | 规则 |
| --- | --- |
| 模型 ID | 必填，按供应商要求原样保留大小写，只去除首尾空白 |
| 显示名称 | 可选；为空时使用模型 ID |
| 图片输入 | 可开关；文本输入始终启用 |
| 推理模型 | 可开关 |
| 上下文窗口 | 正整数，可修改 |
| 最大输出 Token | 正整数，可修改，且不得大于上下文窗口 |

Pi 提供的数据只作为首次填入的值。管理员修改 Pi 模型或手工添加目录外模型后，保存值就是运行时事实；后续 Pi 目录
更新不得覆盖。手工添加模型时，页面可以提供明确标注为“平台默认值”的 Token 初始值，但不得把它描述成 Pi 或供应商
官方数据。

### 4.4 保存、测试与切换

页面提供以下清晰、互不混淆的操作：

- **保存**：持久化当前编辑内容，不改变当前使用的供应商；
- **测试**：测试该供应商最近保存的配置，不保存、不切换；
- **设为当前**：把最近保存的配置切换为当前配置；
- **保存并使用**：原子完成保存和设为当前，不能出现“保存成功但页面声称已经切换”的中间结果。

修改并重新保存供应商后，旧测试结果失效，状态恢复为“未测试”。测试成功不是保存或切换的强制门禁；管理员可以跳过
测试直接切换，但页面必须如实显示其未测试状态。

上述操作不展示也不接收“变更理由”。服务端仍可自动记录操作者、时间、对象和动作，但不得把人工填写理由作为请求
合法性条件。

## 5. 真实可用性测试

“测试”必须向配置的接口地址和默认模型发送一次最小文本生成请求。仅请求 `/models`、仅检查 TCP/HTTP 连通性或仅在
本地校验字段，不算测试成功。

测试请求必须满足：

1. 使用该已保存配置对应的 API Key 和默认模型；
2. 使用固定、无用户数据的短文本输入；
3. 设置受限输出和超时，不开启流式响应；
4. 只有供应商返回成功状态且响应能解析为有效的 assistant 输出时才判定成功；
5. 成功结果显示“文本请求测试成功”和测试时间，不宣称图片输入已经验证；
6. 失败结果至少区分地址或网络错误、超时、鉴权失败、模型不存在、协议响应不兼容和其他供应商错误；
7. 失败详情必须脱敏，不返回 API Key、Authorization 请求头或完整供应商响应正文。

最近一次测试状态和时间必须随已保存配置持久化。测试不得自动保存配置，也不得自动设为当前。

## 6. 切换后的运行时生效

切换操作的服务端成功响应必须表示当前配置已经持久提交。管理页面必须重新读取服务端当前配置后再显示“当前使用”，
不能只依赖前端乐观状态。

切换完成后：

- 此后创建的新 Run 必须解析并固定新的当前供应商、默认模型和对应凭据；
- Worker 不得要求重启，也不得因为进程启动时缓存或 Pi 目录快照继续使用旧模型；
- 同一 Run 的重试、恢复和继续执行仍使用该 Run 已固定的配置，不能在执行中途换模；
- 新配置无法装配时，该 Run 必须明确失败，不能静默回退到旧 active 配置或部署模型；
- 没有任何当前配置时，才允许使用部署回退，并在管理页面明确展示。

“切换已生效”的验收依据是新 Run 的真实供应商调用，而不是数据库状态、页面标签或控制 API 返回值单独成立。

## 7. 请求校验与错误反馈

模型配置 API 必须返回可定位到字段的校验错误。页面必须把错误显示在对应字段或模型行附近，不能只显示
“请求参数无效”。至少覆盖：

- 接口地址不是合法 HTTPS URL或被平台网络策略拒绝；
- 模型 ID 为空或重复；
- 默认模型不存在；
- Token 字段不是正整数或最大输出大于上下文窗口；
- API Key 缺失；
- 保存、测试或切换时目标配置已被并发修改。

错误响应可以保留稳定的顶层错误码，但必须附带安全的字段路径，例如 `baseUrl`、`models[0].contextWindow`。任何校验
错误、供应商错误或内部错误都不得回显请求中的 API Key。

## 8. 最小接口能力

控制 API 至少需要提供以下能力；具体 HTTP 路径不由本文规定：

1. 列出已保存供应商，并返回唯一当前配置和最近测试状态；
2. 创建或更新供应商配置；
3. 对已保存配置执行真实测试；
4. 将已保存配置设为当前；
5. 原子执行“保存并使用”；
6. 读取当前实际配置，供页面和 Worker 使用。

模型配置的创建、更新、测试和切换请求均不得要求 `reason`。内部 ID、并发令牌和审计字段可以存在，但不应成为普通
管理员可见或手工填写的内容。

## 9. 验收标准

实现完成时至少通过以下自动化验收：

1. 使用显示名称 `DeepSeek`、合法接口地址和目录外模型 ID 能保存自定义供应商；
2. Pi 供应商可以添加 Pi 目录未收录的模型，并修改图片输入、推理、上下文窗口和最大输出；
3. 非法接口地址在 `baseUrl` 字段得到具体错误，而不是只有 `INVALID_REQUEST`；
4. 两个供应商保存后在进程重启后仍存在，并可来回切换；
5. 正确配置的测试会命中默认模型的文本生成接口，错误密钥和不存在的模型分别得到可理解的失败结果；
6. 测试只改变测试状态，不改变当前配置；重新保存后测试状态恢复为“未测试”；
7. 供应商 A 为当前时创建的 Run 调用 A；切换到 B 后创建的新 Run 调用 B，切换前已经开始的 Run 仍调用 A；
8. 切换后不重启 Admin API 或 Worker，也能满足上一条；
9. 模型配置页面和相关请求中不存在变更理由字段，服务端不会因缺少理由拒绝请求；
10. 列表、错误响应和日志均不包含 API Key。

自动化测试至少直接覆盖页面交互、协议校验、持久化重启、真实探针替身和 Worker 新旧 Run 路由，不能只测试领域对象。
