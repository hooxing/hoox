# 团队版发展规划

## 产品原则

团队版不是给个人功能加一个文件夹，而是增加第二种权限、资产与协作边界。设计应始终回答四个问题：资产属于谁、谁能继续修改、成员退出后保留什么、多人同时工作时如何避免互相覆盖。

## 当前试验版

- 个人空间与团队空间单选切换；团队入口默认折叠，多团队通过下拉切换。
- 左上角新建会话固定回到个人空间；团队入口提供团队新对话。
- 个人任务可按消息快照发布到团队；团队任务可创建多个独立分支并行推进。
- 团队云盘和个人云盘在同一窗口双栏展示。
- 团队文件进入个人任务前复制为个人快照，退出团队后已用副本保留，新引用失败关闭。
- Skill 按空间安装；团队 Owner/Admin 管理，成员使用。
- 团队成员支持 Owner/Admin/Member、角色调整、移除和 Owner 解散。

## 下一阶段

### M1：可用的团队协作

- 邀请链接、待接受邀请、邀请过期和重新发送。
- 团队名称、头像、默认团队和最近访问团队。
- 所有权转移专用流程、成员主动退出、批量成员管理。
- 团队任务提交人展示、分支树、分支命名、分支归档和从分支继续发布。
- 动态 Tenant Worker 调度，保证新建团队可以立即执行任务。

### M2：资产治理

- 团队云盘目录、上传、移动、删除、版本历史和回收站。
- 团队文件配额、个人副本计费、重复内容去重和来源标记。
- Skill 审批、版本锁定、灰度升级、禁用原因和团队自建 Skill。
- 团队模型、工具、网络访问和数据保留策略。

### M3：组织级能力

- 多团队组织、部门层级、用户组和跨团队共享资源。
- SSO/SCIM、域名认领、离职自动回收和合规导出。
- 操作审计、敏感操作二次确认、法务保留和数据驻留。
- 团队用量、成本中心、预算告警和管理员报表。

## 上线前必须补齐的问题

- 邀请的是平台已有用户、邮箱，还是企业目录身份；未注册用户如何落地。
- 团队任务的分支是否需要合并；如果需要，合并的是消息、文件还是 Workspace 变更。
- 发布到团队时哪些附件允许复制，敏感文件是否需要来源 Owner 再确认。
- 个人副本是否计入个人配额，团队原文件删除后副本是否显示来源已失效。
- 团队 Skill 的发布者信任、权限声明、版本升级和紧急下架责任由谁承担。
- 解散后的恢复窗口、账单结算、数据导出和最终删除策略。
- 成员退出后其署名、审计记录、交付物版权和未完成自动化由谁接管。
- 多团队同名、同一任务多次发布、重复文件和重复 Skill 调用名如何向用户解释。
