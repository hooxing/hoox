# Hoox 部署版本体验与功能测试报告

本文供产品、前端和部署维护者安排修复与复测，记录 2026 年 9 月 5 日部署站点的时点证据，不代表后续版本持续通过。当前行为以对应代码、配置契约和自动化测试为准；验证记录入口见[验证记录索引](README.md)。

## 结论

**核心个人任务链路可用，但运营统计目前不能作为可信依据，草稿保留和团队加入流程存在明显缺口。** 本轮实际完成了新建会话、两轮模型任务、Sandbox 文件写入、交付和文本预览。没有发现已测试主流程的整页崩溃。

建议先修复运营统计，再处理草稿和团队加入入口；同时复核邮箱发信配置及下载落盘。不能据此宣布所有功能或生产发布门禁通过。

## 已确认的问题

优先级：P1 表示核心判断或运营能力受影响；P2 表示正常操作受阻或有数据丢失、误操作风险；P3 表示可读性和说明改进。下述严重程度为测试建议。

### HOOX-01 · P1 · 管理端统计与真实任务明显不一致

- **复现**：工作台创建验收会话并完成两轮请求；打开管理端工作台，点击“刷新”；再进入“数据运营”。
- **实际**：前台个人任务由 13 增至 14，验收任务已经回复并交付文件；管理端累计对话、累计 Run、24h 成功、输入和输出 Token 均为 0。数据运营页显示数据生成于 2026/9/5 15:15:17，口径明确写“全部 Thread”和“所有执行记录”。
- **预期**：统计至少反映刚完成的一条会话和两次执行；无法获取数据时显示不可用及原因，不能显示成功读取的 0。
- **影响**：维护者无法判断使用量、成功率和系统是否活跃。刷新后仍存在，不能仅以页面未刷新解释。
- **建议**：核对控制面与 Runtime 的数据库、Schema、受限聚合视图、角色可见范围和投影更新；增加“真实创建 Run → 聚合可见”的集成验证。上述为排查方向，未确认根因。
- **复测**：创建一条带唯一标记的任务，核对对话、Run 和成功计数增量；明确 Token 聚合是否存在延迟。

### HOOX-02 · P2 · 刷新会直接丢失未发送草稿

- **复现**：在验收会话输入 `未发送草稿：hoox-qa-draft-20260905`，不发送，刷新页面。
- **实际**：消息历史和交付文件恢复，输入框变为空，发送按钮禁用。
- **预期**：按会话保存草稿并恢复，或者提供明确的离开保护。
- **影响**：用户编写较长任务时，误刷新会丢失输入。
- **建议及复测**：区分新会话草稿与已有会话草稿；验证刷新、会话切换、发送成功后的清理及多标签冲突。本轮只确认刷新丢失，未把其他切换方式计为失败。

### HOOX-03 · P2 · 加入团队要求用户 ID，却没有获取入口

- **复现**：账号菜单 → 团队中心 → 加入团队。
- **实际**：说明要求让 Owner 或管理员“通过你的用户 ID 添加成员”；团队中心、已检查的账号菜单均无展示或复制用户 ID 的控件，只有刷新加入状态。
- **预期**：原地提供可复制 ID，或者提供明确可用的邀请方式与入口。
- **影响**：用户无法依照当前页面完成加入流程，需要额外咨询。
- **复测**：一个未加入团队的账号可以在不查询数据库或管理接口的情况下拿到所需标识。

### HOOX-04 · P2 · 个性化弹窗缺少 Esc 关闭及可访问名称

- **复现**：打开个性化，在自定义指令输入框按 Esc。
- **实际**：弹窗仍保持打开；DOM 中该弹窗仅为无名称 `dialog`，标题未成为其可访问名称。点击“关闭个性化”可以正常关闭。
- **预期**：Esc 按明确的未保存策略关闭；对话框与标题建立可访问关联。
- **影响**：键盘操作不一致，辅助技术无法从对话框名称判断当前上下文。
- **复测**：Esc、标题名称、焦点进入和退出、Tab 边界分别测试。焦点陷阱本轮未实测，不认定为已确认缺陷。

### HOOX-05 · P2 · 定时任务的同名目标无法区分

- **复现**：打开定时任务，检查“目标任务”选项。
- **实际**：已有多个“你好”和“你是啥模型”选项，只有标题，无创建日期、最近更新时间或其他辨别信息。
- **预期**：显示足够区分同名任务的辅助信息，并支持查看目标。
- **影响**：容易把定时指令绑定到错误会话；该操作还会复用目标会话的工作区。
- **复测**：建立两个同名测试会话，用户可以在提交前准确辨认目标。

### HOOX-06 · P2 · 已暴露技能入口但部署无可用技能，空状态没有下一步

- **复现**：工作台 → 技能中心；同时查看管理端工作台技能计数。
- **实际**：技能中心显示“没有找到可安装的技能”；管理端已发布 Skill 为 0，安装数为 0。入口仅有搜索，没有发布、配置说明或申请渠道。
- **判断**：不是已经证明的列表接口故障；当前部署确实没有向该使用路径提供可用技能。
- **建议**：若演示需要展示技能能力，发布最小可用技能；否则空状态应明确尚未提供技能及下一步。区分“目录为空”和“搜索无匹配”。
- **复测**：有技能、零技能、无匹配和加载失败四种状态分别给出准确反馈。

### HOOX-07 · P2 · 部署环境标签与配置就绪表达不一致

- **复现**：管理端工作台及运行配置。
- **实际**：顶部统一标“生产环境”；`ADMIN_CONTROL_JWT_SIGNING_KEYS` 显示未配置；配置地图又说明生产需要独立签名配置，并混有“本项目依赖 uu 端口映射”等本机说明。记忆服务未启用，其两个秘密仍计入 `10/13` 未配齐状态。
- **预期**：显示真实部署类型与对应就绪要求，区分“当前能力必需”“未启用而不适用”“无法检测”。
- **影响**：维护者无法仅凭页面判断是否满足该部署的验收契约。
- **边界**：这不等于已经证明认证绕过；本轮未改变或绕过认证。管理网关可能采用另一种受控身份方式，需要维护者确认。
- **复测**：演示与生产分别展示准确模式，关闭记忆时不把它显示为必修缺口。

### HOOX-08 · P3 · 定时、团队和状态说明夹杂实现术语

- **实际**：定时说明使用 Sandbox、Workspace；团队创建说明使用 Owner；任务完成后出现“工作区已暂停”，没有解释下一次发送是否自动恢复。首次执行字段未显示业务时区。
- **影响**：普通用户需要理解实现细节才能判断操作后果；跨时区协作时执行时间易产生歧义。
- **建议**：用用户动作和结果描述复用关系；时间旁显示实际业务时区；暂停状态说明恢复方式。暂停是否自动恢复尚未在本轮验证，不应直接承诺。
- **复测**：维护者更改业务时区后，界面说明与实际调度一致；暂停后继续发送的行为有明确反馈。

### HOOX-09 · P3 · 管理端手机视口中有效编辑宽度过窄

- **复现**：390 × 844 视口打开模型服务。
- **实际**：约 72 px 固定图标导航，加上多层卡片和内边距，供应商名称、默认模型和地址频繁换行；截图中供应商内容区域明显狭窄。
- **判断**：未观察到整页横向溢出或入口完全不可用，属于可读性问题。
- **建议**：手机上将导航改为可完全收起的抽屉，减少嵌套卡片边距，让模型字段获得更多宽度。
- **复测**：390 px 下名称、状态和主要操作仍容易扫读，编辑字段不需要横向滚动。

## 尚未覆盖

本轮是有真实任务执行的探索性验收，不是完整自动化回归或安全审计。以下没有标为通过：新用户注册及邮件到达、忘记密码、文件上传和大文件、图片/视频理解、停止运行和排队的实际状态流转、定时任务触发与重复调度、团队创建和成员权限、多账号隔离、归档恢复和删除、管理配置发布与回滚、真实移动设备软键盘、断网恢复、负载及长上下文压力测试、内部轨迹的全面检查。

受限原因包括既有演示账号没有团队、技能目录为空、避免改变已部署平台策略，以及浏览器下载观测和控制延迟。以上覆盖缺口需要专用测试账号、隔离配置或定向补测，不应被“核心链路通过”掩盖。

## 修复与复测顺序

1. 先核对 HOOX-01 的统计数据接入；同时确认邮箱配置与文件下载的最终结果。

4. 改善手机编辑宽度和任务状态说明；补齐未覆盖流程，再作生产发布判断。

本报告不修改运行时代码。验收会话标题以 `【部署验收 20260905】` 开头，包含两轮请求和一份文件，保留用于人工复核；临时视口已重置。
