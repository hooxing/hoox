## 结论

后台托管路由已在 Demo 真实接管新实例，供应商切换、按权重分配、版本固定、密钥保护和探测门禁都已验证；E2B 路径可完成真实任务。

腾讯云 AGS 在上海地域暂不能承担新实例：从 Demo 主机（春川）到上海地域的数据面写入约 1.2–1.7MB/s、约 0.85 秒/文件，同一份快照在 E2B 上 8 秒完成，在 AGS 上无法在时限内完成。当天稍后改用香港地域后该路径可用，结论见下节。

## 后续定位：AGS 失败是部署主机到数据面的链路问题

同日在提交 `34b9972` 上复验并继续定位。

受控快照物化原先逐文件串行写、单文件一次大请求且不重试。实测 127MB、172 文件快照在本机需要 99.5 秒；改为有界并发与分块重试后降到 29.1 秒（E2B 写入总量 284.6 秒、墙钟 79.9 秒），摘要校验全部通过。该改进已随 PR #30 部署，但没有解决 Demo 的 AGS 失败。

连续三次 Demo 实测在“资源目录准备”阶段失败，耗时分别 61.6 秒、93.0 秒和约 90 秒；一次现场采样显示写入停在第 22 个文件、0.34MB 后不再前进。现场读取 AGS 沙箱内 `envd` 日志显示：最后一次 `POST /files` 在 11:45:17.776Z，之后到沙箱被回收都没有新的文件请求进入服务端；同一时间从本机（中国）发往同一 `envd` 的探测命令持续正常返回。

因此失败不在快照体积、不在重试策略，也不在 Sandbox 侧：部署主机（Oracle 春川）到 AGS 上海数据面的路径在约 20 余次请求后停止投递新请求，客户端每次重试都等到自己的超时。控制面（创建、销毁）始终正常。同一快照从中国本机到 AGS 上海连续 180 次写入全部成功。

已用现有凭据验证 AGS 域名在 `ap-shanghai`、`ap-hongkong`、`ap-singapore`、`ap-guangzhou`、`ap-beijing` 都可鉴权，只是沙箱工具 `hoox-ags-smoke` 仅存在于上海。按“沙箱地域应参考春川部署”的判断，下一步是在香港地域新建沙箱工具并复验；该操作需要在腾讯云控制台登录后进行。

随后又补上自适应降级：分块写入连续失败时自动换用更小的请求体重试同一文件（4MiB → 1MiB → 256KiB），见 [ADR](../decisions/20260910202709-resourcefs-snapshot-adaptive-chunk-downshift.md)。该改进随 PR #32 部署后在 Demo 上再次用 AGS 单供应商跑真实任务，仍然失败：任务运行约 3 分钟后回到「Sandbox 连续调用失败」，说明三级降级后最小 256KiB 的请求体同样无法通过这条路径。结论收敛为：从春川到 AGS 上海的写入路径在约 20 余次请求后不再投递后续请求，请求体大小不是决定性因素，客户端侧的降级与重试不能修复该路径。

Demo 已恢复为 E2B 单供应商并复验真实任务通过（`python3 -c "print(6*7)"` 返回 `42`、退出码 0、工作区按空闲策略暂停）。

## 香港地域复验与权重分配验证

在腾讯云控制台完成登录后创建香港地域的沙箱工具，并把后台 AGS 配置保存为新版本（域名 `ap-hongkong.tencentags.com`、模板 `hoox-ags-hk`，API Key 留空复用上一版本凭据），随后按以下顺序验证：

1. Demo 后台真实探测通过，8.8 秒。
2. 发布 AGS 单供应商路由后新建会话执行 `python3 -c "print(6*7)"` 与 `uname -s`，分别返回 `42` 与 `Linux`，退出码均为 0；香港账号出现 `hoox-ags-hk` 实例（14:05:44Z 创建），任务结束后为 `paused`。
3. 发布 E2B 版本 1 与 AGS 香港版本 2 的 1:1 权重分配，再新建 3 个会话执行 `11*11`、`12*12`、`13*13`，分别返回 `121`、`144`、`169`，全部完成且工作区按空闲策略暂停。
4. 对照沙箱账号：验证前 E2B 17 个、AGS 香港 1 个；验证后 E2B 19 个、AGS 香港 2 个。新增的 3 个实例分布在两个供应商上，证明权重分配对新实例真实生效。

沙箱工具是地域内资源：同一个 API Key 在 `ap-hongkong`、`ap-singapore`、`ap-guangzhou`、`ap-beijing`、`ap-nanjing` 都能通过鉴权，但跨地域调用只返回 `ResourceNotFound.SandboxTool`，因此必须为目标地域单独创建工具。

## 未完成与边界

- 后台探测不覆盖 ResourceFS 快照物化，探测通过不等于真实任务可用；选择地域时优先靠近部署主机，并先用真实任务验证再加入新建池。
- 上海地域从该部署主机不可用；本次只在香港验证成功，未逐个验证北京、南京、新加坡等地域。
- 未覆盖：暂停保留到期回收、Worker 重启后的恢复、路由发布后的并发容量上限，以及春川到各目标地域的延迟比较。
- 本次记录时先出现本地 uu 端口映射不可达（`ECONNREFUSED`），映射恢复后 `pnpm db:setup` 通过（数据库迁移版本 65，无新增迁移）；Cube 服务未在本次验证中真实探测。

这些证据仅属于上述提交、环境和时点，不代表后续版本的持续保证。
